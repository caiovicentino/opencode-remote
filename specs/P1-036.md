# P1-036 — Preservar branch da task entre attempts

## Problem

The BACKLOG claim ("pipeline.ts:717 deletes the branch on EVERY attempt") is already
fixed on main: P1-060 landed branch preservation as a prerequisite
(`preserveBranch()` at apps/pilot/src/pipeline.ts:141, wiring at pipeline.ts:1016-1030,
builder "continue from existing history" block at pipeline.ts:282-284, planner-spec
reuse/recovery at pipeline.ts:1083-1103). What P1-036 still owes:

1. The task's own acceptance criterion is unmet: there is NO unit test exercising
   attempt 2 with a preserved branch. The decision logic lives INLINE in
   `runPipeline` (pipeline.ts:1016-1030), which cannot be called in a unit test
   (it runs LLM agents). The existing tests only pin the pure truth table
   (scripts/unit.test.ts:994-996) and prompt text (1016-1017).
2. Docs are stale: AGENTS.md (line ~28) still scopes branch-across-attempts to
   `(size: L)` tasks, but the code applies it to EVERY task;
   docs/PILOT.md:129 says "qualquer task" but credits P1-060.

## Approach

M1 — Extract, do not rewrite. Move the branch-setup block from `runPipeline`
(pipeline.ts lines 1010-1030: `attemptNo` read is kept by the caller; the fetch /
reset / clean / preserve-or-recreate part) into an exported function in the same
file:

```ts
/** Returns true when the workspace resumed an existing preserved branch. */
export function setupTaskBranch(ws: string, id: string, attempts: number | undefined): boolean
```

It must: fetch origin, `reset --hard` + `clean -qfd`, then
`preserveBranch(attempts, branchExists(ws, branch))` → checkout the branch and log
the "branch preserved from previous attempt" line, else delete + `checkout -B
branch origin/main` + `clearCheckpoint(id)`. `runPipeline` becomes
`const resumed = setupTaskBranch(ws, t.id, attemptNo);`. Preconditions stay as
today: `TASK_ID_RE` was already checked by the caller (pipeline.ts:1009); do not
interpolate an unvalidated id. Behavior must be byte-for-byte equivalent — this is
a testability refactor, not a redesign.

M2 — Unit coverage in scripts/unit.test.ts (new `// --- P1-036 ...` block), using
the same scratch-repo pattern as the spec-recovery tests (unit.test.ts:1022-1049:
mkdtemp, `git init -b main`, seed `refs/remotes/origin/main`, execSync helper):

- attempt 2 with preserved branch: create branch `pilot/P1-036T` with an empty
  commit ("attempt-1 work"), record its sha, then
  `setupTaskBranch(repo, "P1-036T", 1)` → returns true; HEAD is the branch; the
  recorded sha still resolves (`git cat-file -e <sha>^{commit}`); the committed
  file still exists in the worktree.
- attempt 0 recreates: with a stale branch + stale commit present,
  `setupTaskBranch(repo, id, 0)` → returns false; branch now points at
  origin/main; the stale commit is unreachable.
- `setupTaskBranch(repo, id, undefined)` behaves like attempt 0.
- missing-branch fallback: `setupTaskBranch(repo, freshId, 3)` with no branch →
  returns false and creates the branch at origin/main.

M3 — Docs: AGENTS.md sentence "keep the `pilot/<ID>` branch across attempts" —
state it applies to all tasks after N failures (size L only changes budgets /
checkpoints); docs/PILOT.md:129 attribution "(P1-060)" → "(P1-060/P1-036)".

## Edge cases

- Stale branch exists but `taskAttempts[id] == 0` (task re-entering Ready after a
  blocker or breaker reset): must take the FRESH path — delete + recreate, old
  work discarded by design; checkpoint file also cleared.
- `attempts > 0` but branch missing (fresh slot clone): `preserveBranch` returns
  false → fresh path, no crash.
- Checkout of a preserved branch fails (dirty index race): `resumed = false`
  falls through to the fresh path, exactly as today — attempt work is recoverable
  via the gate-fail carryover tail.
- Only COMMITTED work survives; uncommitted dirt is wiped by `reset --hard` +
  `clean` before the decision (unchanged; carryover tail remains the mechanism).
- Invalid task id: never reaches the new function (`runPipeline` returns first at
  pipeline.ts:1009); keep it that way.
- The preserved branch may lack a valid spec: the existing planner
  reuse/recover/fail-fast block (pipeline.ts:1083-1103) already handles it — do
  not duplicate that logic.

## Acceptance criteria

1. `npx tsx scripts/unit.test.ts` (or `npm run test:unit --silent`) passes and
   prints ≥4 new OK lines matching `P1-036:` — including "attempt 2 ... preserved"
   with a real preserved commit surviving, and "attempt 0 ... recreated" with the
   stale commit unreachable.
2. `npm run typecheck --silent` green.
3. `git grep -n "git branch -qD" apps/pilot/src/pipeline.ts` shows the delete
   command only inside the non-resumed (fresh) path of `setupTaskBranch`.
4. `preserveBranch` behavior unchanged: existing checks at unit.test.ts:994-996
   still pass unmodified.
5. AGENTS.md + docs/PILOT.md updated as in M3 (branch preservation documented as
   all-task behavior); no other docs touched.

## Out of scope

- Rebasing/replaying the preserved branch onto a newer origin/main (stale-base
  merges are handled by the existing squash-PR/fallback merge path).
- Preserving uncommitted work or expanding the 1200-char gate-fail carryover.
- Checkpoint review, size budgets, attempt caps (P1-060 / P1-014 territory).
- scripts/invariants.ts, deploy/, crypto/auth surfaces (constitution-protected).
- Any change to `preserveBranch`'s exported signature or semantics.
