# P1-077 — Cache-aware prompt assembly

## Problem

Measured on the live opencode.db (51h window): 1.87B input tokens vs 954k cache.read — a
0.05% provider prefix-cache hit rate. Root cause is prompt assembly order in
`apps/pilot/src/pipeline.ts`: every agent prompt opens with VARIABLE content (task id/title/spec,
round, findings, lessons) before the STABLE blocks (role rules, `CONSTITUTION`, EVIDENCE/verdict
format). Provider prefix caching (GLM/CulturaBuilder supports context caching server-side) only
engages on a byte-identical prefix, so nearly every request pays full input price. Literature for
agentic loops with stable system prefixes reports 50–90% input savings; this is the largest cost
lever still switched off.

Current offenders (line numbers on today's main):
- `builderPrompt` (`pipeline.ts:294`): task text + findings + `lessonsBlock` at :321 come BEFORE
  `CONSTITUTION` at :323; `round` is interpolated in the very first line (:316).
- `plannerPrompt` (:54): task text at :64-66 before the stable rules at :67-81.
- `reviewerPrompt` (:474): task title/spec/focus before `CONSTITUTION` at :490 (diff already ends the prompt — good).
- `scribePrompt` (:365): task text at :370-372 before the stable rules (diff already last — good).

## Approach

1. MEASURE first (P2-028 extension). In `apps/pilot/src/costs.ts` the SQL already selects
   `tokens_cache_read`/`tokens_cache_write` but `parseSessionTokens` collapses them into one total.
   Keep a 4-way breakdown per session; extend `applySessionCosts` to also fold
   `input / cacheRead / cacheWrite` into a new state field (additive, same REPLACE-by-recompute and
   `TASK_COST_CAP` pruning as `taskCosts`). `applySessionCosts` is called once per run at
   `apps/pilot/src/index.ts:289` — no new call site needed. After folding, log one line per task:
   `msg:"task cache" data:{task, input, cacheRead, cacheWrite, ratio}` where
   `ratio = cacheRead/(cacheRead+input)` (0 when denominator is 0).
2. Reorder the four templates in `apps/pilot/src/pipeline.ts` so the STABLE prefix is byte-identical
   across requests and tasks, and the VARIABLE tail follows:
   - Stable prefix (in this order): role line (WITHOUT `round ${round}`), role rules, `CONSTITUTION`,
     output-format contract (EVIDENCE block for the builder; the reviewer's verdict-marker block;
     the scribe's LESSONS/completion-marker block; spec sections + the planner's completion marker).
   - Variable tail, always after the last stable line: task id/title/spec, round, attempt/retry,
     specBlock/longBlock, resumeBlock, reviewer findings, `lessonsBlock`, failure-lessons block,
     UI-screenshot bullet (contains `${t.id}-r${round}`), and the diff (reviewer/scribe keep diff last).
   - IER lessons (`lessonsBlock`) must NEVER appear before the stable block — builder prompt currently
     violates this at :321.
   - The builder EVIDENCE template has one unavoidable variant (`uiTask` on/off): the prefix must be
     identical within a variant; keep both variants deterministic.
3. Provider-cache investigation (item 4 of the task): confirm CulturaBuilder/GLM prefix caching is
   active through opencode by comparing two requests with identical prefix but different suffix in
   `~/.local/share/opencode/opencode.db` (`cache_read > 0` on the second). Document the finding and
   any `~/.config/opencode/opencode.jsonc` model-option conclusion in `docs/PILOT.md`. Do NOT commit
   config or keys (constitution 4); the repo has no model config of its own.
4. Keep `state.taskCosts` shape unchanged (dashboard `apps/pilot/dashboard/index.html:455` reads it);
   the new breakdown is a separate optional field. Normalize it in `apps/pilot/src/doctor.ts:257`-style
   state hygiene and in `apps/pilot/src/state.ts` `loadState`.

## Touched files

- `apps/pilot/src/costs.ts` — breakdown parse + `applySessionCosts` folds cache metrics (additive).
- `apps/pilot/src/state.ts` — new optional `taskCache?: Record<string, {input: number; cacheRead: number; cacheWrite: number}>` on `PilotState`, normalized in `loadState`.
- `apps/pilot/src/pipeline.ts` — reorder `builderPrompt`, `plannerPrompt`, `reviewerPrompt`, `scribePrompt`; add the per-task cache log line where costs reconcile (or export a helper for index.ts).
- `apps/pilot/src/index.ts` — pass the breakdown through `runSlot`'s existing `applySessionCosts` call (:289).
- `apps/pilot/src/doctor.ts` — normalize the new optional field (mirror of :257).
- `scripts/unit.test.ts` — new checks in the pipeline/prompt section (~:1289) and the P2-028 costs section.
- `docs/PILOT.md` — document the cache metrics, the hit-ratio formula and the provider-cache finding.

## Edge cases

- Legacy state.json without the new field: `loadState`/doctor backfill `{}` — never crash, dashboard untouched.
- sqlite rows missing cache columns (older DBs): treat as 0, keep the taskCosts total path working.
- Recompute must stay REPLACE-by-recompute: a resumed builder session grows; re-folding must not double-count cache tokens (same invariant costs.ts already enforces for totals).
- Empty lessons/findings: the variable tail degrades gracefully; the stable prefix is unaffected (existing tests at scripts/unit.test.ts:1304 pin the "clean prompt" behavior — keep them green).
- `ratio` with 0 denominator → 0, not NaN (log/JSON must stay valid).
- First run after deploy shows cacheWrite spike with low read; the ≥30% criterion is evaluated over the 10-cycle window, not per task.
- Tier-B roles reuse the same templates — ordering change applies to them automatically; no runner change needed (`-s` session resume is orthogonal caching).

## Acceptance criteria

- `npm run typecheck`, `npm run build`, `npm run test:unit` all pass (gate re-runs them).
- Unit (new, scripts/unit.test.ts): for two DIFFERENT tasks/rounds, `builderPrompt` outputs are
  byte-identical up to an index strictly past the EVIDENCE heading start; equivalently, for all four
  templates `prompt.indexOf(CONSTITUTION) < prompt.indexOf(taskTitle)` and
  `prompt.indexOf(CONSTITUTION) < prompt.indexOf("EXPERIENCE —")` when lessons exist.
- Unit (new): `applySessionCosts` folds `input/cacheRead/cacheWrite` into `state.taskCache` and prunes at `TASK_COST_CAP`; the ratio helper returns `cacheRead/(cacheRead+input)` and 0 on empty input.
- Live (post-merge, 10 pipeline cycles): `state.json` `taskCache` shows aggregate
  `sum(cacheRead)/sum(cacheRead+input) >= 30%` for tasks created after the change (baseline today: 0.05%);
  per-task log lines `"task cache"` present in the pilot log.
- The provider-cache investigation is documented in docs/PILOT.md with the measured before/after numbers.

## Out of scope

- Slot cache-affinity scheduling, byte-identical prefix across slots (repo-1 vs repo-2 paths) and staggered slot starts — that is P1-078; here the prefix only needs to be identical across requests/tasks within a slot.
- Desktop context gauge / context-pressure recap (P1-079).
- Any change to `CONSTITUTION` content, `scripts/invariants.ts`, `deploy/`, auth, or crypto.
- Editing `~/.config/opencode/opencode.jsonc` (host file, contains the API key) — conclusions are documented, not committed.
- Changing cost-based task prioritization logic (P2-028 consumer) beyond feeding it the same totals.
