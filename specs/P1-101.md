# P1-101 — Gate determinístico ANTES dos reviewers + retry-once flaky

## Problem
Hoje `runPipeline` (apps/pilot/src/pipeline.ts:1416-1758) roda preflight typecheck → 2 reviewers (LLM) → `gatekeeper()` (evidence + bateria + corpus + merge). Consequências:
- Uma falha determinística do gate (evidence divergente, unit vermelho, invariants) só aparece DEPOIS de gastar tokens de reviewer e **mata o attempt** (`return { ok:false, detail:"gatekeeper rejected…" }` em pipeline.ts:1733), em vez de voltar como finding para o builder no mesmo attempt (P2-099 queimou 4 attempts assim).
- Um step flaky (integration/desktop-flow/reconnect) é indistinguível de falha real: uma única execução vermelha rejeita o merge.
- `exec()` (apps/pilot/src/runner.ts:326-348) usa `execSync`: em sucesso retorna só stdout, o stderr vai para o terminal do pilot. O vite escreve warnings em stderr, então o re-run de `npm run build --silent` não contém linhas que o builder colou honestamente → "pasted output diverges" falso (gate tail de P2-099).

## Approach
1. **runner.ts — `exec()` captura stderr**: trocar `execSync` por `spawnSync(cmd, { shell: true, cwd, encoding: "utf8", timeout, maxBuffer: 64 MiB, stdio: ["ignore","pipe","pipe"] })`. `output = stdout + stderr` em sucesso E em falha; `ok = status === 0 && !error`. Manter o `throw new Error("exec failed (status N): …")` quando `!allowFail`. Remover `Bun_shim_execSync`.
2. **runner.ts — `runStepWithRetry(cache, cmd, cwd, opts, run?)`** (puro, injetável como `cachedExec`): 1ª execução via `cachedExec`; se `!ok`, `cache.delete(rerunKey(cmd,cwd))` e executa de novo via `cachedExec` (resultado da 2ª fica no cache). Retorna `{ ok, output, flaky }` com `flaky = primeira falhou && segunda passou`. Duas falhas → `output` da segunda. Nunca mais de 2 execuções.
3. **pipeline.ts — extrair `deterministicGate()`** (exportado, sem mutação de `state`, sem `recordGateFail`) a partir de `gatekeeper()` (pipeline.ts:1957-2038): recebe `(ws, t, builderOutput, startedAtMs, rerunResults, nameOnly: string, run?)` e devolve `{ ok: true, flaky: string[] } | { ok: false, step: string, tail: string, flaky: string[] }`. Conteúdo: mesma lista `steps` (desktop-render/desktop-flow condicionais por `nameOnly`, fail-closed quando `nameOnly` vazio/inválido), evidence (`verifyEvidence` com `cachedExec` como hoje), bateria via `runStepWithRetry`, corpus check (`corpusGateDetail`) quando `touchedPilotInfraFromDiff`. Retry-once do evidence: só quando `detail` começa com `cited command failed on re-run:` — evict as keys dos comandos citados cujo cache está `!ok` e chama `verifyEvidence` uma 2ª vez; se passar, `flaky.push("evidence")`. Divergência de paste NÃO é flaky (não re-tenta).
4. **pipeline.ts — renomear o resto de `gatekeeper()` para `mergeTask()`** (push branch, `gh pr create/merge`, verified-merge, mark-done via pilot/meta, corpus capture, `state.merges++`) — corpo inalterado.
5. **pipeline.ts — nova ordem em `runPipeline`** logo após o preflight typecheck (pipeline.ts:1599-1604):
   - `const gateSha = headSha(ws)`; `emit("phase",{phase:"gatekeeper"})`; `const gate = await deterministicGate(...)`; para cada `gate.flaky` → `emit("phase",{task, phase:"gate-flaky", ok:true, detail: step})` + log JSON `msg:"gate-flaky"`; `emit("phase",{phase:"gatekeeper-done", ok: gate.ok, detail: gate.ok ? "green" : gate.step})`.
   - Falha: `findings = \`${findings}\n${gateFindingBlock(gate.step, gate.tail)}\``, onde `gateFindingBlock` (exportado, puro) gera `[deterministic gate failed at step "<step>" — fix this FIRST and re-run the EVIDENCE commands]\n<tail últimos 1500 chars>`. Emitir `gate-fail` (detail = step) e gravar o carryover `pilot/gate-fail/<ID>.json` (extrair de `recordGateFail` um `writeGateFailCarry(taskId, step, tail)` sem `state.failures++`). Se `round < cfg.maxReviewRounds` → `continue` (builder round seguinte conserta; attempt NÃO queimado). Se último round → `recordGateFail(state, t.id, gate.step, gate.tail)` e `return { ok:false, detail: \`gatekeeper rejected at step ${gate.step}: ${tail.slice(-300)}\`, ...roundMeta() }`.
   - Sucesso: reviewers/escalação como hoje. Em `gateSecOk && gateQualOk`: checar `headSha(ws) === gateSha` e `git status --porcelain` vazio; se não → `recordGateFail(state, t.id, "tamper", …)` e `return { ok:false }` (fail-closed: reviewers não editam código). Senão `merged = await mergeTask(...)` seguido do `emit("phase",{phase:"merge", ok: merged})` existente; scribe/cleanup como hoje.
6. **metrics.ts** (apps/pilot/src/metrics.ts:123-128): `COMPLETES` passa a `{"gatekeeper-done":"gatekeeper"}` no lugar de `merge:"gatekeeper"`; `avgPhaseDurations` ignora `gate-flaky` e `gate-fail` como openers (set `AUX_PHASES`), senão eles quebram o pareamento gatekeeper→gatekeeper-done.
7. **Docs**: docs/PILOT.md — nova subseção "Gate determinístico antes dos reviewers + retry-once (P1-101)" perto de "Round efficiency" (docs/PILOT.md:793-812), descrevendo a ordem nova, gate-fail-como-finding, `gate-flaky`, e que o evidence re-run agora inclui stderr. AGENTS.md:9 e 53-54: ajustar a frase da ordem (gate roda antes dos reviewers).

## Edge cases
- `exec` com stderr: parsers de sucesso que usam `.output.trim()` são plumbing git silencioso (`rev-parse`, `log --format`, `diff --name-only`, `remote get-url`, `ls-files`) — stderr vazio; confirmar com `npm run test:unit`. Ordem é stdout depois stderr (buffers separados, interleave perdido) — aceitável para contenção.
- Timeout no `spawnSync` retorna `error.code === "ETIMEDOUT"` e `status === null` → `ok:false`, output com o que foi capturado.
- Retry-once nunca dispara para evidence divergente/fabricada (anti-fabricação P2-009 intacta) nem para o corpus check (determinístico).
- Cache P2-040: após retry, o cache guarda o resultado da 2ª execução; um step verde continua executando 1× por round.
- Gate falha no último round → attempt queimado exatamente como hoje (carryover + `state.failures++`), sem rodar reviewers.
- `gate-fail` continua sendo emitido em toda falha de gate (countFailSteps do dashboard segue funcionando); `state.failures` só cresce no terminal.
- Round com gate falho e `findings` já contendo findings de reviewer do round anterior: os dois blocos coexistem (append, não substituição) — o builder conserta o gate primeiro.
- `desktop-render`/`desktop-flow` são caros (Electron): retry-once ainda vale (é onde o flaky mais aparece), mas cada um roda no máximo 2×.

## Acceptance criteria
- `npm run typecheck --silent`, `npm run build --silent`, `npm run test:unit --silent` verdes (cita os três no EVIDENCE).
- `npx tsx scripts/unit.test.ts 2>&1 | grep -c "^OK   P1-101"` ≥ 7, cobrindo:
  1. `exec("echo out; echo err 1>&2", {cwd, allowFail:true})` → `ok:true` e `output` contém `out` e `err`; comando com `exit 3` → `ok:false`, output com stderr.
  2. `runStepWithRetry` — falha determinística: `run` falha sempre → `ok:false, flaky:false`, exatamente 2 execuções.
  3. `runStepWithRetry` — flaky: falha 1ª, passa 2ª → `ok:true, flaky:true`, 2 execuções, cache com resultado verde.
  4. `runStepWithRetry` — verde: 1 execução; chamada seguinte via `cachedExec` não re-executa (P2-040 preservado).
  5. `deterministicGate` (ws temporário, `run` injetado, evidence válido): step `build` falhando 2× → `{ok:false, step:"build"}`, steps posteriores (`unit`, …) NÃO executados; tail contém o output do erro.
  6. `deterministicGate` com `unit` falhando 1× e passando depois → `{ok:true, flaky:["unit"]}`.
  7. `gateFindingBlock("build", tail)` → 1ª linha `[deterministic gate failed at step "build" — …]`, tail truncado a 1500 chars.
  8. `avgPhaseDurations`: sequência `gatekeeper → gate-flaky → gatekeeper-done` produz 1 amostra de `gatekeeper`; `merge` não fecha mais nada.
- Ordem no código: `grep -n "deterministicGate(\|reviewers start" apps/pilot/src/pipeline.ts` mostra a chamada do gate em linha menor que o log `reviewers start` dentro de `runPipeline`.
- `grep -n "gate-flaky" apps/pilot/src/pipeline.ts apps/pilot/src/metrics.ts docs/PILOT.md` → ≥1 hit em cada.
- `npx tsx -e 'import("./apps/pilot/src/pipeline.ts").then(m=>console.log(m.corpusGateDetail()))'` imprime `null` (corpus verde — o diff toca apps/pilot, então o próprio gate exige isso).
- Nenhuma linha nova em scripts/invariants.ts ou deploy/ (`git diff --name-only main...pilot/P1-101` não lista esses paths).
