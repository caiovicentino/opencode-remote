# P1-065 — verifyFindings drops valid findings: symbol check must use the citation union

## Problem

`verifyFindings` (apps/pilot/src/pipeline.ts:1488) filters reviewer findings through
`findingResolves` (pipeline.ts:1553). When a finding cites files, it requires
`fileCites.every(c => citeResolves(...))` (pipeline.ts:1566) and — inside `citeResolves`
(pipeline.ts:1591-1594) — that **every** quoted symbol appear in **that single** cited
file's content or the diff. Per-citation semantics wrongly drop genuine findings:

1. **Cross-file finding (reproduced).** A finding citing `apps/pilot/src/doctor.ts:34`
   + `apps/pilot/src/pipeline.ts:589` with symbols `DOCTOR_ID_RE`/`TASK_ID_RE` is
   dropped: `TASK_ID_RE` lives only in pipeline.ts (line 589), so the `doctor.ts`
   citation "fails" the symbol check even though both files and symbols are real.
   Repro confirmed in this workspace: the finding lands in `dropped`.
2. **Findings of absence.** "unit.test.ts has no coverage of `runDoctor`" quotes a
   symbol that by definition is not (fully) present in the cited file; per-citation
   checks punish exactly the findings reviewers must be able to make.
3. Any finding citing ≥2 files whose symbols are spread across them collapses.

Desired contract (task statement): symbols are satisfied by the **union** of the
contents of all resolved citations + the reviewed diff, with a two-tier rule, and a
drop that only fires on missing files or zero union matches.

## Approach

All changes in `apps/pilot/src/pipeline.ts` (P2-038 block, lines ~1502-1598):

1. **Split resolution from symbol checking.** Turn `citeResolves` into
   `resolveCite(ws, cite, wsFiles): string | null` — keep exactly the current
   resolution rules (strip `./` and `a/`/`b/` prefixes, reject `..`, path-exact or
   bare-name suffix match via sorted `wsFiles`, cited line must exist and be
   non-empty when present). Return the file content instead of a boolean.
2. **Union semantics (tier 1).** In `findingResolves`, for findings with citations:
   resolve **every** citation; if any returns null → drop (unchanged behavior).
   Build `union = contents.join("\n") + "\n" + diff`. If every symbol from
   `symbolCites` (pipeline.ts:1519) is contained in the union → keep.
3. **Tier-2 rule.** If tier 1 fails, keep the finding when **at least one** quoted
   span of ≥6 chars (symbol or snippet spans; quoted path-shaped spans excluded via
   `FILE_PATH_SHAPE_RE`) appears in the union — tier-2 findings are ordinary `kept`
   findings: they flow into the builder carryover through the existing path
   (pipeline.ts:1442-1444 → `recordGateFail`), no new plumbing.
4. **Drop rule.** Drop a cited finding only when (a) any citation fails to resolve
   (file missing / line empty or out-of-range), or (b) zero quoted spans of ≥6 chars
   match the union.
5. **No-citation path unchanged.** Snippet-only findings still go through
   `SNIPPET_RES` vs the diff (pipeline.ts:1568). Findings with citations but no
   quoted spans keep current behavior (kept iff all citations resolve).
6. **Tests.** Add a `p1-065` block to scripts/unit.test.ts next to the P2-015/P2-038
   blocks (~lines 1339-1418), using the same `mkdtempSync` fake-workspace pattern,
   with files `doctor.ts` (containing `DOCTOR_ID_RE`), `pipeline.ts` (containing
   `TASK_ID_RE`), `unit.test.ts` and an empty/small diff, asserting the four cases
   below plus the `DOCTOR_ID_RE`+`TASK_ID_RE` cross-file repro verbatim.

## Edge cases

- Symbol present in the reviewed diff but in no cited file → tier-1 keep (union
  includes diff; battery-pinned "symbol present in the reviewed diff").
- One citation of several missing/empty-line/out-of-range → still dropped
  (battery-pinned: "nonexistent path", "empty cited line", "out-of-range line").
- `totallyFakeSymbol` with a real file:line → 0 union matches → dropped
  (battery-pinned P2-038 FAKE case must not regress via tier-2).
- No quoted spans at all ("prose mention of real.ts") → kept iff citations resolve.
- Bare-name citations (`CommandPalette.tsx:3`) still resolve by suffix match;
  first candidate in sorted `wsFiles` whose cited line is non-empty wins.
- URLs stripped before citation extraction; `../` traversal and diff `a/`,`b/`
  prefixes rejected (unchanged).
- Quoted file-path-shaped spans (`real.ts:2`) stay citations, never symbols.
- Short (<6 chars) quoted spans count for tier-1 only; they never trigger tier-2.
