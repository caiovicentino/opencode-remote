# P1-034 — Self-reload sempre que o HEAD mudar

## Problem

Em `apps/pilot/src/deploy.ts`, o self-reload pós-deploy (linhas ~330-335) roda
`git diff --name-only ${sha} HEAD -- apps/pilot` DEPOIS do `git reset -q --hard ${sha}`
(linha ~257). Como HEAD === sha nesse ponto, o diff de um commit contra ele mesmo é
sempre vazio → `pilotChanged.output` nunca contém "apps/pilot" → `process.exit(0)`
nunca dispara → o monitor pilot continua rodando código STALE depois de qualquer
merge (causa raiz do incidente stale). O `pilotInfra` (linhas 238-240) está correto
porque diffa `prev..sha` antes do reset; só o bloco de reload está quebrado.

Nota: a linha do BACKLOG cita números antigos (58/125); no arquivo atual `prev` é
capturado na linha 234 (pré-mutação, via `git rev-parse HEAD` — id completo) e o
diff quebrado está em 331-335.

## Approach

1. Em `apps/pilot/src/deploy.ts`, adicionar um helper puro exportado (padrão das
   outras extrações P1-044/P3-006):

   ```ts
   export function shouldSelfReload(prev: string, head: string): boolean
   ```

   Retorna `true` somente se `prev` e `head` são object ids válidos (reusar
   `SHA_RE` de `./deployguard` — já importado no arquivo) e `prev !== head`.
   IDs vazios/inválidos → `false` (nunca recarregar por dado ruim).

2. No caminho de sucesso de `deploy()` (após o bloco de UI shot, linhas ~318-329),
   SUBSTITUIR o diff quebrado por:

   - `const headNow = exec("git rev-parse HEAD", { cwd: cfg.repo, allowFail: true }).output.trim();`
     (pós-reset, id completo de 40 hex — normaliza o caso de `sha` abreviado,
     pois `SHA_RE` aceita 7-40 hex e um compare cru `prev !== sha` daria
     falso positivo).
   - `if (shouldSelfReload(prev, headNow))`: log warn "HEAD moved <prev7> → <head7> — self-reloading",
     `emitEvent("deploy", { phase: "self-reload", ok: true, detail: ... })`
     (usar o `emitEvent` injetável, padrão P3-006) e `process.exit(0)`.
     O KeepAlive do launchd + singleton pidfile (P0-004) reassumem no código novo.
   - Regra: recarregar SEMPRE que o HEAD mudou, independente de quais arquivos
     mudaram — o cérebro nunca pode rodar stale. NÃO manter nenhum filtro por diff.

3. `prev` já está capturado antes de qualquer mutação (linha 234) — não mover.
   Todos os caminhos de rollback/fracasso retornam antes do bloco → só deploy
   bem-sucedido recarrega.

## Touched files

- `apps/pilot/src/deploy.ts` — remover diff quebrado (linhas ~330-335); adicionar
  `shouldSelfReload` + wiring no fim de `deploy()`.
- `scripts/unit.test.ts` — novo bloco de checks P1-034 (importar `shouldSelfReload`
  junto dos demais exports de `../apps/pilot/src/deploy`, linha ~124-133).
- `docs/PILOT.md` — seção "Self-healing (3 níveis)", item 3 (linha ~325): o
  self-reload pós-deploy agora dispara sempre que o HEAD mudou (não só quando
  `apps/pilot` muda).

## Edge cases

- `sha` abreviado (SHA_RE aceita 7-40 hex): comparar só depois de normalizar via
  `rev-parse` do HEAD pós-reset; `prev` já é id completo.
- `rev-parse` pós-reset falha → string vazia → `shouldSelfReload` retorna false
  (guarda SHA_RE): impossível recarregar em loop por erro de probe.
- Self-heal de deploy pendente (`index.ts:152-172`): só roda quando
  `prodSha !== target` (index.ts:158), então prev === sha não ocorre na prática;
  se ocorrer (re-deploy do mesmo sha), prev === headNow → sem reload (correto).
- Reload mata o processo antes do `.then/.finally` de `launchDeploy`
  (`index.ts:325-341`): log "deploy result"/digest são perdidos nesse caminho —
  já é o comportamento atual do lane pilot-infra; `state.deploys` foi salvo
  antes; não redesenhar.
- Evento `deploy done` (linha 318) e UI shot (321-329) rodam ANTES do bloco de
  reload → evidência no dashboard não é perdida.
- Rollbacks (health/invariants/soak) NÃO chegam ao bloco → prod voltou para
  `prev`, pilot não recarrega (correto: código não mudou).

## Acceptance criteria

1. `npm run typecheck` (raiz) verde.
2. `npm run test:unit` (raiz) verde, com novo bloco P1-034 em `scripts/unit.test.ts`:
   - "P1-034: HEAD moved → reload" — `shouldSelfReload(A, B) === true` com A≠B,
     incluindo o caso "HEAD mudou mas diff de apps/pilot vazio": a função não
     recebe diff nenhum, então um par de ids distintos retorna true (ex.:
     `shouldSelfReload("a".padEnd(40,"1"), "b".padEnd(40,"2"))`).
   - "P1-034: same sha → no reload" — `shouldSelfReload(X, X) === false`.
   - "P1-034: invalid ids → no reload" — `false` para `("", X)`, `("nope", X)`,
     `(X, "")`.
3. Grep de regressão: `git diff --name-only ${sha} HEAD` NÃO aparece mais em
   `apps/pilot/src/deploy.ts` (o padrão quebrado foi removido).
4. Critério observável (E2E, deploy real seguinte): todo deploy bem-sucedido com
   `prev !== headNow` registra o evento `deploy/self-reload` + log warn e o
   processo sai com exit 0 (KeepAlive reassume no sha novo) — visível no
   `pilot.log`/`events.jsonl`; um deploy que não move o HEAD não recarrega.
