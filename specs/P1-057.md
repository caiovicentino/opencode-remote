# P1-057 — Aux agents sem shell: researcher/strategist/redteam/scribe read-only

## Problem
- `writeSandboxConfig` (apps/pilot/src/pipeline.ts:560) dá `bash:allow, edit:allow, external_directory:allow`
  a TODO agente, incluindo os auxiliares que ingerem conteúdo externo não confiável
  (researcher via webfetch; apps/pilot/src/researcher.ts:25-66). Uma página pesquisada pode
  injetar instruções e o agente tem shell → RCE no host com credenciais de push.
- Pior: researcher.ts:66 executa `git push origin main` ANTES do `git add/commit` — empurra
  o HEAD local (qualquer código que o agente tenha commitado) direto para main, sem gatekeeper.
- O mesmo padrão de push cego existe no strategist (apps/pilot/src/index.ts:475) e no redteam
  (index.ts:388 e 401).
- `/dashboard` (apps/daemon/src/index.ts:1597-1606) embute o apiToken real no HTML
  (`__APITOKEN__`), entregue sem nenhuma autenticação.
- `npm ci` do deploy (apps/pilot/src/deploy.ts:135,138,144) roda lifecycle scripts de
  dependências — vetor de supply chain.

## Approach
1. **(a) Sandbox restrito para aux agents** — em apps/pilot/src/pipeline.ts adicionar
   `writeAuxSandboxConfig(ws)`: mesmo formato de `writeSandboxConfig`, porém com
   `permission: { edit: "deny", bash: "deny", external_directory: "deny", webfetch: "allow" }`
   (webfetch continua: o researcher precisa; a injeção morre no bash negado).
   Usar em todos os spawns auxiliares:
   - `runResearcher` (researcher.ts:54) e `runStrategist` (index.ts:434): chamar
     `writeAuxSandboxConfig(cfg.workspace)` ANTES do spawn e `writeSandboxConfig` depois
     (aux só roda com `running.size === 0` — index.ts:180 — logo a troca não tem corrida).
   - redteam (index.ts:366): idem, dentro de `maybeNightly` após explorer/forensic.
   - scribe (apps/pilot/src/pipeline.ts:398): `writeAuxSandboxConfig(ws)` antes do spawn.
     A próxima pipeline já reescreve a config full em pipeline.ts:919.
2. **(a) Saída vira texto validado; runner commita** — os aux agents NÃO editam mais arquivos:
   - Novas funções puras (em apps/pilot/src/backlog.ts): `parseAuxTaskLines(output: string): string[]`
     (extrai linhas entre marcadores `AUX-TASKS:` / `AUX-TASKS-EOF` do output, aceita no máximo
     5 linhas, cada uma obrigatoriamente no formato do backlog — mesma regex de parseBacklog
     backlog.ts:56 + `AREA_RE` + id `(P\d-0\d\d|RT-\d\d\d)` + area ∈ KNOWN_AREAS) e
     `appendReadyLines(repoDir: string, lines: string[]): boolean` (insere no fim de `## Ready`,
     rejeita IDs duplicados contra o arquivo atual).
   - researcher.ts: reescrever o prompt (linhas 46-52): "não commitar, não editar arquivos;
     imprima as linhas de tarefa entre AUX-TASKS / AUX-TASKS-EOF; última linha RESEARCHER:DONE".
     Remover o bloco exec da linha 66. Novo fluxo no runner: validar linhas →
     `appendReadyLines` → `git add BACKLOG.md && git commit` → push com guard (item b).
   - index.ts `runStrategist`: mesmo fluxo (o prompt já diz "do not commit" — trocar a instrução
     de editar BACKLOG.md por imprimir as linhas); substituir o exec da linha 475.
   - redteam: o achado já vira `addTask` no runner (index.ts:400) — apenas trocar o push cego
     da linha 401 pelo guard; manutenção de EXPERIENCE.md (linha 388) continua, mas sob o guard
     com arquivo permitido `docs/EXPERIENCE.md` (ver Edge cases).
3. **(b) Guard de push** — helper puro testável em backlog.ts (ou novo auxtasks.ts):
   `mayPush(nameOnlyOutput: string, allowed: string): boolean` — true somente se as linhas não
   vazias de `git diff --name-only origin/main...HEAD` forem EXATAMENTE `[allowed]`.
   Nos três fluxos aux: commit → `git diff --name-only origin/main...HEAD` → se
   `!mayPush(...)`, logar `warn` "aux push refused" e NÃO empurrar; se ok, push com o loop de
   retry 3x existente (rebase/fetch entre tentativas como hoje).
4. **(c) /dashboard sem apiToken sem auth** — apps/daemon/src/index.ts:
   - `/dashboard` passa a servir o HTML com `__APITOKEN__` SEMPRE substituído por `""`
     (nenhuma rota entrega o token no corpo). O token box + `?token=` + localStorage já
     existem no dashboard (apps/pilot/dashboard/index.html:388-399) e continuam funcionando.
   - Novo `POST /api/session` (Bearer obrigatório): gera id de sessão random (crypto, 32 hex),
     guarda em Map em memória com TTL 12h, responde 200 com
     `Set-Cookie: ocr_session=<id>; HttpOnly; SameSite=Strict; Path=/; Max-Age=43200`.
   - Novo helper `authorized(req)`: aceita `Authorization: Bearer <apiToken()>` OU cookie
     `ocr_session` válido. Usar no gate comum de `/api/*` (index.ts:1643-1647) e nos gates
     de browse/pairing (1637, 1614). Sessões expiradas/ausentes → 401 (send401 existente).
5. **(d) npm ci com --ignore-scripts** — deploy.ts:135 e 138 (`npm ci --no-audit --no-fund
   --ignore-scripts --loglevel=error`) e rollback (144). O `npm ci` do slot (index.ts:594) e do
   gate NÃO muda (o gate precisa dos lifecycle scripts).

## Edge cases
- Output aux inválido/sem linhas: runner loga `warn`, commita NADA, estado do git intacto
  (não existe mais push cego que empurraria lixo). Datas/guards (`researchLast`) não mudam.
- ID duplicado ou área desconhecida: linha rejeitada individualmente; as válidas podem ir;
  se nenhuma válida, nenhum commit. `nextId` é recalculado contra o BACKLOG.md atual no runner.
- Push não-fast-forward (deploy concorrente): manter retry 3x com `git fetch` — o guard é
  reavaliado a cada tentativa (diff re-lido após o fetch/reset).
- Manutenção de EXPERIENCE.md (redteam nightly) e `commitLessons` (scribe) continuam
  determinísticos no runner e usam o guard com `allowed` = único arquivo do diff
  (`BACKLOG.md` para tarefas, `docs/EXPERIENCE.md` para lições).
- Reinício do daemon: sessões em memória somem → cliente refaz auth Bearer (documentado).
- electron/esbuild têm postinstall: deploy só roda `npm run build` (tsc/esbuild, sem electron
  binary) — se o build falhar num lock novo, rollback existente cobre; `dist`/packaging não
  faz parte do deploy. Verificar no critério 5.
- desktop BrowserView (apps/web/src/components/BrowserView.tsx:20) abrirá o token box na
  primeira vez — fluxo já suportado pelo dashboard.

## Acceptance criteria
1. `npm run typecheck` passa; `npm run test:unit` passa com NOVOS checks:
   - `parseAuxTaskLines` aceita 1-5 linhas válidas e rejeita linhas com `;`, backticks,
     `curl exfil`, ids fora do formato e area inválida (casos negativos no teste);
   - `mayPush("BACKLOG.md\n", "BACKLOG.md") === true`;
     `mayPush("BACKLOG.md\nevil.sh\n", "BACKLOG.md") === false`;
     `mayPush("", "BACKLOG.md") === false`;
   - `writeAuxSandboxConfig` produz JSON com `bash:"deny"`, `edit:"deny"`,
     `external_directory:"deny"`, `webfetch:"allow"`.
2. `grep -n "git push" apps/pilot/src/researcher.ts` → nenhum push no arquivo (só o runner,
   via guard, em index.ts/pipeline).
3. `npm run test:desktop` (sidecar bundle): além dos checks atuais —
   - `GET /dashboard` 200 e o corpo NÃO contém o apiToken real;
   - `POST /api/session` com Bearer → 200 + `Set-Cookie` HttpOnly;
   - `GET /api/health` só com o cookie → 200; sem auth → 401.
4. Critério-chave do task: um "pesquisado" que injeta `curl exfil` no conteúdo não executa
   comando — coberto estruturalmente por (1) (bash:deny pinado) + (2).
5. Deploy local de conferência: após `npm ci --ignore-scripts --no-audit --no-fund` num
   checkout limpo, `npm run build` e `npm run typecheck` completam (evidence no bloco EVIDENCE).
6. README.md/docs/PILOT.md descrevem o novo fluxo de token do /dashboard e o sandbox aux.
