# P1-095 — Nightly pass: impossible condition + skipped event + P1-071 audit

## Problem

The nightly redteam/explorer pass requires two conditions that almost never
coincide:

- all slots idle: `if (running.size === 0) await maybeNightly(...)` (apps/pilot/src/index.ts:187);
- exact hour: `if (hour !== 3) return;` (apps/pilot/src/index.ts:443, inside `maybeNightly`).

Pipelines routinely span the whole 03:00–03:59 window — `git log` shows merges
at 03:47, 03:53, 03:57 — so `hour === 3 && running.size === 0` is effectively
unreachable and redteam/explorer/forensic never run. There is also no record
when the pass is missed: the skip is silent. This is how P1-071 got marked Done
(BACKLOG.md `## Done`, line ~53) without its acceptance criterion ("explorer
fresh-state roda no ciclo noturno") ever being observed in `git log`.

## Approach

Replace the exact-hour gate with an idle-window gate: the nightly pass runs at
the first moment the scheduler has been idle **>= 2h since the last pipeline
cycle** (once-per-day guards in `maybeNightly`, `runExplorer`, `runForensic`
stay unchanged). A missed classic window becomes observable: while the pass is
pending and slots are busy past 03:59, record `nightlySkipped` in state.json
and emit a `nightly skipped` event to Mission Control. Finally, reopen the
unfulfilled P1-071 criterion as its own backlog task.

1. **Idle trigger** — new constant `NIGHTLY_IDLE_MS = 2 * 60 * 60_000` and pure
   helpers in apps/pilot/src/scheduler.ts (module already hosts the eval-battery
   scheduling seams):
   - `nightlyIdleDue(lastCycleAt: number | undefined, now = Date.now()): boolean`
     → `now - (lastCycleAt ?? 0) >= NIGHTLY_IDLE_MS` (undefined = idle since
     forever → due).
   - `nightlySkipDue(st: { redteamLast?: string; explorerLast?: string; nightlySkipped?: { date: string } | null }, today: string, hour: number, slotsBusy: boolean): string | null`
     → returns a reason string only when `slotsBusy && hour >= 4 &&
     !(st.redteamLast === today && st.explorerLast === today) &&
     st.nightlySkipped?.date !== today`; null otherwise.
2. **Cycle timestamp** — `recordCycle` (apps/pilot/src/audit.ts:47) sets
   `st.lastCycleAt = now` (the injected `now` keeps tests hermetic). Every
   pipeline outcome (ok or merit-fail) refreshes it.
3. **State fields** (apps/pilot/src/state.ts, `PilotState` ~line 146):
   `lastCycleAt?: number` and `nightlySkipped?: { date: string; reason: string } | null`,
   both added to the `shared` block of `loadState` (202-213) so the midnight
   rollover never wipes them; tolerant parse (garbage → null), matching the
   `normalizeAudit` pattern.
4. **maybeNightly** (apps/pilot/src/index.ts:440-447): replace
   `if (hour !== 3) return;` with `if (!nightlyIdleDue(st.lastCycleAt)) return;`.
   After the `nightlyDone && !forensicDue(...)` early-return, when the pass is
   actually going to start, clear `st.nightlySkipped = null` and `saveState(st)`.
   In `--once` mode return immediately (a one-shot eval run must never kick off
   a 30-min redteam agent).
5. **Skip event at the call site** (index.ts:186-187): keep the idle branch as
   is; add an `else` branch that calls `nightlySkipDue(state, today, hour, true)`
   and, when a reason comes back, sets `state.nightlySkipped`, `saveState(state)`
   and `emit("phase", { task: "nightly", phase: "skipped", ok: false, detail: reason })`.
   The dashboard ticker (apps/pilot/dashboard/index.html:540-547) renders any
   event generically (`[nightly] skipped …`) — no dashboard change needed; the
   state field reaches Mission Control through `/api/pilot-events`
   (apps/daemon/src/index.ts:2103 passes state.json through verbatim).
6. **Reopen P1-071** — append one task line to `## Ready` in BACKLOG.md with the
   next free P3 id (same id logic as `nextId`, apps/pilot/src/backlog.ts:117):
   "[P1-071 reopen] explorer fresh-state roda de fato — com o gatilho P1-095,
   provar 1 run real do explorer em janela noturna; criterio: state.explorerLast
   === hoje + commit `pilot(explorer):` em origin/main (git log) ou evento
   `task:"explorer"` em events.jsonl dentro de 24h do merge, shots em
   ~/.opencode-remote/pilot/shots/explorer/, typecheck/build/unit verdes."

## Edge cases

- Fresh state (`lastCycleAt` undefined): due immediately — an idle day runs the
  nightly on the first loop cycle, no artificial wait.
- `--once` (eval battery): maybeNightly returns early; battery coverage happens
  via the pure seams, exactly like today.
- Explorer stamps `explorerLast` before its run, redteam stamps `redteamLast`
  after (index.ts:464-466, explorer.ts:145-147): a crash mid-pass leaves
  `nightlyDone` false; the next idle window retries only what is missing, and a
  same-day skip record stays honest if slots stay busy.
- Skip record is once per day (deduped by `nightlySkipped.date`); cleared when
  the pass starts; hour >= 4 gate keeps the reason truthful ("busy through the
  03:xx window").
- `maybeNightly` still runs only with `running.size === 0` (call-site guard):
  the nightly never overlaps a pipeline; it merely waits for a 2h-idle gap
  instead of a wall-clock hour.
- Rollover: `lastCycleAt`/`nightlySkipped` survive midnight (in `shared`);
  daily counters reset as before.

## Acceptance criteria

1. `npm run typecheck` and `npm run build` exit 0 (real output in EVIDENCE).
2. `npm run test:unit` exits 0 and includes:
   - `nightlyIdleDue(undefined)` → true; `nightlyIdleDue(now - 1.9e6*60)`-style
     checks: 1h59m ago → false, 2h01m ago → true;
   - `nightlySkipDue` matrix: busy at hour 3 → null; busy at hour 4 with
     `redteamLast: yesterday` → reason string; `nightlySkipped.date === today` →
     null; `redteamLast === explorerLast === today` → null; `slotsBusy: false` → null;
   - `recordCycle` sets `lastCycleAt === now` (injected now);
   - `loadState` date-rollover keeps `lastCycleAt` and `nightlySkipped`.
3. Simulated busy day (unit level, state fixtures): slots busy + pass pending +
   hour 4 → `state.nightlySkipped = { date: <today>, reason: ... }` and the
   emitted event line appears in events.jsonl with `"task":"nightly","phase":"skipped"`.
4. Simulated idle day: with `lastCycleAt` 2h+ old and `redteamLast`/`explorerLast`
   unset, `maybeNightly` proceeds past its guards (pure-guard assertions +
   existing explorer/forensic unit seams); `nightlySkipped` is cleared to null.
5. `rg -n "hour !== 3" apps/pilot/src` returns no hits.

## Out of scope

- Changing redteam/explorer/forensic prompts, budgets or sandbox configs.
- Dashboard DOM redesign (the generic ticker already surfaces the event).
- Executing the fresh-state explorer run itself — that is the reopened P3 task.
- Any change to `scripts/invariants.ts`, `deploy/`, crypto, allowlist, replay
  protection or the 0600 state-file permissions.
