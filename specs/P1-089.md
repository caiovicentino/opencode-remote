# P1-089 — Histórico duplicado ao voltar pra sessão

## Problem
Operator bug: switching to another conversation and back re-renders messages that are
already on screen (duplicated bubbles). Two actors populate the same transcript:

1. `loadHistory` (apps/web/src/components/ChatView.tsx:557) fetches
   `/session/<id>/message` and **replaces** the bubble list via `setBubbles(out)`.
2. The stream effect (ChatView.tsx:643-717) replays `message.part.updated` /
   `session.idle` events from the shared event buffer and, on idle, **appends** a new
   assistant bubble from `liveRef` (ChatView.tsx:708).

The append at :708 guards only against the exact same text being the **last** bubble
(`b[b.length-1]?.text === final`). If anything sits after the matching bubble (a queued
user bubble, tool rows, a second turn), or if the live text differs from the joined
history text, the append creates a duplicate.

The replay vector: `lastEventId` (ChatView.tsx:356) is a watermark into App's rolling
event buffer (App.tsx:286 caps it with `prev.slice(-500)`; App also clears it on machine
switch, App.tsx:476/489). The stream effect does `events.findIndex(e => e.id ===
lastEventId.current)` (ChatView.tsx:649) and, when the watermark slid out of the buffer,
`start` stays 0 → the **entire** buffered history of the current session replays → old
`session.idle` re-fires → duplicate assistant bubble. The P1-061 reconnect resync
(ChatView.tsx:740-752) re-anchors the watermark and refetches, but the same
race (append landing after `loadHistory`'s replace) can still duplicate.

## Approach
Make bubble identity **stable per messageID** across the history+stream merge:

1. New pure helper (same file or `apps/web/src/lib/bubbleMerge.ts`):
   `mergeBubbles(existing: Bubble[], incoming: Bubble[]): Bubble[]` — keyed by
   `messageID` (`Map<string, Bubble>`), existing order preserved, incoming entries
   replace same-id entries in place, id-less bubbles (optimistic user message) appended;
   only the LAST id-less bubble may be promoted to an id (already done for user at
   ChatView.tsx:667-681). Exported for unit tests.
2. Stream effect: thread `p.part.messageID` (already read at :658) through the live tail
   — `liveRef` becomes `{ text, messageID }`. On idle, instead of the text-only check at
   :708, append/replace via the id map: if a bubble with that messageID exists, do
   nothing (history is source of truth) or update in place; never push a second bubble
   with the same id. Keep a text-only fallback for parts with no messageID.
3. Watermark fallback: when `findIndex` returns -1 and `lastEventId.current` was set
   (buffer slid/was cleared), replay is now **idempotent** thanks to the id map — no
   duplicate appends on replay. Do not treat "empty buffer" as replay.
4. On `[sessionId]` switch (effect at :448), also clear `liveRef.current` /
   `setLiveText("")` so session A's live tail can never finalize into session B.
5. Event filtering by current `sessionID` already exists (:661) — keep it; ensure the
   live-tail finalize path uses the messageID captured **before** the sessionID filter.

## Edge cases
- Watermark slid out of the 500-cap buffer or buffer cleared (`setEvents([])` on machine
  switch, App.tsx:476/489) → full replay must be a no-op for bubble count.
- Reconnect resync (P1-061, ChatView.tsx:740): `loadHistory` replace racing the idle
  append — id map makes both orders converge to one bubble per id.
- Assistant message with multiple text parts: history joins parts with `\n`
  (`rowsToBubbles`, ChatView.tsx:121), stream sees one part at a time — same messageID
  must collapse to ONE bubble; history version wins after fetch.
- Optimistic user bubble without messageID (:1176) + `message.updated` echo tagging
  (:667): promote in place, never add a second bubble with the same id.
- Rows with no text/images produce no bubble — ids must not be required for them.
- Switching sessions mid-stream: stale `liveText` must not render in the new session.
- Legacy daemons answering a plain array (no paging envelope) — unaffected paths.

## Acceptance criteria
1. Unit (new `scripts/bubble-merge.test.ts`, wired into `npm run test:unit`): merging
   `[hist(a1..a4)]` with `[stream(a4'), user(u1), stream(a5)]` where `a4'` repeats a1's
   id yields exactly 5 unique-id bubbles, order `a1..a4,u1,a5`; replaying the same
   incoming list twice is a no-op the second time (idempotent).
2. Desktop-flow repro (extends `scripts/desktop-flow.test.ts` local-boot block): spawn a
   fake opencode backend serving `/session/<id>/message` with ≥6 fixed rows (pattern:
   `scripts/message-paging.test.ts`), point the hermetic daemon's `OPENCODE_URL` at it,
   then `location.hash = '#/session/<id>'` → back to list → re-enter, 3x. After each
   re-entry probe `document.querySelectorAll('.messages .msg').length`
   (selectors verified at ChatView.tsx:1594-1653); the count must equal the row count
   every time (delta 0 across the 3 re-entries).
3. `npm run typecheck` and `npm run build` pass (all workspaces).
4. `npm run test:unit` and `npm run test:desktop-flow` pass.
5. Manual/visual: evidence shots of the re-entered session at 1440x900 and 390px saved
   under `~/.opencode-remote/pilot/shots/builder/` — no duplicated bubble pairs, styling
   untouched (design bar intact).
