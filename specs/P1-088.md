# P1-088 — Draft por sessão + input estável no composer

## Problem

The operator types a message, switches to another session, and the text they typed
"troca de mensagem no mesmo campo": the composer text is shared between sessions.
Root cause: `ChatView` is mounted persistently and is NOT keyed by session
(`apps/web/src/App.tsx:874` — "the chat is persistent"), so the single
`const [input, setInput] = useState("")` (`apps/web/src/components/ChatView.tsx:225`)
survives a session switch and shows session A's draft inside session B. Worse, the
draft is also lost on unmount/remount paths (mobile back → reopen). Send clears the
shared text (ChatView.tsx:1149), so a half-typed message in B can be wiped by sending in A.

## Approach

1. **New pure module `apps/web/src/lib/drafts.ts`** (mirrors the `sessionCache.ts`
   precedent — memory-only, unit-testable, no DOM):
   - `const drafts = new Map<string, string>()` keyed by sessionId, cap 100 entries
     (oldest-evicted on insert).
   - `getDraft(id): string`, `setDraft(id, text)` (stores trimmed-as-is value; empty
     string deletes the key), `clearDraft(id)`, `appendDraft(id, text)` (appends with a
     single space separator, returns the new value). Export `DRAFTS_MAX = 100` for tests.
2. **ChatView writes through the draft map**:
   - Keep `input` state for rendering, but every write goes through
     `updateInput(value)` / `appendToInput(text)` helpers that use `sessionIdRef.current`
     (already kept in sync at ChatView.tsx:359/410) to write `setDraft(sid, ...)` AND
     `setInput(...)` only when `sid === sessionIdRef.current`.
   - Restore: a `useEffect` on `[sessionId]` does `setInput(getDraft(sessionId))`.
     Initialize `useState(() => getDraft(sessionId))` so remounts also restore.
   - `send()` (ChatView.tsx:1141): replace `setInput("")` with `updateInput("")` —
     clears ONLY the sending session's draft (it is the current one at click time).
   - Async appends — `micUp` (ChatView.tsx:1471) and `processVideo`
     (ChatView.tsx:1374, 1391): capture `const sid = sessionId` when the action starts;
     on resolution call `appendToInput` with `sid` (draft always lands in the origin
     session; visible input updates only if the operator hasn't navigated away).
3. **Invariant — no stream/event effect writes the user's input**: today the streaming
   path already uses the separate `liveText` state (ChatView.tsx:617-767) and never
   touches `input`. Keep it that way: after this change the ONLY `setInput` owners are
   the textarea `onChange` (2091), `send`, `micUp`, `processVideo` and the sessionId
   restore effect. Add a short comment at the `input` declaration stating the invariant
   so reviewers can grep-enforce it (`rg 'setInput\(' ChatView.tsx` — every hit must be
   one of those five sites).

- `apps/web/src/components/ChatView.tsx` — draft keyed by sessionId: restore effect + `useState` initializer; `updateInput`/`appendToInput` helpers; `send()` clears only the current session; mic/video appends pin the origin session; invariant comment on the `input` state.
- `scripts/unit.test.ts` — new block importing `apps/web/src/lib/drafts.ts` (same style as the sessionCache tests, line ~506).
- `scripts/desktop-flow.test.ts` — extend the P1-070 "local boot" block (after the P1-080 overflow section, `localEnv` still open) with the A/B composer scenario.
- `README.md`, `README.pt-BR.md` — one line each: composer drafts are kept per conversation.

## Edge cases

- Async result lands after a session switch (voice transcription, video note): the
  append must go to the ORIGIN session's draft, never to the on-screen composer of
  another session; the on-screen input is untouched when `sid !== sessionIdRef.current`.
- First visit to a session: `getDraft` returns `""` — composer starts empty (no bleed from A).
- Emptying the composer: `setDraft(id, "")` deletes the key — no `""`-valued entries, and
  going back shows an empty field.
- Typing DURING the restore effect: the effect is the last writer on navigation (runs
  after commit of the new `sessionId`); user keystrokes after it write through
  `updateInput` with the new id — no stale-write window in practice.
- Reload/restart: drafts are memory-only (same lifecycle as the bubble cache) —
  intentionally NOT persisted to localStorage.
- Voice `liveText` (streaming transcription) and pending images are separate states;
  per-session attachments are NOT part of this fix.
- Offline send: `send()` clears the input optimistically before the request
  (ChatView.tsx:1149) — unchanged semantics, now scoped to the current draft.

## Acceptance criteria

- `npm run typecheck && npm run build && npm run test:unit` all green.
- Unit (new block in `scripts/unit.test.ts`, runs in the `test:unit` chain):
  `setDraft("a","x"); getDraft("b") === ""` (independence); `getDraft("a") === "x"`;
  `setDraft("a","") → getDraft("a") === ""` (empty deletes); `appendDraft("a","y") === "x y"`;
  after `clearDraft("a")`, `getDraft("a") === ""`; inserting `DRAFTS_MAX + 1` keys evicts
  the first (`getDraft(first) === ""`).
- Desktop-flow (hermetic local boot, real app, extend `scripts/desktop-flow.test.ts`):
  1. deep-link `location.hash = '#/session/ses-draft-a'` → `["type", ".composer textarea", "rascunho A"]`;
  2. deep-link `#/session/ses-draft-b` → ipc probe `document.querySelector('.composer textarea').value` is `""`;
  3. type `rascunho B` there;
  4. deep-link back to `ses-draft-a` → probe value is `rascunho A`;
  5. click `.composer button.primary` → composer becomes `""`; switch to B and back to A → value stays `""` (sent draft never restored).
- `rg 'setInput\(' apps/web/src/components/ChatView.tsx` shows exactly the five documented
  owner sites (onChange, send, micUp, processVideo ×2 — or their `updateInput` wrappers).
- No relay/protocol/crypto changes; `npm run lint` green.

## Out of scope

- Persisting drafts to localStorage/daemon or syncing them across devices.
- Per-session attachments (pending images stay component-scoped).
- Any change to `scripts/invariants.ts`, `deploy/`, crypto, handshake allowlist, replay
  protection or the 0600 state file.
- Changing composer visuals/copy (no design change; i18n dictionaries untouched).
- Refactoring `liveText`, the offline queue (`ocr.queue.<sessionId>`) or ChatView paging.
