# P1-072 — Auto-preview: agent constrói → app abre o site sozinho, grande e interativo

## Problem

Hoje, quando o agent sobe um site local (ex.: `python -m http.server`), o usuário precisa
abrir o pane Browser e colar a URL na mão (repro 17:4x, site de inferência privada). Pior:
o pane atual renderiza **screenshots** via `/api/browse` (Playwright no host) — scroll, click
e edit não funcionam de verdade. E o prompt de sessão (apps/daemon/src/sessionctx.ts:19)
até **proíbe** o agent de servir preview por http.server.

## Approach

Três consertos, na ordem de dependência:

1. **DETEÇÃO (daemon)** — novo módulo puro `apps/daemon/src/preview.ts` (padrão localws.ts:
   helpers puros testáveis, pois index.ts roda main() no import):
   - `extractLocalUrls(text: string): string[]` — regex determinística para
     `http(s)://(localhost|127.0.0.1):<port>` (exige porta explícita, 1..65535); ignora URLs
     não-loopback e a porta própria do daemon (:8792) p/ não se auto-disparar; cap de
     comprimento por URL (2048) e máx. 4 URLs por chamada.
   - `PreviewDedupe` — Map `sessionID:url` → ts, TTL 10min, cap 100 entradas.
   - Em `forwardEvents()` (apps/daemon/src/index.ts:1245): rastrear `messageID→role` a partir
     de `message.updated`; em `part.type === "text"` de role assistant (role desconhecido ⇒
     tratar como assistant, fail-open), extrair URLs, dedupe, e `broadcast` evento sintético
     `ocr.preview { sessionID, url }` — mesmo envelope `{type:"event", event:{id,type,properties}}`
     de `ocr.permission.auto` (index.ts:1226). O relay continua roteador cego (payload selado).
2. **CLIENT (auto-open)** — em App.tsx o handler `client.onEvent` (linha ~260) ganha um ramo:
   evento `ocr.preview` + bridge desktop presente (`browseFn` não-nulo) ⇒ `setPreviewUrl(url)`
   + `dispatchView({type:"open", slot:"browser"})`. O layout desktop já mantém o chat
   persistente à esquerda do `desk-pane` (App.tsx:799-825) e o BrowserView já tem botão ←
   (`onBack`) — requisito (b) sai quase de graça. No PWA (sem bridge) o evento é ignorado
   (localhost do Mac não é alcançável do celular mesmo).
3. **PANE INTERATIVO (webview real)** — em Electron, o BrowserView passa a renderizar
   `<webview>` nativo:
   - apps/desktop/src/main.ts: adicionar `webviewTag: true` ao webPreferences (manter
     `contextIsolation: true, nodeIntegration: false, sandbox: true`).
   - BrowserView.tsx: se `window.ocrDesktop` existe → modo webview: `<webview src={url}
     allowpopups={false} webpreferences="contextIsolation=yes, sandbox=yes">`; barra editável
     (valida http/https, reutilizar a lógica de `browseTarget` em browse.ts:30 como pure
     import), botão ↻ reload e botão maximize que alterna `.maximized` no `desk-pane`
     (`.desk-pane.maximized { width: 80vw; min-width: 0; }` em index.css). Sem bridge → modo
     screenshot atual (PWA nunca ganha webview). `crashed`/`did-fail-load` mostram o erro e
     o botão reload; nada de placeholder.
   - Visual: tokens existentes (var(--surface), var(--border), radius 8), mesma densidade da
     barra atual — nada de gradiente/emoji.

Habilitar o agente: atualizar a linha 19 do prompt de sessão (sessionctx.ts) — em vez de
proibir http.server, orientar: documentos/artifacts seguem o protocolo; **sites/servidores
locais devem mencionar a URL `http://localhost:<porta>` na resposta** para o pane abrir sozinho.

## Edge cases

- URL não-loopback (`https://example.com`) ou sem porta (`http://localhost`) → nunca emite preview.
- Menção repetida da mesma URL durante o build → `PreviewDedupe` (10min) evita re-navegar o pane
  a cada token; dedupe client-side adicional por `lastPreviewUrl` no App.
- Parte de texto do usuário (pergunta colada com URL) → não emite (role user via message.updated).
- Cliente novo + daemon velho (e vice-versa): evento desconhecido é simplesmente ignorado.
- Relay: evento via envelope selado existente — nada de plaintext no relay/log (constituição #1).
- webview: `allowpopups={false}`, sem nodeIntegration, src só http/https; `file://` rejeitado na
  barra de URL; crash do webview → mensagem + reload, sem derrubar o app.
- Pane já aberto em outra URL → navega para a nova; usuário navegou manualmente → próxima
  preview ainda assume o controle (comportamento desejado: agent mandou, app mostra).

## Acceptance criteria

1. `npx tsx scripts/preview.test.ts` (via `npm run test:unit`) verde, pinando:
   `extractLocalUrls("suba http://localhost:3000 e http://127.0.0.1:5173/x")` → 2 URLs,
   na ordem; ignora `https://example.com` e `http://localhost` sem porta; ignora `:8792`;
   `PreviewDedupe` → 2ª emissão da mesma `sessionID:url` em <10min é descartada;
   `previewFromEvent` rejeita envelope sem `ocr.preview`.
2. `npm run test:desktop-flow` estendido: sobe fake server `http` em 127.0.0.1:<porta
   aleatória> servindo HTML com texto-marcador; lança o app real (harness P1-051) e, via
   `page.evaluate`, monta um `<webview src=...>` na página; aguarda `did-finish-load`,
   `executeJavaScript` devolve o marcador e simula scroll/click (scrollTo + click em botão
   do próprio fake server) — tudo <60s, exit 0.
3. Repro manual: pedir um http.server ao agent ⇒ o evento `ocr.preview` aparece no stream,
   o pane abre side-by-side (chat à esquerda), botão ← volta pro chat, scroll/click/edit
   funcionam no webview, maximize alterna ~80% (medido: `.desk-pane.maximized` width 80vw).
4. `npm run typecheck && npm run build` verdes; `npm run test:unit` completo verde.
5. `grep -r "http.server" apps/daemon/src/sessionctx.ts` retorna a linha nova (permite e
   orienta), e `scripts/preview.test.ts` pin o texto novo do prompt.
6. READMEs/AGENTS.md descrevem o auto-preview; nenhum arquivo fora da lista acima é tocado;
   `scripts/invariants.ts` e `deploy/` intocados.

## Out of scope

- PWA/celular: auto-open de preview (localhost do Mac é inalcançável do phone) — evento chega e é ignorado.
- Migrar Mission Control ou outros panes para webview; o modo screenshot continua para o
  browser-driving de reviewers (`tools/browse.mjs`, `/api/browse` intocado).
- Detecção por heurística de tool-call ("iniciou server") — só parse determinístico de texto.
- Histórico/abas múltiplas no pane (uma URL viva por vez).
- Alterar `scripts/invariants.ts`, `deploy/`, cripto E2E, allowlist ou replay protection.
