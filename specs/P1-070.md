# P1-070 — Desktop local nunca pede pareamento: auto-connect no daemon da máquina

## Problem

Numa instância fresca do desktop (sem pairing em localStorage), com o daemon são
e saudável no mesmo disco, a UI abre na tela de pareamento/QR (P2-007): o
auto-pair depende de achar o URI de pairing via stdout/daemon.log
(`getPairUrl()`, apps/desktop/src/daemon.ts:235) e o overlay de QR renderiza
sempre que `!phonePaired && qrDataUrl` (apps/web/src/App.tsx:588). Isso é um bug
de modelo mental: no host, o app e o daemon compartilham o mesmo trust domain
(arquivo 0600 `~/.opencode-remote/daemon.json`, loopback, mesmo usuário) — o
P1-061 já provou o transporte local (WS loopback com token, E2E intacto), mas o
boot ainda conduz o usuário por uma cerimônia de pareamento sem sentido local.

## Approach

Detecção em boot + modo explícito, tudo aditivo (cripto/allowlist/state 0600
intocados):

1. **`apps/desktop/src/pairing.ts`** (puro, sem electron): `PairingState` ganha
   `mode?: "local" | "remote"` (undefined = legado). Novo helper puro
   `localPairing(link: { port: number; token: string; room: string; ecdhPub: string }): Pairing-shaped`
   que monta `{ v: 2, relay: localWsUrl(port, token), room, k: ecdhPub, name: "local" }`
   — mesma receita provada em scripts/localws.test.ts:282-295 (k = `ecdhPub` do
   daemon.json, room = `room` do daemon.json, relay = a própria URL local).
   Retornar `null` se faltar campo.
2. **`apps/desktop/src/main.ts`**:
   - Em `onReady`, após `startDaemonSidecar`/`waitForDaemonHealth`:
     `localMode = healthOK && readApiToken() !== null` (o `healthOnce` de
     daemon.ts já faz o challenge 401 anti-squatter antes do Bearer). Hatches
     `OCR_DAEMON_FORCE_*` vence o modo local (determinismo do gate).
   - `refreshPairingState()`: com `localMode` e poll saudável, setar
     `{ mode: "local", uri: null, qrDataUrl: null, devices, phonePaired, appVersion, daemonVersion, versionMismatch }`
     — NUNCA buscar `__ocr/pairing-uri` nem gerar QR (mata o overlay do boot).
     Falha de poll no modo local cai na degradação existente
     (reconnecting/daemon-down/null), sem QR. `remotePairingRequested`
     (flag em memória) reabilita o fluxo de QR: aí sim busca uri+QR e publica
     `{ mode: "remote", uri, qrDataUrl, ... }`.
   - IPC `app:localLink` (main.ts:307): passar a retornar
     `{ port, token, room, ecdhPub }` lidos do daemon.json (leitura 0600
     existente; loopback-only, mesmo trade-off já documentado no P1-061).
   - Novo IPC `app:setRemotePairing(on: boolean)` → liga/desliga
     `remotePairingRequested` (off volta ao estado local no próximo tick).
3. **`apps/desktop/src/preload.ts` + espelho da interface em
   `apps/web/src/App.tsx`** (`interface PairingState`, linha ~51 — manter em
   sync): expor `setRemotePairing` e o `LocalLink` estendido.
4. **`apps/web/src/App.tsx`**: no `tryAutoPair()`, ANTES do caminho
   `getPairUrl`: se `bridge.getLocalLink` existir e o pairingState reportar
   `mode === "local"`, montar o pairing via `localPairing(await getLocalLink())`
   e `connect(localPairing, false)` — **sem `saveState`** (não persistir token
   de loopback no localStorage; re-derivado a cada boot). Fallback: erro de
   connect local cai no fluxo atual (auto-pair por URI / tela unpaired).
   O overlay continua gated por `qrDataUrl` (local nunca o tem) + dismiss
   chama `setRemotePairing(false)`.
5. **`apps/web/src/components/SettingsView.tsx` + `apps/web/src/lib/i18n.ts`**:
   seção/país de ação "Parear um telefone (dispositivo remoto)" visível só com
   bridge (desktop), chamando `setRemotePairing(true)`; chaves i18n EN + pt-BR.
   Estilo discreto consistente (sem gradientes/emoji — bar Linear/Raycast).
6. **Docs**: README.md (~linha 270 "Zero pairing on the host machine" e ~280
   P1-061), README.pt-BR.md, docs/security.md item 9 (escopo do IPC estendido:
   room/ecdhPub para o renderer same-user) e AGENTS.md (seção desktop) —
   descrever: boot com daemon local sadio entra direto no chat; QR só via
   Configurações ou deep link.

## Edge cases

- Sem daemon local (state file ausente/token nulo/health ≠200): comportamento
  atual preservado — tela de pareamento (modo remoto é o default aí).
- Squatter 200-anywhere na porta: `healthOnce` exige o challenge 401 JSON +
  Bearer correto do arquivo 0600 — nunca adota respondente anônimo.
- Token rotacionado/daemon trocado no meio do run: poll falha → degradação
  existente; recuperação re-deriva o localPairing (getLocalLink relê o arquivo).
- Daemon rejeita o host ("rejected by daemon"): superfície de erro existente;
  nada de limpar allowlist automaticamente.
- Hatches `OCR_DAEMON_FORCE_DOWN/RECONNECTING/VERSION_MISMATCH` têm precedência
  sobre o modo local (gate hermético continua determinístico mesmo em máquina
  com daemon real — o `OCR_DAEMON_STATE_FILE` temporário do harness já isola).
- PWA/browser sem bridge: zero mudança (relay-only, `getLocalLink` ausente).
- `scripts/invariants.ts` (regexes sobre main.ts/daemon.ts) — mudanças aditivas;
  nenhuma linha protegida removida.

## Acceptance criteria

1. `npx tsx scripts/unit.test.ts` verde, incluindo: `localPairing` com state
   completo → `{ k: ecdhPub, room, relay: "ws://127.0.0.1:<port>/ws?token=…" }`;
   campos faltando → `null`; estado `mode:"local"` com uri/qr null nunca renderiza
   overlay (`overlayVisible` false).
2. `npx tsx scripts/localws.test.ts` permanece verde (P1-061 sem regressão).
3. `npx tsx scripts/desktop-flow.test.ts` verde com novo bloco "local boot":
   daemon REAL hermético (padrão localws.test.ts: HOME=tmp, porta livre) +
   launch com `OCR_DAEMON_STATE_FILE` do fixture, `OCR_DAEMON_METRICS_PORT`,
   entry inexistente (sem sidecar) e userData fresco (sem pairing em
   localStorage). Asserts: `getPairingState()` → `mode==="local"`, `uri===null`,
   `qrDataUrl===null`; DOM sem `.pair-overlay` e sem `.pair-submit`; ganchos
   `data-phase="paired"` no `#root` (atributo novo, aditivo) visível; shots
   `~/.opencode-remote/pilot/shots/builder/P1-070-local-boot.png` (1440x900) e
   `-390.png`. Se o budget de 60s estourar, subir `DEADLINE_MS` para 90s
   documentando no commit (AGENTS.md cita <60s — atualizar na mesma PR).
4. `npm run typecheck && npm run lint && npm run build` verdes.
5. Repro do task verificado pelo bloco do critério 3: pairing storage vazio +
   daemon rodando ⇒ app abre direto no chat, nenhum QR; parar o daemon ⇒
   banner/degradação existentes; parear telefone continua possível via
   Configurações ou deep link (caminho P2-007/P3-014 intacto).

## Out of scope

- Cripto E2E, handshake, allowlist, replay (seq-in-AAD), formato do state 0600,
  apps/relay e apps/daemon (constituição 1 e 2 — apenas leituras novas do
  daemon.json já existentes).
- `scripts/invariants.ts` e `deploy/` (constituição 3).
- Formato/rota do pairing URI, QR scanner do celular, UI mobile/PWA.
- Descoberta de daemon em porta custom (mantém `DAEMON_METRICS_PORT` única).
- Migrar pareamentos remotos existentes para o modo local.
