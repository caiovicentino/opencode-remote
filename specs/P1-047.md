# P1-047 — Design tokens + light theme funcional

## Problem
O shell usa `--panel/--bg2/--fg` e `data-theme="light"` existe (P2-055 definiu os tokens
básicos em `apps/web/src/index.css:1-45`), mas o sistema de design continua incompleto e o
light theme quebrado:

1. **Hex/rgba hardcoded em 8 arquivos TSX** (com fallbacks de token inexistente):
   `ChatView.tsx:1491,1588-1589,1752,1811,1828,1892,1903-1905` (ex.: `var(--text-muted, #aaa)`
   mas `--text-muted` nunca foi definida; overlays `rgba(0,0,0,0.94)`), `SessionsView.tsx:194,283,320,337,375`
   (ex. `#2ecc71`, `#9ca3af`), `FileCard.tsx:65,197,209`, `FilesView.tsx:163,221`,
   `ArtifactViewer.tsx:71,85,186,194,245,291`, `BrowserView.tsx:167,170`, `SettingsView.tsx:630`.
   No light theme esses pontos continuam escuros (overlay preto 94%, texto `#aaa`, bordas
   `rgba(255,255,255,0.1)`).
2. **Hex solto no próprio index.css** fora do bloco de tokens: `#06280f` (110), `#052e12` (442),
   `#fff` QR (791), `rgba(248,113,113,0.12)` (806, 835), `rgba(0,0,0,0.35)` (902).
3. **Patchwork `!important`+`nth-child`**: index.css:599-668 (49 `!important` no arquivo)
   reestiliza `.desk-side .card.session-card > div:nth-child(n)` — frágil, quebra se a
   estrutura do card mudar (SessionsView.tsx:309).
4. **Tema não respeita o SO**: `applyTheme()` (SettingsView.tsx:74-79) só aceita
   `dark`/`light` do localStorage `ocr_theme`, default `dark`; sem opção "system".
5. **Escala incompleta**: não há tokens de espaçamento nem tipografia; `--status-err`
   não existe (SessionsView mapeia `err → --danger` ad hoc).

## Approach
**Tudo que é literal de cor vive num único arquivo: `apps/web/src/tokens.css`**
(criar, importado na 1ª linha de index.css via `@import './tokens.css';`).

1. **tokens.css** com dois blocos — `:root` (dark, default) e `:root[data-theme="light"]`:
   - cores atuais (bg, surface, panel, bg2, border, text/fg, muted, accent, danger, warn,
     user-bubble, status-ok/wait/work/done) — valores escuros atuais inalterados;
   - novos tokens semânticos: `--status-err` (dark `#f87171`, light `#dc2626`),
     `--on-accent` (texto sobre botão accent: `#06280f` / `#06280f`), `--scrim`
     (overlays de modal: `rgba(0,0,0,0.94)` dark / `rgba(24,24,27,0.92)` light),
     `--shadow-overlay` (0 18px 48px rgba(0,0,0,.35) / versão light mais suave),
     `--banner-danger-bg`, `--qr-bg` (#fff em ambos — contraste de scanner),
     `--on-danger` (#fff);
   - escala de espaçamento `--space-1..6` (4/8/12/16/24/32px) e tipografia
     `--font-size-xs/sm/md/lg` (0.72/0.85/0.95/1.15rem), `--font-weight-medium: 500`;
   - raios já existem (`--radius-*`), apenas movem para tokens.css.
2. **`applyTheme` (SettingsView.tsx)**: valores `dark | light | system`, default `system`;
   em `system`, `data-theme` = `matchMedia('(prefers-color-scheme: light)')` + listener
   `addEventListener('change')` para trocar ao vivo (remover listener anterior ao re-aplicar).
   Settings → Appearance ganha `<option value="system">System</option>` (SettingsView.tsx:395-398).
   `dark`/`light` salvos continuam funcionando (localStorage compatível).
3. **Migração TSX**: substituir cada literal por `var(--token)` correspondente
   (`var(--text-muted, #aaa)` → `var(--muted)`; `#2ecc71` → `var(--status-ok)`;
   `#9ca3af` → `var(--status-done)`; `rgba(0,0,0,0.94)` → `var(--scrim)`;
   `#fff` em botão/iframe → `var(--on-danger)`/`var(--surface)` conforme contexto;
   `rgba(46,160,67,0.18)`/`rgba(248,81,73,0.18)` → `color-mix(in srgb, var(--status-ok) 18%, transparent)`
   e idem danger).
4. **Fim do patchwork**: SessionsView.tsx (bloco do card de sessão, ~309-340) passa a
   emitir classes reais (`session-title`, `session-snippet`, `session-meta`); index.css
   reescreve os seletores `.desk-side .card.session-card > div:nth-child(n)` como
   `.desk-side .session-title` etc., **sem `!important`** e sem `nth-child`, mantendo o
   visual atual (linha única, ellipsis, hover `--bg2`). Revisar os outros `!important`
   do bloco 599-668 (input de busca, chips, desk-nav) substituindo por seletores de
   classe reais; os `!important` de normalização fora desse bloco (`.typing`, iframes)
   ficam.
5. **Docs**: user-visible (tema system + light corrigido) → 1 linha em docs apropriados.

## Edge cases
- Primeiro load sem `ocr_theme`: deve vir `system` (hoje é `dark`) — iOS/webview em
  modo escuro do SO não pode "flashar" light.
- Listener `matchMedia` deve ser removido/trocado ao re-aplicar tema (App.tsx:220 chama
  `applyTheme()` no boot; saveTheme chama de novo) — sem leak de listeners.
- QR code precisa continuar branco puro em ambos os temas (contraste de scanner).
- `user-bubble`, `accent` e `danger` precisam de contraste WCAG AA no light
  (accent light `#16a34a` com texto `--on-accent` escuro).
- Overlays de diff/preview usados dentro de `.desk-pane` (fundo claro) — scrim deve
  cobrir viewport inteira (`position: fixed`) como hoje.
- `color-mix` já é usado no repo (index.css:764, 820, 887) — engine OK (Electron/wkwebview).

## Acceptance criteria
1. `rg -n '#[0-9a-fA-F]{3,8}\b|rgba?\(' apps/web/src --glob '!tokens.css'` → **zero
   matches** em `apps/web/src` (tokens.css e nenhum outro arquivo têm hex/rgba literal).
2. `rg -c '!important' apps/web/src/index.css` → ≤ 2 (hoje: 49) e
   `rg -n 'nth-child' apps/web/src/index.css` → só `.typing` (364-367).
3. `npm run typecheck`, `npm run test:unit` e `npm run test:desktop-flow` passam.
4. Settings → Appearance mostra System/Dark/Light; com `system`, mudar o tema do SO
   alterna dark↔light sem reload (checar via devtools: `document.documentElement.dataset.theme`).
5. Evidência EVIDENCE: 4 shots reais em `~/.opencode-remote/pilot/shots/builder/`
   (`tools/browse.mjs shot <p>.png 1440 900` e `390 844`), dark e light, desktop e mobile —
   mesma hierarquia visual entre temas (sidebar, chat, cards de sessão legíveis no light,
   sem blocos pretos).
6. Light theme: diff overlay, modais e banners legíveis (scrim tokenizado, não preto 94%
   sobre fundo claro) — conferir shot 390px light.

## Out of scope
- Mudar valores/estética do dark (design atual aprovado — só tokenizar).
- Big-bang de substituição de todo `rem`/px por `var(--space-*)` (apenas os pontos
  reescritos no passo 4 adotam a escala).
- Temas adicionais (sepia/high-contrast), troca de fonte, sync do tema entre máquinas.
- Electron/`apps/desktop` (o tema é aplicado no renderer web — nenhum change em main).
- `scripts/invariants.ts` e `deploy/` (intocados — regra 3 da constituição).
