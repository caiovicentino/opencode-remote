# P1-068 — Injetar protocolo de artifacts em toda sessão de chat

## Problem

O protocolo de artifacts (escrever docs em `~/.opencode-remote/artifacts/<sessionId>/`,
mencionar o filename na resposta, self-contained, usar `uploads/` + `[file: <path>]`
para download) hoje só chega ao agente pelo AGENTS.md do workspace (ver AGENTS.md
"Artifacts"/"Entregando arquivos"). Workspaces sem AGENTS.md (ex.: um repo "Major") criam
sessões que desconhecem o protocolo: o agente entrega preview via `python -m http.server`
ou link solto — o usuário não ganha card nem pane de Artifacts.

O daemon é o roteador de TODA sessão criada pelos clients (PWA/relay, desktop local,
API local, rotinas). O opencode server aceita `system?: string` no body de
`POST /session/{id}/message` (SessionPromptData no SDK — verificado em
`~/.opencode/node_modules/@opencode-ai/sdk/dist/gen/types.gen.d.ts`), appendo de
system prompt por turno. Pontos de criação de sessão no daemon:
`proxy()` passthrough (apps/daemon/src/index.ts:757, resposta de `POST /session`),
`fireRoutine` (index.ts:939) e `POST /api/session` (index.ts:2158).

## Approach

1. **Novo módulo `apps/daemon/src/sessionctx.ts`** (padrão localws.ts: helpers puros
   importáveis sem bootar o daemon):
   - `ARTIFACTS_MARKER = "ocr-artifacts-protocol"` — string única de dedupe.
   - `buildArtifactsPrompt(sessionId: string): string` — bloco pt-BR (~10 linhas) com:
     destino `~/.opencode-remote/artifacts/<sessionId>/` (sessionId real interpolado),
     mencionar o filename na resposta, arquivo self-contained, `uploads/` + linha
     `[file: <caminho absoluto>]` para download no celular, e "nunca servir preview por
     http.server/link solto". Primeira linha contém o marker.
   - `workspaceCoversArtifacts(directory: string): boolean` — lê
     `<directory>/AGENTS.md` (e `agents.md`); true só se o conteúdo contém
     `ARTIFACTS_MARKER` ou `.opencode-remote/artifacts`. Qualquer erro de
     leitura/parse → false (fail-open: injeta).
   - `injectArtifactsSystem(body, sessionId): body` — seta
     `body.system = [body.system, buildArtifactsPrompt(sessionId)].join("\n\n")`
     (trim de vazios); no-op se `body.system` já contém o marker.
2. **Registro de sessões criadas pelo daemon** (index.ts): `Set` em memória de sessionIds
   que precisam do protocolo. Preencher:
   - `proxy()`: quando `req.method === "POST" && req.path === "/session"`, após o
     passthrough parse do body (index.ts:770), se resposta tem `id` prefixo `ses` e
     `!workspaceCoversArtifacts(directory)` (campo `directory` da resposta) → add.
     Resposta repassada intocada.
   - `POST /api/session` (index.ts:2158) e `fireRoutine` (index.ts:939): idem, via helper
     compartilhado.
3. **Injeção por turno** (index.ts):
   - No intercept de `POST /session/<id>/message` que já existe no proxy (bloco de
     attachments, index.ts:679), se o sessionId está no Set → `injectArtifactsSystem`.
   - `POST /api/session/<id>/message` (index.ts:2182) e o POST do `fireRoutine`
     (index.ts:949) recebem o mesmo treatment.
   - Sessão registrada é injetada em todo prompt (o `system` é por turno; marker evita
     duplicação). Mantém o corpo existente (`parts`, `model`, `agent`) intacto.
4. **Docs**: README.md + README.pt-BR.md — "sessões criadas pelo daemon sempre carregam
   o protocolo de artifacts, mesmo em workspaces sem AGENTS.md".

## Touched files

- `apps/daemon/src/sessionctx.ts` (novo) — marker, builder do bloco, check de cobertura, inject.
- `apps/daemon/src/index.ts` — registro no proxy/`fireRoutine`/`/api/session` + injeção nos 3 pontos de prompt.
- `scripts/unit.test.ts` — pins dos helpers (import direto do módulo, sem daemon).
- `scripts/desktop-flow.test.ts` — seção nova que importa `sessionctx.ts` e assegura a
  injeção hermeticamente (critério da task; o gate roda em diffs de daemon também via unit).
- `README.md`, `README.pt-BR.md` — comportamento documentado.

## Edge cases

- Workspace com AGENTS.md que já cobre (`repo-1` contém `.opencode-remote/artifacts`) → Set não registra, zero injeção, zero custo de tokens.
- `directory` ausente/indefinido na resposta de criação → injeta (fail-open; pior caso é instrução redundante).
- AGENTS.md ilegível (permissões/ENOENT) → `workspaceCoversArtifacts` = false → injeta.
- `body.system` já presente (client mandou) → append depois do existente, nunca sobrescrever; marker já presente → no-op.
- Daemon restart perde o Set (memória) → sessões criadas antes do restart não são re-injetadas; documentado, aceitável.
- Sessões criadas direto no opencode (CLI/TUI, pilot) não passam pelo daemon → intocadas.
- Resposta de `POST /session` sem `id` prefixo `ses` → ignorar registro (defensivo).
- Bloco pequeno (~1KB): sem risco de estourar o frame de 1MB do relay.

## Acceptance criteria

1. `npm run typecheck --silent` e `npm run build --silent` verdes.
2. `npm run test:unit --silent` verde com novos asserts, contra os helpers reais:
   a. `buildArtifactsPrompt("ses_x")` contém `artifacts/ses_x`, o marker e a linha `[file:`.
   b. `workspaceCoversArtifacts`: tmpdir com AGENTS.md contendo o marker → true; tmpdir vazio → false; AGENTS.md sem marker/artifacts path → false.
   c. `injectArtifactsSystem`: body `{parts:[...]}` sai com `system` contendo o bloco; body com `system` pré-existente faz append; chamada dupla NÃO duplica (marker).
3. `npm run test:desktop-flow --silent` verde — nova seção assegura que uma sessão criada em workspace sem AGENTS.md recebe o bloco e que workspace coberto não recebe.
4. Comportamento E2E (manual/live-eval): sessão criada via app num workspace vazio, prompt "gere um preview HTML de <relatório>" → resposta menciona o filename e a pane Artifacts lista o arquivo (evidência: shot da pane em `shots/builder/`).
5. Nenhuma mudança no shape do request do client: `parts`/`model`/`agent` chegam ao opencode iguais (unit do inject compara o resto do body).
6. `npx tsx scripts/invariants.ts` verde (arquivos safety-critical intocados).

## Out of scope

- Mudar a API do opencode server ou o formato do envelope E2E (cripto, allowlist, replay).
- Tocar em `scripts/invariants.ts` e `deploy/`.
- Persistir o Set de sessões em disco (sobreviver a restart).
- Cobrir sessões criadas fora do daemon (CLI/TUI direto no opencode).
- Adicionar o protocolo ao AGENTS.md do usuário ou sincronizar AGENTS.md entre workspaces.
- Novos endpoints na UI; qualquer mudança visual (não há UI nova).
