# P1-096 — System prompt byte-idêntico entre sessões (prefix cache do provider)

## Problem

`buildArtifactsPrompt(sessionId)` (apps/daemon/src/sessionctx.ts:12-21) interpola o dir
por sessão `~/.opencode-remote/artifacts/<sessionId>` (linha 13) no bloco que
`injectArtifactsSystem` anexa ao campo `system` de TODO turn de toda sessão criada pelo
daemon (apps/daemon/src/index.ts:729 proxy e :1013 routines). O system prompt é o começo
do request no provider: qualquer byte por-sessão nele faz duas sessões diferentes nunca
compartilharem prefixo → cache do provider é zero pro produto (todo turn de toda sessão
re-processa todo o prompt estável). Hoje, sessões diferentes divergem no system; o fix é
tornar o `system` byte-idêntico entre sessões e mandar o caminho variável por outra via.

## Approach

Divisão estável/variável no mesmo ponto de injeção de sempre:

1. **`apps/daemon/src/sessionctx.ts`** (helpers puros, padrão do módulo):
   - `buildArtifactsPrompt()` — **sem** parâmetro. Mesmo bloco de 5 linhas, mas o bullet
     1 deixa de citar o dir concreto: "…gravado no diretório de artifacts da sessão
     (caminho exato na linha `[ocr-artifacts-path]`; crie o diretório se não existir)".
     Manter intocado: `ARTIFACTS_MARKER`, linha `[file:`, linha de http.server +
     `http://localhost:<porta>` (pinado por preview.test.ts).
   - **Novo** `buildArtifactsPathLine(sessionId: string): string` — única linha
     `[ocr-artifacts-path] Diretório de artifacts desta sessão: <abs dir>/`
     (`join(homedir(), ".opencode-remote", "artifacts", sessionId)`).
   - **Novo** `injectArtifactsPathPart<T extends { parts?: unknown[] }>(body, sessionId)`:
     faz append de `{ type: "text", text: pathLine }` ao fim de `body.parts`, a menos que
     algum part já contenha `[ocr-artifacts-path]` (idempotente). Body malformado → no-op.
   - `injectArtifactsSystem(body)` — comportamento atual (append após system do cliente,
     dedupe por marker), sem o param `sessionId`.
2. **`apps/daemon/src/index.ts`**:
   - Junto de `artifactSessions` (~linha 975), novo `const artifactPathTold = new Set<string>()`
     (in-memory, mesma limitação documentada de restart).
   - No proxy (~728) e em `fireRoutine` (~1013): sempre `injectArtifactsSystem(body)`;
     `injectArtifactsPathPart(body, sid)` só na 1ª turn da sessão — se `!artifactPathTold.has(sid)`,
     injeta e adiciona ao Set. A linha fica no histórico; turns seguintes a enxergam.

## Touched files

- `apps/daemon/src/sessionctx.ts` — bloco estável + novos `buildArtifactsPathLine`/`injectArtifactsPathPart`.
- `apps/daemon/src/index.ts` — split das duas injeções + Set `artifactPathTold` (~15 linhas).
- `scripts/unit.test.ts` (~1234-1276) — pins novos (ver Acceptance 2); remover pin do dir concreto.
- `scripts/preview.test.ts` (~184) — chamada vira `buildArtifactsPrompt()`; pins de marker/http.server seguem.
- `scripts/desktop-flow.test.ts` (~54-92) — pin do dir `ses_flow` vira "bloco independente de sessão" + pin do path part.

## Edge cases

- Workspace coberto por AGENTS.md → `registerArtifactSession` não registra (igual hoje):
  nem bloco nem path line (o AGENTS.md já ensina `<sessionId>`).
- Body sem `parts` ou só com parts não-texto → system block injetado, path part skip (fail-open).
- Chamada dupla no mesmo body → dedupe por `ARTIFACTS_MARKER` (system) e `[ocr-artifacts-path]` (parts).
- Restart do daemon → Sets in-memory zeram; só sessão nova recebe injeção (comportamento
  já documentado em index.ts:972-975).
- `homedir()` no bloco é estável por instalação → não quebra cache cross-session na mesma máquina.
- Relay continua roteador cego: body trafega dentro dos frames selados E2E, nada de log
  plaintext (constituição #1).

## Acceptance criteria

1. `npm run typecheck && npm run build` → exit 0.
2. `npm run test:unit` verde com os pins novos em scripts/unit.test.ts:
   - Byte-exato: `injectArtifactsSystem` em dois bodies com `ses_a`/`ses_b` produz strings
     `system` **idênticas** (`a.system === b.system`).
   - `buildArtifactsPrompt()` NÃO contém `join(homedir(), ".opencode-remote", "artifacts", ...)`
     nem id de sessão algum; contém marker, `[file:` e `http://localhost:<porta>`.
   - `buildArtifactsPathLine("ses_a")` contém `[ocr-artifacts-path]` e o dir absoluto de `ses_a`.
   - `injectArtifactsPathPart`: append no fim de `parts`; 2ª chamada no-op; parts do usuário intactos.
3. `npm run test:desktop-flow` e `npm run test:e2e` verdes (pins atualizados conforme Touched files).
4. `grep -n "sessionId" apps/daemon/src/sessionctx.ts` não mostra interpolação de id dentro
   do bloco de system (só em `buildArtifactsPathLine`).
5. Sem mudança user-visible (artifacts continuam nos mesmos dirs; pane/listagem intactos) →
   READMEs intocados; `scripts/invariants.ts` e `deploy/` intocados.

## Out of scope

- Mudar onde artifacts são gravados ou o formato de listagem no pane (apps/web) — intocados.
- Migrar outros prompts do daemon para o padrão estável/variável (ex.: título de rotina).
- Persistir `artifactPathTold` em disco (mesma semântica in-memory de `artifactSessions`).
- Tocar cripto E2E, allowlist, replay protection, `scripts/invariants.ts` ou `deploy/`.
- Reescrever o texto do protocolo além do estrito necessário (bullet 1) — risco de quebrar
  pins de preview.test.ts.
