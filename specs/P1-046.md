# P1-046 — Desktop shell v2: duas colunas reais + navegação sã

## Problem
No desktop (≥1024px) a UI hoje tem um único `.desk-main` cujo conteúdo é escolhido
por 5 booleanos (`session`, `settings`, `filesView`, `artifactsView`, `browserView`,
apps/web/src/App.tsx:130-133). Consequências reais:
- Abrir Artifacts/Browser/Config/Arquivos zera `session` (App.tsx:671-719) — o chat
  é desmontado e o usuário perde o contexto da conversa.
- `mainContent` (App.tsx:625-637) é uma cadeia `?:` que prioriza um pane só; a
  ordem dos booleanos decide o vencedor em vez de uma regra de navegação.
- Bugs de estado: o botão Arquivos (App.tsx:699-710) só limpa `browserView` —
  deixa `artifactsView` ligado; Config (711-719) só limpa `browserView`. Dois
  botões do rail ficam `.active` simultaneamente e `goBack` (423-440) precisa
  adivinhar qual booleano derrubar primeiro.

## Approach
Toda a navegação vive em **um `useReducer` puro** e o desktop vira **3 colunas**:

1. **Reducer único** — novo `apps/web/src/lib/viewState.ts` (puro, sem React):
   - `type Slot = "chat" | "artifacts" | "browser" | "files" | "settings" | "share"`;
   - `ViewState = { stack: Slot[]; chatSession: string | null }`;
   - `viewReducer(state, action)` com ações `open(slot)`, `openChat(sessionId)`,
     `closeChat()`, `back()`, `replace(slot)`;
   - invariantes garantidas no reducer: `stack` não tem duplicatas, `back()` dá
     pop, `open(slot)` substitui o slot no topo; `chatSession` é limpo só por
     `closeChat`/`switchMachine`/`disconnect` — **abrir pane nunca toca o chat**;
   - exportar `topSlot(state)` (fallback `"chat"` quando stack vazia) e
     `activeSlots(state)` (set para pintar o rail).
2. **Layout desktop** — em `App.tsx`, o branch `isDesktop` renderiza
   `.desk-side` (hoje) + `.desk-chat` (ChatView persistente do `chatSession`,
   ou `.desk-empty` se null) + `.desk-pane` contextual à direita (~480px,
   `display:none` quando stack vazia) com Artifacts/Browser/Files/Settings.
   BrowserView continua montado-escondido (preserva URL/página, App.tsx:726-732).
   O rail `.desk-nav` marca `.active` só via `activeSlots()` — impossível ter 2.
   Mobile (390px) não muda visualmente: o mesmo reducer alimenta o `mainContent`
   existente (topo do stack) e o `TabBar` (App.tsx:748-768).
3. **Atalhos** — Electron: `buildMenu()` (apps/desktop/src/main.ts:549-581) ganha
   menu "Go" com accelerators `CmdOrCtrl+T` (nova conversa), `CmdOrCtrl+K`
   (palette), `CmdOrCtrl+1..5` (chat/artifacts/browser/arquivos/config); cada
   item faz `win.webContents.send("ocr:menu-action", id)`. `preload.ts` expõe
   `onMenuAction(cb) => unsubscribe`; `App.tsx` despacha no reducer. Web puro
   (dev no browser): fallback `keydown` com `(metaKey||ctrlKey)` — best-effort,
   sem garantia fora do Electron. Cmd+T = mesma ação de `createSession()`
   (SessionsView.tsx:101-119) quando o daemon está conectado.
4. **Command palette (Cmd+K)** — novo `apps/web/src/components/CommandPalette.tsx`:
   overlay flat estilo Raycast/Linear (bg `--panel`, borda `--border`,
   `--radius-sm`, sem gradientes/emoji), input busca sessões
   (`GET /session` + `applySessionFilters`) e ações fixas (nova conversa,
   abrir artifacts/browser/arquivos/config). Navegação ↑/↓/Enter/Esc.
5. **Deep links** — rotas `#/session/:id`, `#/files`, `#/artifacts`
   (App.tsx:244-281) passam a despachar actions equivalentes.

## Edge cases
- Aberto Artifacts com sessão ativa: chat **permanece montado** à esquerda
  (scroll/streaming preservados); pane abre à direita.
- `switchMachine`/`disconnect` (App.tsx:388-410) devem resetar stack e `chatSession`.
- Share Target (`#/send`, App.tsx:248-257): share entra no stack; `back()` pop.
- Browser sem bridge (`browseFn === null`, browser dev): pane Browser mostra estado
  vazio, não crash (BrowserView já trata `browse: null`).
- Atalhos quando `phase !== "paired"`: ignorados (sem client, nada p/ abrir).
- Cmd+1..5 com janela sem foco no renderer: Menu do Electron só emite p/ a
  window focused — nada a fazer.
- keydown fallback não deve disparar 2x no Electron (o bridge já cobriu): registrar
  keydown só quando `desktopBridge() === null`.

## Acceptance criteria
1. `npm run typecheck && npm run lint && npm run test:unit` verdes na raiz.
2. `npm run test:desktop-flow` verde (<60s) — fluxo estendido: abrir app, abrir
   pane Artifacts via Cmd+1..5 (dispatch direto no driver), assert 2 colunas visíveis.
3. Novos testes unitários do `viewReducer` cobrem: abrir artifacts com sessão
   ativa mantém `chatSession`; `open(files)` após `open(artifacts)` deixa
   `activeSlots()` com **1** pane só; `back()` popa; share entra/sai do stack.
4. Shots reais 1440x900 em `~/.opencode-remote/pilot/shots/builder/`:
   (a) chat + Artifacts lado a lado, ambos legíveis; (b) palette Cmd+K aberta
   sobre o layout; (c) rail com exatamente um botão `.active` em cada shot.
5. `npm run dist --workspace @ocr/desktop` builda; no app empacotado, Cmd+T cria
   conversa, Cmd+K abre palette e Cmd+1..5 trocam panes (evidência: shot +
   log do driver citando o action id recebido via `ocr:menu-action`).
6. Mobile 390px: `npm run build --workspace @ocr/web` + screenshot 390px —
   sem regressão visual (TabBar e telas como antes).

## Out of scope
- Criar sessões "scratch" offline ou fila de envio pendente (Cmd+T exige daemon vivo).
- Refactor visual do ChatView/SessionsView (só o shell ao redor).
- Atalhos por teclado no PWA mobile (teclado físico não é o alvo).
- Persistência do layout/pane aberto entre reinícios do app.
- Qualquer mudança em `scripts/invariants.ts`, `deploy/`, cripto ou allowlist.
