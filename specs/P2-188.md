# P2-188 — relay hospedado serve o bundle estático (preflight fail-closed)

## Problem
`apps/relay/src/healthz.ts:62` responde `404` para todo caminho HTTP que não seja
`/healthz`: o relay do estágio 4 roteia frames e nada mais. A única origem que hoje
entrega o app ao celular é a origem tailnet do watchdog `apps/daemon/src/pwawatch.ts`
(proxy de `127.0.0.1:5173`), que quem instala um DMG nunca terá. Resultado: a missão de
`docs/VISION.md:8` ("sem terminal, sem TLS, sem tailscale") trava no primeiro passo —
não existe URL para o usuário leigo abrir no telefone antes de escanear o QR.

## Approach
1. **`apps/relay/src/webroot.ts` (novo, puro)** — só `node:path` (`basename`, `extname`,
   `join`, `resolve`, `sep`); nada de `node:http`, `node:fs` nem `ws`. Espírito de
   `limits.ts`/`tlsconfig.ts`, rigidez de `resolveUpdatePath` (`apps/daemon/src/updates.ts:45`).
   Exports:
   - `WEB_CONTENT_TYPES: Record<string,string>` — allowlist `.html .js .css .map .json
     .svg .png .jpg .webp .ico .woff2 .txt .webmanifest`.
   - `resolveWebPath(root, pathname): string | null` — devolve o arquivo absoluto ou
     `null`. É `null`: caminho que não começa com `/`; segmento `..` ou qualquer segmento
     iniciado por `.`; barra invertida `\`; byte nulo `\0`; escape percent malformado;
     sequência percent-codificada que após **uma única** `decodeURIComponent` vira subida
     ou separador; extensão fora da allowlist ou ausente; e — backstop final — todo alvo
     cujo `resolve()` não fique contido em `resolve(root) + sep`. Query string é cortada
     pelo chamador (o handler já usa `req.url.split("?")[0]`).
   - `spaFallbackPath(root, pathname): string | null` — mesmas rejeições de segurança
     (compartilhando um helper interno `safeSegments`), porém exige ausência de extensão
     e devolve sempre `<root>/index.html`. Caminho inseguro → `null` (404, nunca index).
   - `contentTypeFor(filePath): string` — mapa puro, default `application/octet-stream`.
   - `cacheControlFor(filePath): string` — `public, max-age=31536000, immutable` para nome
     de asset com hash (`/-[A-Za-z0-9_-]{8,}\.[a-z0-9]+$/`, formato emitido pelo vite);
     `no-store` para qualquer outro nome, incluindo o `index.html` de entrada.
   - `webRootPlan(env, probeDir, indexReadable): { root, enabled, problems }` — preflight
     fail-closed no formato `problems` de `knobs.ts`/`tlsconfig.ts`, com I/O injetado.
     `RELAY_WEB_DIR` ausente ou em branco → `{ enabled: false, problems: [] }`. Presente →
     um problem por causa: diretório inexistente, ilegível, caminho que não é diretório,
     `index.html` ausente/ilegível dentro dele. O texto cita **apenas** `RELAY_WEB_DIR`,
     nunca o caminho absoluto (mesma regra de `tlsconfig.ts:97`).
2. **`healthz.ts`** — terceiro parâmetro opcional `web?: WebStatic` com I/O injetado
   (`{ root, isFile(abs): boolean, send(abs, req, res): void }`), mantendo os imports
   type-only. Ordem no handler:
   1. `GET /healthz` continua **primeiro** e byte a byte idêntico (200/503 atuais);
   2. `web` ausente → `res.writeHead(404).end()` exatamente como hoje, para qualquer
      método e caminho — comportamento pré-P2-188 preservado byte a byte;
   3. `web` presente e `isDraining()` → `res.writeHead(503).end()` (P2-145: o balanceador
      tira a instância de rotação também pela rota estática);
   4. método diferente de `GET`/`HEAD` → `res.writeHead(405, { allow: "GET, HEAD" }).end()`;
   5. `resolveWebPath` não-nulo e `isFile` → `send` com `content-type` de `contentTypeFor`
      e `cache-control` de `cacheControlFor`;
   6. caminho **com** extensão que não resolve ou não existe → `404` (asset faltando nunca
      responde 200 com HTML);
   7. `GET`/`HEAD` **sem** extensão → `spaFallbackPath`; não-nulo e `isFile` → `index.html`
      da raiz com `no-store`; caso contrário `404`.
3. **`index.ts`** — resolve `webRootPlan(process.env, …)` no boot, junto dos demais
   preflights (após `KNOBS`, antes de qualquer listener). `problems.length > 0` → uma
   linha por problem via `ev("warn", "invalid relay web root, refusing to start (fail-closed)", { reason })`
   e `process.exit(1)` **sem** abrir listener. `enabled` → passa `WebStatic` ao
   `healthzHandler` com `isFile` = `statSync(...).isFile()` e `send` = `createReadStream`
   (para `HEAD`, `res.end()` sem corpo). Campo aditivo `webRoot: boolean` na linha
   `relay listening` (nunca o caminho). O path de `server.on("upgrade")` não é tocado.
4. **`deploy/relay/Dockerfile`** — novo estágio `FROM node:22-slim AS web`: copia
   `package.json`, `package-lock.json`, `tsconfig.base.json`, `scripts/gen-version.mjs`,
   `apps/web/package.json`, `packages/protocol`, roda `npm ci --workspace apps/web
   --workspace packages/protocol`, copia `apps/web/{src,public,index.html,vite.config.ts,tsconfig.json}`
   e roda `npm run build --workspace apps/web` (script já existente, `vite build --base=./`).
   Runtime: `COPY --from=web /app/apps/web/dist ./apps/web/dist` e
   `ENV RELAY_WEB_DIR=/app/apps/web/dist`. Justificativa obrigatória no commit (deploy/ é
   safety-critical): a imagem passa a servir arquivos estáticos, nenhuma outra mudança.
5. **Docs** — `docs/RELAY-HOSTING.md` (linha na tabela de env vars + seção curta),
   `README.md` (bloco do relay hospedado, ~linha 438) e `README.pt-BR.md` (seção
   "Relay hospedado (Docker)", ~linha 384): a variável, a recusa de boot com uma linha por
   motivo, e que **só** arquivos estáticos da allowlist são servidos.

## Edge cases
- `RELAY_WEB_DIR` ausente/em branco: zero problems, zero rota estática, `404` de hoje.
- `/healthz?probe=1` continua probe, nunca asset (a query é cortada antes de resolver).
- `/` → fallback SPA (sem extensão) → `index.html`; `/pair` idem.
- `/assets/app.js` inexistente → `404`, nunca `index.html`.
- `/..%2f..%2fetc%2fpasswd`, `/.env`, `/a\b.js`, `/x%00.js`, `/etc/passwd` → `null` → `404`.
- Link simbólico dentro da raiz apontando para fora: barrado pela contenção do caminho
  resolvido (`resolve(root) + sep`).
- `POST /` → `405` com `allow: GET, HEAD`; durante o dreno, `503` vem antes do `405`.
- `RELAY_WEB_DIR` apontando para arquivo, ou diretório sem `index.html`: um problem cada.

## Acceptance criteria
- Blocos novos em `scripts/relay-healthz.test.ts` (já na cadeia `test:unit`) cobrindo:
  asset comum resolvido; subida `..` rejeitada; subida percent-codificada rejeitada;
  caminho absoluto rejeitado; arquivo oculto (`.env`) rejeitado; extensão fora da allowlist
  rejeitada; alvo que escapa da raiz por link simbólico rejeitado pela contenção;
  `contentTypeFor` (mapa + default `application/octet-stream`); `cacheControlFor`
  (`immutable` para nome com hash × `no-store` para `index.html`); fallback SPA só para
  `GET`/`HEAD` sem extensão; `POST` → `405`; `web` ausente → `404` atual preservado e
  `webRootPlan` com zero problems; diretório inexistente → 1 problem; `index.html` ausente
  → 1 problem.
- `/healthz` mantém os asserts existentes verdes (corpo 200 e 503 byte a byte).
- `npm run typecheck`, `npm run build` e `npm run test:unit` verdes, com output real colado
  no EVIDENCE (`relay-healthz: ALL OK` incluído).
- `npx tsx scripts/invariants.ts` verde (relay continua sem dependência de crypto).
- `git diff --stat package.json package-lock.json` vazio — nenhuma dependência nova no relay.

## Out of scope
- Crypto E2E, allowlist de handshake, proteção de replay (seq no AAD), arquivo de estado 0600.
- Qualquer decisão de admissão, cap, rate limit, roteamento de frames ou path de upgrade ws.
- Logar id de sala, caminho absoluto ou qualquer plaintext — o relay continua cego.
- Novas dependências no relay (tamanho de bundle e superfície de auditoria).
- Mudança visual: **nenhum screenshot é evidência desta task**.
