# RT-466 — Symlink escape no allowlist de download (invariante #6)

## Problem
`accessibleDownload()` (`apps/daemon/src/index.ts:893-896`) valida só a forma *string* do
caminho: `resolve(p)` + `abs.startsWith(r + "/")`. `path.resolve` nunca consulta o disco, então
um symlink dentro de qualquer raiz permitida (`~/.opencode-remote/uploads`, Desktop, Downloads,
Documents, repo) passa o gate. Ex.: `ln -s ~/.ssh/id_ed25519 ~/Downloads/x` (ou um diretório
`~/Documents/etc -> /etc`) → `POST /__ocr/download/start {path:"~/Downloads/x"}` passa, o
`statSync` (linha 1198) segue o link e `GET /__ocr/download/chunk` (`openSync`, linha 1245) lê o
alvo fora das raízes. `/__ocr/files` (1172-1191) também lista symlinks via `statSync` (segue
links), anunciando arquivos de fora. Há ainda TOCTOU: o caminho é gravado no `start` e reaberto a
cada `chunk`, então trocar o arquivo por um symlink depois do `start` escapa também.
Viola `docs/CONSTITUTION.md` item 6 ("Sem traversal — downloads restritos a uploads/Desktop/
Downloads/Documents/repo").

## Approach
1. Novo módulo puro-ish `apps/daemon/src/downloadpath.ts` (só `node:fs`/`node:path`, sem estado):
   - `resolveDownloadRoots(roots: string[]): string[]` — para cada raiz, `realpathSync` quando
     existe (macOS: `/var`→`/private/var`, home symlinkado), senão `resolve`; dedupe.
   - `containedIn(real: string, roots: string[]): boolean` — `real === r || real.startsWith(r + sep)`.
   - `accessibleDownloadPath(p: string, realRoots: string[]): string | null` — `resolve(p)`,
     depois `realpathSync(abs)` (erro → `null`); retorna o caminho REAL só se `containedIn`, e só
     se `statSync(real).isFile()` (diretórios/fifos/devices → `null`). Nunca lança.
   - `openContainedFile(real, realRoots): number | null` — `openSync(real, O_RDONLY | O_NOFOLLOW)`
     (constante de `fs.constants`; ausente no Windows → 0), depois `fstatSync(fd).isFile()` e
     re-checagem `realpathSync(real)` contida; qualquer falha fecha o fd e retorna `null`.
2. `index.ts`:
   - `DOWNLOAD_ROOTS` continua (string, usado para listar); adicionar
     `DOWNLOAD_REAL_ROOTS = resolveDownloadRoots(DOWNLOAD_ROOTS)` calculado lazy na primeira
     chamada (raízes criadas depois do boot, ex. uploads, precisam aparecer) — recalcule se a raiz
     não existia antes (cache simples por raiz, sem timer).
   - `accessibleDownload(p)` passa a delegar para `accessibleDownloadPath(p, realRoots())`.
   - `/__ocr/download/start`: usa o caminho real retornado; o `statSync(abs).size` fica, mas sobre
     o real. Registra `downloads.set(id, { path: real, ... })`. Resposta 403 idêntica
     (`"path not allowed"`) para symlink fora da raiz, inexistente continua 403/404 como hoje
     (inexistente → realpath falha → 403 é aceitável; documentar).
   - `/__ocr/download/chunk`: trocar `openSync(d.path, "r")` por `openContainedFile(d.path,
     realRoots())`; `null` → 404 `"file gone"` (fecha o TOCTOU pós-start).
   - `/__ocr/files`: usar `lstatSync` e pular entradas `isSymbolicLink()` (listagem nunca anuncia
     link; o shape `{path,name,size,mtime}` não muda).
   - Log de recusa: `log("warn", "download start refused", { reason: "outside-roots" })` — sem
     caminho no log (padrão P2-314).
3. `scripts/invariants.ts`: fortalecer o check da linha 46 para exigir também `realpathSync` e
   `O_NOFOLLOW` no fluxo de download (ex.: ler `apps/daemon/src/downloadpath.ts` e checar
   `/realpathSync/` e `/O_NOFOLLOW/`, e que index.ts importa `./downloadpath.js`). Commit deve
   justificar explicitamente a mudança em invariants.ts (constituição #3) e citar invariante #6.
4. Teste unitário `scripts/download-path.test.ts` (padrão de `scripts/handoff.test.ts`: `check()`,
   `mkdtempSync` em `tmpdir()`, sem rede), adicionado ao fim de `test:unit` em `package.json`.
   Se `scripts/portablecoverage.ts` exigir registro de cada teste do `test:unit`, registrar lá
   também (sem causa de exclusão — o teste é portável; symlink no Windows: pular os casos de
   link com `check` OK+skip se `symlinkSync` lançar EPERM).
5. Docs: uma linha em `docs/CONSTITUTION.md` item 6 ("caminhos resolvidos por realpath; symlinks
   que saem das raízes são recusados") e nota curta na seção de entrega de arquivos do
   `AGENTS.md`/README ("links simbólicos para fora das pastas permitidas não são baixáveis").

## Edge cases
- Raiz ela mesma é symlink (ex. `~/Documents` → iCloud, `/var`→`/private/var` do tmpdir): deve
  continuar funcionando — por isso as raízes são realpath'd.
- Symlink DENTRO da raiz apontando para outro arquivo dentro da mesma (ou de outra) raiz: permitido
  (o alvo real está contido).
- Symlink de diretório intermediário (`~/Documents/etc -> /etc`, pedido `~/Documents/etc/passwd`):
  recusado (realpath resolve componentes intermediários).
- Prefix confusion: raiz `/Users/x/Documents` vs alvo real `/Users/x/Documents-evil/f` → recusado
  (separador obrigatório).
- Symlink quebrado / arquivo inexistente → `null`, nunca exceção não tratada.
- Diretório, FIFO, `/dev/*` via link → recusado (`isFile`); FIFO nunca pode travar o `openSync`
  (checar `statSync` antes de abrir no start; no chunk o caminho já é real e `O_NOFOLLOW`).
- Arquivo trocado por symlink entre `start` e `chunk` → chunk 404, nunca lê o alvo.
- `O_NOFOLLOW` indefinido (Windows) → fallback 0 + re-checagem por realpath.
- Download legítimo de 1.2MB em `uploads/` (fluxo de `scripts/download.test.ts`) segue idêntico.

## Acceptance criteria
- `npx tsx scripts/download-path.test.ts` sai 0 e cobre no mínimo: arquivo regular na raiz → caminho
  real; symlink para arquivo fora → `null`; symlink de diretório intermediário para fora → `null`;
  prefixo irmão (`root-evil`) → `null`; symlink interno→interno → permitido; link quebrado → `null`;
  diretório → `null`; raiz via symlink (tmpdir realpath) → permitido; `openContainedFile` num
  caminho que virou symlink após validação → `null`.
- `grep -n "abs.startsWith(r + \"/\")" apps/daemon/src/index.ts` não retorna nada (gate string-only
  removido); `openSync(d.path, "r")` não existe mais em index.ts.
- `npx tsx scripts/invariants.ts` passa; removendo `realpathSync` de `downloadpath.ts` ele falha.
- `npm run typecheck` e `npm run test:unit` verdes.
- `/__ocr/files` não lista entradas symlink (coberto por teste da função de filtro ou por asserção
  de fonte que `lstatSync`/`isSymbolicLink` aparece no handler).
- Nenhum caminho de arquivo aparece em linhas de log novas; payloads de sucesso de
  start/chunk/files mantêm o mesmo shape.

## Out of scope
- Mudar a lista de raízes permitidas ou o protocolo de download/chunk (tamanho de chunk, caps P2-314).
- Rotas de artifacts, uploads (`/__ocr/upload/*`), handoff e o SSRF do `proxy()` (outros itens RT).
- UI do telefone/desktop (mensagens de erro já existentes continuam).
- Qualquer mudança em crypto, relay, allowlist de pareamento ou deploy/.
