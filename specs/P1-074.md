# P1-074 — Infra failures must not burn attempts or fever samples

## Problem

Every failed pipeline run is treated as task merit evidence: `runSlot` (apps/pilot/src/index.ts:283-289) calls `recordCycle(state, false, task.id)` and `tripCircuitBreaker`, which increments `state.taskAttempts[id]` via `recordTaskFailure` (apps/pilot/src/state.ts:222). When the failure is actually infra — opencode API down, spawn error, timeout with no output — a healthy task burns attempts and can land in `## Blocked` (P1-056 was blocked at 23:28 by API churn despite P2-016's preflight: once `waitForApi` exhausts its ~45s window, the run still fails through the merit path). Infra outcomes also feed the fever window (apps/pilot/src/audit.ts:47), so repeated infra noise can co-trip the queue-wide breaker.

## Approach

1. **Classifier** (`apps/pilot/src/audit.ts`, exported pure function):
   `infraFailureKind(text: string): "api-down" | "spawn" | "network" | null` — case-insensitive match of: `[preflight] opencode API unreachable` and `Cannot connect to API` → `api-down`; `spawn error:` → `spawn`; `ECONNREFUSED`/`ECONNRESET`/`ETIMEDOUT` → `network`. Anything else → `null` (merit failure).
2. **Timeout with no output** (`apps/pilot/src/pipeline.ts`, round-crash return ~line 1224): when `build.timedOut && !build.output.trim()`, return detail `[infra] builder timed out without output (round N)` so the classifier catches it; other crash details unchanged (their tails already embed `spawn error:`/`Cannot connect to API` when infra).
3. **State** (`apps/pilot/src/state.ts`): optional field `infraFails?: number` on `PilotState`; backfill to 0 in `loadState` both branches (same pattern as `merges`); daily reset via the existing date-rollover is fine (diagnostic counter, not a breaker).
4. **Wiring** (`apps/pilot/src/index.ts`, `runSlot` failure branch): on `!result.ok`, first `const infra = infraFailureKind(result.detail)`.
   - infra → do NOT call `recordCycle` (no fever sample) and do NOT call `tripCircuitBreaker` (no attempt burned, no block, no digest); `state.infraFails = (state.infraFails ?? 0) + 1`; log `pipeline infra-failure` with the kind; `state.failures` untouched.
   - infra && `(state.infraFails ?? 0) % 3 === 0` → wake the doctor: extract the existing audit-mode diagnosis block (index.ts:125-136 — `apiHealthy` + `buildDiagnosis` + `formatDiagnosis` + log + `state.auditDiagnosis`) into a local `async function runDoctorPass(state)` and reuse it in both places. No audit mode is entered.
   - non-infra → current behavior exactly (recordCycle + tripCircuitBreaker).
5. **Docs**: docs/PILOT.md circuit-breaker section (~line 377) gains a paragraph: infra-signature failures (API down, spawn error, timeout without output) increment `infraFails` and every 3rd one runs a doctor diagnostic pass; they never count toward `taskAttempts` or fever.

## Touched files

- `apps/pilot/src/audit.ts` — `infraFailureKind`, `INFRA_DOCTOR_EVERY = 3`, `recordInfraFailure(st)` (increment + wake check, pure)
- `apps/pilot/src/state.ts` — `infraFails` field + `loadState` backfill
- `apps/pilot/src/pipeline.ts` — one return site: infra marker for timed-out-empty builder round
- `apps/pilot/src/index.ts` — `runSlot` failure branch split; `runDoctorPass` helper extraction
- `scripts/unit.test.ts` — new checks (see criteria)
- `docs/PILOT.md` — breaker section paragraph

## Edge cases

- Merit-looking detail that merely *mentions* infra words in a builder log tail: acceptable false-positive direction is infra (retry is free — attempts not burned); the pinned negatives below bound the classifier.
- Timed-out run WITH substantial output (builder was mid-work, no marker): stays a merit failure — only empty-output timeouts are infra.
- Preflight-abort runs: detail is the `[preflight] …` string → infra; task keeps its preserved branch (P1-036) since `taskAttempts` is unchanged, and `attemptNo` (pipeline.ts:1063) stays stable.
- Pipeline *crash* path (catch in `runSlot`, index.ts:312-321) unchanged — it stays un-attributed fever evidence.
- `infraFails` missing (legacy state.json): backfilled to 0, never NaN.

## Acceptance criteria

- `npm run typecheck` and `npm run test:unit` pass.
- New unit checks in scripts/unit.test.ts, all passing:
  - `infraFailureKind("...[preflight] opencode API unreachable...") === "api-down"`; `("x\nspawn error: ENOENT") === "spawn"`; `("Cannot connect to API") === "api-down"`; `("ECONNREFUSED ...") === "network"`.
  - Negatives → `null`: `"gatekeeper rejected: eval battery or invariants failed"`, `"max review rounds reached — findings: ..."`, `"builder produced an empty diff"`.
  - Fever immunity: state with 12 consecutive infra outcomes (classifier path simulated via `recordInfraFailure` + skipping recordCycle) has `feverReason(st) === null` and `st.taskAttempts === {}`.
  - Merit control: one non-infra failure still calls the existing path (recordCycle sample present, `recordTaskFailure` bumps attempts).
  - Doctor wake: `recordInfraFailure` returns true exactly on the 3rd and 6th call (INFRA_DOCTOR_EVERY=3), false otherwise; `loadState` backfills `infraFails: 0` from a legacy file without the field.
- Observable runtime behavior: a cycle whose detail contains `[preflight] opencode API unreachable` logs `pipeline infra-failure kind=api-down`, leaves `taskAttempts` for the task unchanged in `~/.opencode-remote/pilot/state.json`, adds no `cycles` entry, and every 3rd occurrence posts an `audit diagnosis`-style line with `api=down` while the queue keeps running.

## Out of scope

- The pipeline crash path (un-attributed `recordCycle(false)` in the catch) and deploy failures (`state.failures` in `launchDeploy`).
- Dashboard/web rendering of `infraFails` (state field is documented, not charted).
- Retrying infra-failed runs inside the same cycle (the scheduler naturally re-picks the task next cycle).
- `scripts/invariants.ts`, `deploy/`, and the auth/crypto surface (constitution 1-3 untouched).
- Extending the P2-016 preflight window or its tuning constants.
