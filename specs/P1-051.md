# P1-051 — Olhos e mãos no app real: harness Playwright `_electron`

## Problem

O pipeline hoje só enxerga a UI pelo build **web** (`tools/browse.mjs` → `/api/browse`
do daemon) e pelo render smoke estático (`scripts/desktop-render.test.ts`, que só
confere boot + `#root` montado + console limpo). Ninguém consegue **interagir** com o
app desktop real: clicar abas, digitar, tirar shot da janela nativa ou ler o estado
exposto via IPC. Builders de task UI validam "no escuro"; o gate não exercita nenhum
fluxo de navegação. Faltam olhos (shot) e mãos (click/type) no app empacotado.

## Approach

Playwright já está no repo como dependência transitiva (`playwright-core` 1.62.1,
hoisted; `node -e "require('playwright-core')._electron"` confirma o export `_electron`).

1. **Novo CLI `tools/desktop.mjs`** (mesma DX de `tools/browse.mjs`, stdin/stdout silencioso, exit code = veredito):
   - `open [shot.png [w h]]` — lança o app uma vez e reutiliza a instância do worker.
   - `see <texto>` — assertion de texto visível no DOM (exit 0/1, msg clara).
   - `click <selector>` / `type <selector> <texto>` — interação real via `page.click/fill`.
   - `shot <out.png>` — screenshot da janela nativa (não do browser host).
   - `ipc <expr>` — roda `page.evaluate` com `window.ocrDesktop` e imprime o JSON (estado IPC).
   - `close` — encerra a instância.
2. **Lançamento determinístico** (`_electron.launch({ args: [apps/desktop/dist-electron/main.js], cwd: repoRoot })`):
   - `OCR_USER_DATA_DIR` apontando para `mkdtemp` (novo escape hatch, ver Touched files) —
     isola bounds/estado e evita disputa de `requestSingleInstanceLock` com outra instância dev.
   - `OCR_DAEMON_STATE_FILE` → arquivo temp sem `apiToken` (token null ⇒ nunca reusa o daemon de produção,
     apps/desktop/src/daemon.ts:87) e `OCR_DAEMON_ENTRY` → path inexistente (`resolveEntry` retorna null ⇒
     **nenhum sidecar spawnado**, daemon.ts:241-247). Reproduz o padrão dos testes `OCR_DAEMON_*` existentes.
   - `ELECTRON_DISABLE_SECURITY_WARNINGS=1`.
3. **Novo gate `scripts/desktop-flow.test.ts`** (`npm run test:desktop-flow`): build web+desktop
   (reuso do padrão de pré-build de desktop-render.test.ts:43-54), lança o app, executa 1 fluxo
   real: espera a navegação desktop (`button[title="Conversas"]`, App.tsx:627-640) →
   `click button[title="Artifacts"]` (App.tsx:641-655) → `see` no texto do header de Artifacts →
   `shot` → assertion IPC (`window.ocrDesktop.version` string não-vazia; `getPairingState()`
   retorna objeto `PairingState`). Alvo < 60s (timeout duro de 60s no script).
4. **Wiring no gatekeeper** (`apps/pilot/src/pipeline.ts`, bloco `renderTouched` ~linha 1137):
   além de `desktop-render`, push do step `["desktop-flow", "npx tsx scripts/desktop-flow.test.ts"]`.
5. Builders de task UI passam a citar `tools/desktop.mjs` no EVIDENCE quando a task tocar `apps/desktop`.

## Touched files

- `tools/desktop.mjs` — **novo** CLI (open/see/click/type/shot/ipc/close), espelha browse.mjs.
- `scripts/desktop-flow.test.ts` — **novo** gate: 1 fluxo de interação real, <60s.
- `apps/desktop/src/main.ts` — ~3 linhas: `if (process.env.OCR_USER_DATA_DIR) app.setPath("userData", ...)`
  antes de `initDesktopLog` (linha ~47), mesmo padrão dos hatches `OCR_DAEMON_*`.
- `apps/pilot/src/pipeline.ts` — novo step condicional `desktop-flow` no bloco `renderTouched`.
- `package.json` (raiz) — scripts `test:desktop-flow` + `devDependencies.playwright-core: "1.62.1"`
  (hoisted hoje por apps/daemon; pin explícito evita drift).
- `docs/PILOT.md` — seção de evidência UI: como builders usam `tools/desktop.mjs` + novo step do gate.
- `AGENTS.md` — parágrafo de 3 linhas sobre o harness (docs de user-visible change, constituição #5).

## Edge cases

- **Concorrência**: gate roda sob o lock cross-slot (P1-006); mesmo assim o flow test
  mata a instância no `finally` (`electronApp.close()`) e usa userData temporário — duas
  execuções sequenciais nunca colidem.
- **App demora a abrir**: timeout de 60s no script inteiro; `firstWindow()` com `waitForEvent` +
  retry de 15s; nunca pendurar o gate.
- **Renderer sem `ocrDesktop`** (preload quebrou): assertion IPC falha com mensagem explícita,
  não timeout vazio.
- **CI headless / macOS**: reusar `app.dock.hide()`/`disableHardwareAcceleration` já feitos pelo
  app? Não estão no path dev — o harness só exige janela; se DPI variar, shot sai no tamanho da
  window: `_electron` permite `electronApp.evaluate` para fixar `setSize` 1440x900 quando w/h pedidos.
- **Erro de login do macOS (tray/notificações)**: notificações são best-effort no próprio app
  (main.ts:323), não afetam o harness.
- **`playwright-core` sem browsers baixados**: `_electron` não baixa browser — só requer o binário
  Electron (devDep `apps/desktop`, já no lock).

## Acceptance criteria

1. `npm run build && npx tsx scripts/desktop-flow.test.ts` → exit 0, imprime `OK` para:
   boot do app, fluxo Conversas→Artifacts, shot gravado, assertion IPC `app:version` e
   `app:pairingState` (main.ts:120/169) — duração reportada **< 60s** no output.
2. `node tools/desktop.mjs open` → `node tools/desktop.mjs see "Artifacts"` → exit 0;
   `see "texto-inexistente-xyz"` → exit 1 com mensagem.
3. `node tools/desktop.mjs shot /tmp/x.png 1440 900` grava PNG de exatamente 1440x900
   (`sips -g pixelWidth` confere) — mesmo critério de dimension do EVIDENCE (P2-009).
4. Gatekeeper: `apps/pilot/src/pipeline.ts` contém o step `desktop-flow` disparado pela
   mesma condição `renderTouched` do `desktop-render`.
5. `npm run test:unit && npm run typecheck` seguem verdes; nenhum daemon de produção é
   spawnado pelo harness (log do app mostra `no daemon entry found`, nunca `daemon sidecar spawned`).
6. Docs atualizadas (`docs/PILOT.md`, `AGENTS.md`) citam o harness e o novo step do gate.

## Out of scope

- Empacotar/notarizar (`npm run dist`) ou testar o binário DMG — harness roda o app dev.
- Fluxos que exigem daemon real ou phone pareado (chat, push, pairing E2E).
- Trocar o browse.mjs / `/api/browse` — continuam sendo a via para a UI web.
- Multiplicar fluxos no gate (1 fluxo basta; mais fluxos = task futura).
- Alterar `scripts/invariants.ts`, `deploy/`, cripto, allowlist ou replay protection.
