# P1-075 — Governança da memória de experiência (IER)

## Problem
- `docs/EXPERIENCE.md` has 213 lesson lines vs cap 60 (`EXPERIENCE_CAP`, apps/pilot/src/experience.ts:12). `git log --all --grep="pilot(redteam)"` is EMPTY — the nightly prune never landed once.
- Pilot log shows "nightly redteam starting" (2026-09-01 03:15, 2026-09-03 09:36) with NO "experience maintained" / "experience maintenance failed" after it. Root cause in `maybeNightly` (apps/pilot/src/index.ts:536-635): `st.redteamLast = today` is stamped BEFORE the 30-min redteam agent runs; a process exit/reload during that window loses the maintenance for the whole day (stamp prevents retry). The maintenance block also sits after the agent instead of running independently.
- Dedupe is exact-string (`lessonKey`): the 4 semantic copies of the same lesson (re-worded across attempts, e.g. checkout -B re-landings) all survive `appendLessons`/`dedupeAndPrune`.
- `scribePrompt(t, diff, findings)` (apps/pilot/src/pipeline.ts:586) injects reviewer findings/gate-fail tails, so the scribe distills harness/process lessons instead of product-code lessons.
- No data measures whether lesson injection helps (merges/rounds/cost with vs without).

## Approach
1. Scribe sees only the diff (a): drop the `findings` param from `scribePrompt` and the `REVIEWER FINDINGS` block; caller `runScribe(ws, t, diff, trackSession)` (pipeline.ts:659-1723). Update the two `scribePrompt` cache tests (scripts/unit.test.ts:1712-1713) to the new signature, asserting prompt-stability invariants.
2. Semantic dedupe (b): in experience.ts add `jaccard(a: Set<string>, b: Set<string>): number` and `const JACCARD_DUPE = 0.6` over the existing `tokenize`. A candidate is a duplicate when `lessonKey` matches OR (both token sets ≥ 5 tokens AND jaccard ≥ 0.6). Apply in `appendLessons` (vs file and vs batch) and in `dedupeAndPrune` (newest wording wins — keep iterating newest→oldest).
3. Score-based prune + archive (c): extend `dedupeAndPrune(md, cap)` to return `{ md, removed, archived: string[] }`. After dedupe, while above cap: lessons matching `isHarnessLesson` (harness vocabulary regex: pilot/pipeline/builder/reviewer/scribe/gate/backlog/planner/slot/refresh…) whose `(fonte: ID)` is in the Done set are REMOVED from the file and returned as `archived`. If still above cap, drop oldest-first within class — harness first, product lessons last (product has priority; within a class, oldest first). Add `doneTaskIds(md): Set<string>` to apps/pilot/src/backlog.ts (parse `(ID)` from `## Done` lines, regex anchored on the marker). Nightly caller (index.ts) appends each archived lesson to `~/.opencode-remote/pilot/lessons.jsonl` via `appendFailureLesson` as `{kind:"failure", task: fonteId, attempts: 0, step: "archived", findings: lessonText, tail: ""}` (file lives outside every worktree, P1-037). Guard `failureLessonsBlock` (apps/pilot/src/failureLessons.ts): archived entries fill at most 3 of the 10 slots — real blocked-task failures keep ≥ 7.
4. Nightly scheduling fix (d) — pilot cycle, no new daemon: in `maybeNightly`, (i) run the deterministic experience maintenance (dedupe+prune+archive+commit+push with the existing `mayPush` guard) BEFORE the redteam agent, guarded by its own `state.expMaintLast` (ISO date) so agent failure never blocks it; (ii) stamp `st.redteamLast = today` only AFTER the agent completes; (iii) wrap the `maybeNightly` call site (index.ts:262) in try/catch (log "nightly pass crashed"); (iv) add log lines "nightly redteam finished/failed" so silence is diagnosable. Keep the `--once` skip.
5. Instrumentation (e): pure `recordLessonImpact(state, { lessons, rounds, ok, tokens })` in apps/pilot/src/metrics.ts folding into `state.lessonImpact = { with: {merges, roundsTotal, tokensTotal}, without: {...} }` (+ validation in state.ts load path). In pipeline.ts, where lessons are picked for the builder (line ~1422), pass `lessons.length` through the result; at "pipeline result" time also log a structured `lesson impact` line (task, lessonsInjected, rounds, ok, tokens from the existing cost reconciliation).

## Edge cases
- Short lessons (< 5 tokens each): Jaccard is noisy → only exact `lessonKey` dedupe applies.
- Jaccard threshold pinned as exported `JACCARD_DUPE = 0.6` (battery pins the number).
- Archive only when above cap and fonte is done; product lessons are never archived; lessons from undone/unknown fontes stay.
- lessons.jsonl corrupt lines already tolerated by `parseFailureLessons`; archived entries must not crowd out real failures (max 3 of 10).
- Workspace on a task branch / push failure: maintenance is fs-first (file rewritten), commit+push best-effort with the existing `mayPush("docs/EXPERIENCE.md")` guard; never crashes the loop.
- `--once` (eval battery) still never starts the nightly pass.
- Concurrent slots' scribe appends during the nightly rewrite: commitLessons already refetches+retries; nightly commits from slot-1 workspace only while slots are idle.

## Acceptance criteria
- `npm run typecheck`, `npm run build`, `npm run test:unit` all pass (gate re-runs them).
- New unit tests in scripts/unit.test.ts: (1) paraphrased lesson with same tokens (jaccard ≥ 0.6) is dropped by `appendLessons` and by `dedupeAndPrune`; a genuinely different lesson is kept; (2) prune above cap archives a harness lesson whose fonte is in `doneTaskIds`, keeps a product lesson even if older, and `archived` equals the removed harness lines; (3) `failureLessonsBlock` shows ≤ 3 archived entries when ≥ 7 real failures exist; (4) `scribePrompt` output contains no "REVIEWER FINDINGS" and no findings text; (5) `recordLessonImpact` folds merges/rounds/tokens into the right cohort.
- On the real file (scratch copy): running `dedupeAndPrune` via a tsx one-liner yields ≤ 60 lessons and `archived` ≥ 1 from the current 213.
- Next nightly cycle: log shows "experience maintained" (or "nightly pass crashed" on failure) after "nightly redteam starting"; a `pilot(redteam): experience maintenance` commit can land on origin/main; if the redteam agent fails/times out, maintenance still runs (unit: agent stub throwing before stamp → expMaintLast set, no redteamLast).

## Out of scope

- launchd plist / install-pilot.sh changes (scheduling stays inside the pilot cycle); deploy/, scripts/invariants.ts, relay crypto/auth surface.
- Backfilling or rewriting historical EXPERIENCE.md content beyond dedupe/prune/archive; tier-B for scribe/redteam.
