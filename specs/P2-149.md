# P2-149 — Daemon distingue opencode não instalado de opencode parado

## Problem
`classifyUpstream` (`apps/daemon/src/upstream.ts:85-90`) devolve, para **qualquer** conexão
recusada, o mesmo hint: *"o servidor do agente não está aceitando conexões — verifique se o
opencode está rodando nesta máquina"*. Quem acabou de instalar o app desktop e nunca instalou
o servidor do agente lê exatamente a frase de quem só esqueceu de subir o servidor. O card
calmo da P2-138 repassa esse hint como texto (`README.md:578-588`, `README.pt-BR.md:136-146`),
então o usuário leigo do estágio 3 fica sem ação concreta. Falta ao daemon o único dado que
separa os dois casos: existe um binário `opencode` executável nesta máquina?

## Approach
1. **Novo módulo puro `apps/daemon/src/opencodebin.ts`** — sem `node:fs`, `node:child_process`,
   `node:path`, `node:os` nem `fetch` (mesmo contrato de `relayurl.ts`/`upstream.ts`; `index.ts`
   roda `main()` no import e o unit test avalia em Node puro — lição P2-129). Junção de caminhos
   por concatenação de string (`/` em posix, `\` em win32), nunca `path.join`, para o resultado
   ser determinístico rodando em darwin.
   - `export type OpencodeBinarySource = "path" | "known";`
   - `export interface OpencodeCandidate { path: string; source: OpencodeBinarySource }`
   - `export interface OpencodeBinaryPick { path: string | null; source: OpencodeBinarySource | null }`
   - `export function opencodeCandidates(env: Record<string, string | undefined>, platform: string,
     home: string): OpencodeCandidate[]` — primeiro as entradas do PATH (`env.PATH ?? env.Path`,
     split por `:` em posix e `;` em win32), depois as localizações conhecidas:
     - posix: `${home}/.opencode/bin/opencode`, `/opt/homebrew/bin/opencode`,
       `/usr/local/bin/opencode`;
     - win32: `${env.LOCALAPPDATA}\opencode\bin\opencode.exe` e
       `${env.ProgramFiles ?? "C:\\Program Files"}\opencode\opencode.exe`.
     Só caminhos **absolutos** entram (posix: começa com `/`; win32: `X:\…` ou UNC `\\…`);
     entradas vazias, relativas ou com o env ausente são descartadas. Deduplicação preservando a
     primeira ocorrência (PATH ganha de `known`).
   - `export function pickOpencodeBinary(candidates: OpencodeCandidate[],
     isExecutable: (p: string) => boolean): OpencodeBinaryPick` — devolve o primeiro candidato em
     que `isExecutable` retorna true (`{path, source}`); `{path: null, source: null}` quando
     nenhum serve. `isExecutable` que lança conta como "não serve" (try/catch por candidato).
     Toda a seleção fica pura; o I/O é injetado (lição P2-065).
2. **Resolução cacheada em `apps/daemon/src/index.ts`** (perto do bloco P2-135, linhas 1269-1332):
   - estado de módulo `let binaryPick: OpencodeBinaryPick = { path: null, source: null };` e
     `let binaryCheckedAt = 0;`
   - `function refreshOpencodeBinary(force = false): void` — no-op se
     `!force && Date.now() - binaryCheckedAt < 60_000`; senão monta
     `opencodeCandidates(process.env, process.platform, homedir())` e chama `pickOpencodeBinary`
     com `isExecutable = (p) => { try { accessSync(p, constants.X_OK); return true } catch { return false } }`.
     `accessSync`/`constants` vêm de `node:fs` **só aqui**, nunca no módulo puro.
   - chamada uma vez no boot (`force: true`, antes do healthcheck de boot da linha 2651) e, no
     máximo uma vez por minuto, quando o veredito de uma sonda é `unreachable` — ou seja, no
     catch de `probeUpstream` (1311) e no catch do boot (2670), antes de `classifyUpstream`.
   - `probeUpstream` e o healthcheck de boot passam `binaryFound: binaryPick.path !== null` ao
     `classifyUpstream`.
3. **`UpstreamProbe` ganha `binaryFound?: boolean`** (aditivo, opcional) e o ramo `econnrefused`
   de `classifyUpstream` se divide em dois, **mesmo `state: "unreachable"`**:
   - `binaryFound === false` → reason curto tipo `"conexão recusada e o opencode não foi
     encontrado nesta máquina"`, hint mandando **instalar o opencode primeiro**;
   - `binaryFound === true` **ou ausente** → reason `"conexão recusada"` e o hint de hoje,
     **byte a byte**, para os 6 checks P2-135 existentes continuarem passando sem edição.
   Nenhum outro ramo (timeout, 401/403, 2xx, unhealthy, fallback) muda.
4. **`GET /api/health`** (`apps/daemon/src/index.ts:2147-2170`): o objeto `opencode` passa a ser
   `{ ...opencodeDetail, binaryFound: binaryPick.path !== null, binarySource: binaryPick.source }`.
   Campos existentes (`state`, `reason`, `hint`, `checkedAt`) e `opencodeHealthy` intactos.
   **Nenhum caminho absoluto** entra no payload, em `reason`, em `hint` ou em log — só o booleano
   e a origem (`"path"` | `"known"` | `null`).
5. **Docs** (constituição 5): o bloco "Honest agent-server health (P2-135)" do `README.md:578` e o
   bloco "Aviso do upstream (P2-138)" do `README.pt-BR.md:136` documentam `binaryFound` e
   `binarySource` junto do contrato do endpoint, dizendo explicitamente que nenhum caminho é
   exposto. Atualizar também a tabela de `docs/api.md:61-67` com as duas linhas novas.

## Edge cases
- `PATH` ausente/vazio: só as localizações conhecidas entram; lista nunca é `undefined`.
- Entrada de PATH relativa (`.`, `bin`, `~/x`) ou vazia (`::` no meio): descartada.
- Entrada de PATH com barra final (`/usr/local/bin/`): normalizada, sem `//` no resultado.
- win32 sem `LOCALAPPDATA` e sem `ProgramFiles`: cai no default `C:\Program Files`; nada de
  `undefined\opencode.exe` na lista.
- Mesmo diretório em PATH e em `known` (ex.: `/opt/homebrew/bin`): aparece uma vez só, com
  `source: "path"` (primeira ocorrência vence).
- `isExecutable` que lança (EACCES, EPERM): candidato descartado, sem propagar erro — a sonda
  nunca quebra por causa da resolução do binário.
- Binário instalado depois do boot: o refresh de 60s no ramo `unreachable` corrige o hint sem
  reiniciar o daemon; com o upstream saudável não há re-resolução (nada de `accessSync` por tick).
- `binaryFound` ausente na probe (chamador antigo/teste): comportamento idêntico ao de hoje.
- Timeout com binário ausente continua `timeout` — a divisão só existe no ramo refused.

## Acceptance criteria
- `npm run typecheck` verde, output real no EVIDENCE.
- `npm run build` verde, output real no EVIDENCE.
- `npm run test:unit` verde, output real no EVIDENCE, com os checks novos (prefixo `P2-149:`) em
  `scripts/unit.test.ts`, no mínimo:
  1. entrada de PATH com executável → `{source: "path"}` e `path` igual à entrada de PATH;
  2. só uma localização conhecida executável (PATH sem match) → `{source: "known"}`;
  3. nada executável → `{path: null, source: null}`;
  4. `opencodeCandidates({...}, "win32", ...)` → **todos** os candidatos terminam em `.exe` e
     nenhum contém `/`;
  5. dedupe preserva a ordem: diretório repetido em PATH e em `known` aparece 1× e o
     `candidates.map(c => c.path)` é estritamente igual à lista esperada;
  6. `classifyUpstream({error: ECONNREFUSED, binaryFound: true})` e
     `{..., binaryFound: false}` → mesmo `state === "unreachable"` e `hint` **diferentes**,
     ambos não-vazios;
  7. os 6 casos P2-135 já existentes (200 ok, healthy:false, body malformado, 401, 403, refused
     sem `binaryFound`) seguem passando **sem edição no bloco antigo**.
- `grep -nE "node:fs|node:child_process|node:path|node:os|fetch\(" apps/daemon/src/opencodebin.ts`
  não retorna nada.
- `grep -nE "/usr/local|/opt/homebrew|Program Files|homedir" apps/daemon/src/upstream.ts` não
  retorna nada (nenhum caminho vaza para reason/hint).
- `git diff --stat` não inclui `package.json`, `scripts/invariants.ts`, `deploy/`, nem qualquer
  arquivo de crypto/handshake/allowlist/replay.

## Out of scope
- Qualquer mudança no renderer/desktop (card calmo da P2-138, seção de ajuda, botão de instalar).
- Executar, spawnar ou versionar o binário `opencode`; instalar nada automaticamente.
- Expor o caminho absoluto do binário em API, log, push ou diagnóstico.
- Novos estados de `UpstreamState`, mudança nos ramos timeout/401/2xx, ou remoção/renome de campos.
- Alterar `package.json`, a cadeia `test:unit`, `scripts/invariants.ts` ou `deploy/`.
- Crypto E2E, allowlist de handshake, replay (seq em AAD) e o arquivo de estado 0600.
