# P2-197 — sonda de alcance do endereço do app (QR que leva a lugar nenhum)

## Problem
`apps/desktop/src/main.ts:1074` monta `webApp` a partir de `currentWebAppResolution()` e cunha
o QR assim que `webAppRes.problems.length === 0`; a P2-193 pôs a credencial no fragmento
**desse mesmo endereço** (`const pairLink = {` logo abaixo). Nada verifica que o endereço
RESPONDE: relay hospedado fora do ar, DNS que nunca existiu, certificado vencido ou um host
que não é o nosso passam por `webAppUrlProblems` (validação só sintática, `webappurl.ts`) e
produzem um QR perfeito que leva o telefone a uma página em branco. Quem segura o telefone
não tem como saber que o culpado é o relay e não a câmera — o estágio 3 morre no passo um.

## Approach
1. **Novo módulo puro `apps/desktop/src/webreach.ts`** — sem `electron`, sem `node:fs`, sem
   `fetch` (higiene de `webappurl.ts` / `sidecarexit.ts`; lição P2-149/P2-194):
   - `export const WEB_REACH_TIMEOUT_MS = 2_000;` (teto documentado, = `PROBE_TIMEOUT_MS`
     de `main.ts:825`).
   - `export type ReachState = "ok" | "unreachable" | "timeout" | "tls-error" | "dns-error" | "http-error" | "not-our-app";`
   - `export interface ReachProbe { status: number | null; elapsedMs: number; errorName: string; appMarker: boolean }`
   - `export function probeVerdict(p: ReachProbe): { state: ReachState; message: string }` — puro
     e determinístico. Ordem: `errorName` não-vazio **e** `status === null` decide primeiro
     (abort/timeout → `timeout`; nome de resolução de nome → `dns-error`; nome de certificado →
     `tls-error`; qualquer outro erro de rede → `unreachable`); com `status` numérico:
     `status === 200 && appMarker` → `ok`; `status >= 400` → `http-error`; qualquer outro caso
     (inclusive `200` sem marcador) → `not-our-app`.
     Casamento por nome, **case-insensitive**, sobre tabelas locais: abort =
     `AbortError|TimeoutError|ABORT_ERR`; dns = `ENOTFOUND|EAI_AGAIN|EAI_NODATA|getaddrinfo`;
     tls = prefixo `CERT_`/`ERR_TLS`/`UNABLE_TO_VERIFY_LEAF_SIGNATURE|DEPTH_ZERO_SELF_SIGNED_CERT|SELF_SIGNED_CERT_IN_CHAIN|EPROTO`.
   - `export function hasAppMarker(bodyPrefix: string): boolean` — `true` só se o corpo contém
     `id="root"` ou `OpenCode Remote` (marcadores reais de `apps/web/index.html:14` e `:10`).
   - `message`: frase curta em **pt-BR**, estática, acionável, **sem `/`, sem `\`, sem esquema
     de URL, sem token e sem caminho de arquivo** (mesmo padrão de `sidecarexit.ts`).
2. **`main.ts`** — helper local `async function probeWebAppReach(url: string)` acima de
   `refreshPairingState`: `new URL(url).origin` (falha de parse → `unreachable` via
   `probeVerdict`), `await fetch(origin, { signal: AbortSignal.timeout(PROBE_TIMEOUT_MS), redirect: "follow" })`,
   corpo lido só nos 200 e truncado (`(await res.text()).slice(0, 32_768)`) para `hasAppMarker`.
   `catch` extrai o nome curto: `(err?.cause?.code ?? err?.name ?? "")`. **Nunca lança** — todo
   caminho retorna um verdict, para não cair no `catch` que zera `pairingState`. Chamada UMA vez
   por tick, dentro do mesmo guarda do QR (`!quietLocal && (!paired || remotePairingRequested)`)
   **e** só quando `webAppRes.problems.length === 0 && webAppRes.url !== ""`; caso contrário
   `reach` fica `undefined`. Sonda a **ORIGEM de `webAppRes.url`**, JAMAIS `pairLinkRes.url`
   (carrega a credencial no fragmento) e **sem cabeçalho `authorization`**. Log no máximo
   `log("[desktop] app reach: " + reach.state)` — nunca a URL, nunca o corpo.
3. **Payload aditivo**: `reach: { state, message }` no `setPairingState({...})` **depois de
   `webApp`** (nenhum campo removido/renomeado). Espelhar em `preload.ts` (`PairingState`,
   ~L65) e `App.tsx` (`PairingState`, ~L99) como opcional; ausência = estado desconhecido.
   A assertion antiga `/setPairingState\(\{[\s\S]*?webApp,\s*\}\);/` (`unit.test.ts:12616`)
   fixa `webApp` como último campo — relaxá-la para `/setPairingState\(\{[\s\S]*?webApp,[\s\S]*?\}\);/`
   é a **única** edição permitida nas assertions da P2-189/P2-193.
4. **Ação "testar de novo"**: `ipcMain.handle("app:recheckWebApp", () => { void refreshPairingState(); })`
   ao lado de `app:reconnectDaemon` (`main.ts:542`) + `recheckWebApp` opcional no bridge do
   `preload.ts`. O renderer chama com optional-chaining (no browser não existe).
5. **`PairingOverlay.tsx`**: linha de status calma `.pair-reach` **abaixo do QR** (uma só,
   fora do `if/else` dos passos, para valer nos dois layouts), no vocabulário do card da
   P2-112: `state === "ok"` → texto mudo de uma linha; qualquer outro estado → mesma linha em
   tom de aviso com `reach.message` + botão texto `t("pairReachRetry")`; `reach` ausente →
   nada. **NUNCA esconde nem esmaece o QR**, com o motivo escrito em comentário no código:
   *o Mac não alcançar o relay não prova que o telefone não alcança (outra rede, outro DNS)*.
   Estilos novos em `apps/web/src/index.css` junto de `.pair-step*` (~L1944-2005), usando os
   tokens atuais — sem gradiente, sem glassmorphism, sem emoji, sem novo raio de canto.
   Chaves novas em **en e pt** (`pairReachOk`, `pairReachRetry`, `pairReachTesting`) — o
   `scripts/i18n-emoji.test.ts` exige paridade de contagem e zero emoji.
6. **Docs**: README.md (§ pareamento, ~L450-465), README.pt-BR.md (~L469-485) e
   docs/troubleshooting.md (nova linha na tabela, ~L37) registram: a sonda roda **na máquina que
   hospeda o daemon**, uma vez por tick, com teto de 2 s; a credencial (endereço de `pairLink`)
   **nunca** é sondada e nenhum cabeçalho de credencial é enviado; um aviso **nunca** bloqueia o
   pareamento nem esconde o QR.

## Edge cases
- `status` ausente + erro de rede genérico (`ECONNREFUSED`, `fetch failed`) → `unreachable`.
- `AbortError`/`TimeoutError` com `status` nulo → `timeout` (mesmo com `elapsedMs` baixo).
- `200` com corpo sem marcador (portal cativo, nginx default) → `not-our-app`.
- `301/302` já seguidos pelo `fetch`; um `204`/`3xx` final continua `not-our-app`.
- `404`/`503` → `http-error` (nunca `unreachable`).
- Endereço loopback `http://127.0.0.1:<porta morta>` é válido em `webAppUrlProblems` → sonda
  roda e devolve `unreachable` (é exatamente o caso de evidência).
- `webAppRes.problems` não-vazio, modo local quieto ou telefone já pareado → sonda **não** roda.
- Falha da sonda nunca derruba o tick: `pairingState` segue completo, QR intacto.
- Renderer antigo / campo ausente → estado desconhecido, nenhuma linha renderizada.

## Acceptance criteria
- Bloco novo `--- P2-197 ... ---` em `scripts/unit.test.ts` (já na cadeia `test:unit`) com
  `check(...)` para cada estado: `{status:200, appMarker:true}` → `ok`; `{status:200,
  appMarker:false}` → `not-our-app`; `errorName:"CERT_HAS_EXPIRED"` → `tls-error`;
  `errorName:"ENOTFOUND"` → `dns-error`; `errorName:"AbortError"` → `timeout`; `{status:503}` →
  `http-error`; `errorName:"ECONNREFUSED"` → `unreachable`; e um laço provando que **toda**
  mensagem dos 7 estados é não-vazia e não contém `/`, `\`, `http:` nem `https:`.

  sobre um corpo estranho (`<h1>nginx</h1>` → false).

  `webApp` (`new URL(webAppRes.url).origin` / `probeWebAppReach(webAppRes.url)`) e o arquivo
