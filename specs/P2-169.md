# P2-169 — Voz e leitura de QR morrem no app assinado do macOS

## Problem
`apps/desktop/build/entitlements.mac.plist` declara só as 4 chaves da P2-136
(allow-jit, allow-unsigned-executable-memory, disable-library-validation,
allow-dyld-environment-variables) e o bloco `mac:` de
`apps/desktop/electron-builder.yml` (linhas ~57-84) não tem `extendInfo`. O
Info.plist do bundle empacotado nasce, portanto, sem
`NSMicrophoneUsageDescription` e sem `NSCameraUsageDescription`, enquanto
`apps/web/src/lib/recorder.ts:11` pede microfone (`getUserMedia({audio})`) e
`apps/web/src/components/QrScanner.tsx:81` pede câmera. Com
`hardenedRuntime: true` (P2-136), o macOS nega/mata o processo que toca esses
dispositivos sem a string de uso: a gravação de voz e a tela de scan da P2-117
quebram **só** na build assinada/notarizada do estágio 5, nunca em dev — o pior
modo de falha possível. Não há hoje nenhuma checagem que pegue isso.

## Approach
1. **Entitlements (aditivo)**: acrescentar `com.apple.security.device.audio-input`
   e `com.apple.security.device.camera` (`<true/>`) ao dict existente, sem
   remover nenhuma chave. Estender o comentário-cabeçalho no mesmo estilo,
   uma linha por chave explicando o porquê (mic = voz/transcrição do recorder;
   camera = QR de pareamento do QrScanner).
2. **electron-builder.yml**: adicionar `extendInfo:` dentro do bloco `mac:`
   (junto de `hardenedRuntime`/`entitlements`) com as duas descrições em pt-BR,
   curtas, sem caminho, sem token, sem nome de empresa inventado. Sugestão:
   - `NSMicrophoneUsageDescription: O OpenCode Remote usa o microfone para gravar e transcrever mensagens de voz no chat.`
   - `NSCameraUsageDescription: O OpenCode Remote usa a câmera para ler o QR code de pareamento.`
   Comentar o bloco citando P2-169 no estilo do arquivo.
3. **Novo módulo puro `scripts/mac-privacy.ts`** (mesma forma de
   `scripts/release-preflight.ts`: lógica pura + CLI guardado por
   `import.meta.url === invoked`):
   - constantes exportadas `MIC_KEY`, `CAMERA_KEY`, `AUDIO_ENTITLEMENT`,
     `CAMERA_ENTITLEMENT` e os labels `PLIST_LABEL` /`BUILDER_LABEL`
     (`apps/desktop/build/entitlements.mac.plist`, `apps/desktop/electron-builder.yml`).
   - `export function privacyProblems(entitlementsXml: string, builderYml: string): string[]`
     — texto puro, sem dependência de YAML/plist parser (o repo não tem uma),
     retorna **todos** os problemas, `[]` quando o par está completo.
     Um problema por: descrição de uso ausente no yml, descrição presente mas
     em branco (valor vazio, só espaços ou só aspas), entitlement de dispositivo
     ausente no plist. Chave no yml só conta em linha não comentada
     (`/^[ \t]*NSMicrophoneUsageDescription:[ \t]*(.*)$/m`, valor com aspas
     externas removidas e `trim()`); entitlement só conta como presente quando
     `<key>…</key>` é seguido de `<true/>`.
   - CLI: lê os dois arquivos reais via `new URL("../apps/desktop/…", import.meta.url)`,
     imprime `mac-privacy: FAIL` + uma linha `  - <problema>` por item +
     `mac-privacy: N problem(s) found` e sai com código 1; sucesso imprime
     `mac-privacy: OK` e as 4 chaves conferidas.
4. **`apps/desktop/scripts/dist-smoke.mjs`**: nova função exportada
   `macPrivacyProblems(bundleDir)` — retorna `[]` quando o bundle **não** é um
   `.app` de macOS (win-unpacked/linux-unpacked passam sem checagem, o job
   `desktop-win` da P2-164 continua verde); quando é, lê
   `Contents/Info.plist` e exige as duas chaves com `<string>` não vazio.
   Info.plist ausente/ilegível é problema; conteúdo que não começa com `<?xml`
   (plist binário) degrada para nenhuma checagem com uma linha impressa,
   nunca para FAIL. **Não** dobrar essa checagem dentro de `listProblems` —
   as fixtures mac de `scripts/dist-smoke.test.ts:24` não escrevem Info.plist e
   quebrariam. Chamar em `main()` logo após o bloco `listProblems`, no mesmo
   formato de erro; no sucesso imprimir `  Info.plist usage descriptions present`.
5. **Docs**: `README.md` (seção de packaging, ~linha 560), `README.pt-BR.md`
   (~linha 436) e uma linha na tabela de `docs/troubleshooting.md` explicando
   que o macOS pede permissão de microfone e de câmera na primeira vez e que,
   se o usuário negar por engano, o caminho é
   Ajustes do Sistema → Privacidade e Segurança → Microfone/Câmera → ligar
   **OpenCode Remote** e reabrir o app.

Não tocar em `package.json`, `scripts/invariants.ts`, `deploy/`, allowlist,
seq/AAD nem qualquer superfície de crypto.

## Edge cases
- Chave presente no yml com valor vazio (`NSCameraUsageDescription:`) ou só
  aspas (`""`) → problema "present but empty", distinto de "missing".
- Chave só dentro de um comentário `#` no yml → conta como ausente.
- `<key>com.apple.security.device.camera</key>` seguido de `<false/>` → ausente.
- `dist-smoke.mjs` em `win-unpacked`/`linux-unpacked` → zero checagens novas.
- Info.plist binário (não-XML) → degrada, não falha.
- `privacyProblems` reporta os 5 problemas de uma vez, nunca só o primeiro.
- `scripts/` não entra em `npm run typecheck` (workspaces-only); o módulo é
  exercitado por `tsx` via `scripts/unit.test.ts` e por `npm run lint`.

## Acceptance criteria
1. `npx tsx scripts/mac-privacy.ts` no repo sai com código 0 e imprime
   `mac-privacy: OK`.
2. Blocos novos em `scripts/unit.test.ts` (já na cadeia `test:unit`, sem tocar
   `package.json`), com fixtures sintéticas cobrindo, cada um em seu `check`:
   par completo → `problems.length === 0`; `NSMicrophoneUsageDescription`
   ausente → 1 problema citando a chave; `NSCameraUsageDescription` ausente →
   1 problema citando a chave; `com.apple.security.device.audio-input` ausente
   → 1 problema citando o entitlement; `com.apple.security.device.camera`
   ausente → 1 problema citando o entitlement; descrição presente porém em
   branco → 1 problema citando a chave e a palavra `empty`.
3. Assertion de repo real no mesmo bloco: lê
   `apps/desktop/build/entitlements.mac.plist` e
   `apps/desktop/electron-builder.yml` com `readFileSync` e confirma as 4
   chaves novas (2 entitlements + 2 descrições) e que
   `privacyProblems(plist, builderYml).length === 0`.
4. As 4 chaves da P2-136 continuam no plist — o check
   `P2-136: entitlements plist carries the Electron + node-sidecar keys`
   (scripts/unit.test.ts:8081) segue OK.
5. `npm run test:unit` verde (última linha `UNIT TESTS PASSED` no
   `scripts/unit.test.ts` e cadeia inteira sem falha), incluindo
   `scripts/dist-smoke.test.ts` intacto.
6. `npm run typecheck`, `npm run build` e `npm run lint` verdes, com output
   real colado no EVIDENCE.
7. README.md, README.pt-BR.md e docs/troubleshooting.md mencionam
   microfone **e** câmera e o caminho de recuperação em Ajustes do Sistema.
