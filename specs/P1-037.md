# P1-037 — Refill do strategist não pode ser apagado pelo sync

## Problem

`runStrategist` (`apps/pilot/src/index.ts:454-537`) drafts task lines and lands them with
`appendCommitAndPush` (`apps/pilot/src/backlog.ts:241-265`, call at `index.ts:521-526` — the
backlog's "index.ts:439-442" drifted). That helper already retries the push 3x (3s sleeps),
but each retry starts with `git reset -q --hard origin/main`, and when ALL attempts fail it
returns `"failed"` leaving an unpushed refill commit on local `main`. The next idle cycle calls
`syncWorkspace` (`index.ts:185` → `index.ts:658-663`), which does
`git reset -q --hard origin/main` + `git clean -qfd` — silently destroying the drafted tasks.
Nothing is persisted anywhere else, so the refill is lost forever and the queue stays dry
(the structural cause of the dry-queue incident). `runResearcher` (`researcher.ts:86-91`)
shares the same hole.

## Approach

Keep `appendCommitAndPush` (retry semantics) as is. Make the refill durable:

1. New module `apps/pilot/src/refill.ts` (mirror the `failureLessons.ts` pattern: pure
   helpers + fs wrappers with injectable path):
   - `defaultPendingRefillFile()` → `~/.opencode-remote/pilot/pending-refill.json`
     (outside every worktree, so no `reset --hard`/`clean` can touch it).
   - `savePendingRefill(file, lines, message)` → atomic write (writeFileSync to `<file>.tmp`
     + renameSync) of `{ lines, message, ts }`; returns boolean.
   - `readPendingRefill(file)` → parsed `{lines, message}` or `null` (tolerates corrupt JSON).
   - `clearPendingRefill(file)` → best-effort unlink.
   - `relandPendingRefill(repoDir, file, io: AuxPushIo)`:
     a. `io.exec("git fetch -q origin")` + `git show origin/main:BACKLOG.md`; drop pending
        lines whose ids already exist there (parseBacklog).
     b. If nothing remains → clear file, return `"empty"` (avoid infinite retry of landed ids).
     c. Else call `appendCommitAndPush(repoDir, remaining, message, io)`:
        `"pushed"` → clear file, return `"pushed"`; `"refused"` → clear file + warn (guard
        rejection means worktree contamination; never loop on it); `"failed"` → KEEP the
        file, return `"failed"` (transient network issue; retry next cycle).
2. Wire in `runStrategist` (`index.ts:527-533`): when result is `"failed"`, call
   `savePendingRefill` with the exact `lines` + commit message; log + emit
   `phase refill ok:false detail:"pending refill saved (N lines)"`.
3. Wire in the aux-idle block (`index.ts:183-197`): after `syncWorkspace(aux.workspace)`,
   still inside `if (running.size === 0)` and BEFORE the `queue.length < 2` strategist
   trigger: if a pending refill exists, `await relandPendingRefill(...)`, log/emit the
   result, then `continue` (re-read the queue fresh, same as index.ts:190).

## Touched files

- `apps/pilot/src/refill.ts` (NEW — pending store + reland logic, testable in isolation)
- `apps/pilot/src/index.ts` — `runStrategist` failure branch + aux-idle re-land (wiring only; `index.ts` runs `main()` on import, so no logic beyond wiring here)
- `scripts/unit.test.ts` — new checks in/near the `appendCommitAndPush` block (unit.test.ts:525-611)
- `docs/PILOT.md` — one paragraph: aux refills that fail to push are persisted in `pending-refill.json` and re-landed on the next idle cycle

## Edge cases

- Push fails all 3 attempts → pending file saved; the later `syncWorkspace` reset destroys
  only the worktree copy; the store survives and re-lands next idle cycle.
- Ids already landed meanwhile (e.g. redteam path) → duplicate pre-filter drops them;
  all-duplicates → `"empty"`, file cleared, zero pushes.
- Corrupt/partial pending file → `readPendingRefill` returns `null`, treated as "nothing
  pending"; the next `savePendingRefill` overwrites it.
- `"refused"` (mayPush guard) → clear + warn, never retried (contaminated worktree; the
  strategist re-drafts naturally since the queue stays low).
- New strategist run while a pending file exists → `savePendingRefill` overwrites (last
  refill wins; aux agents are serialized by `running.size === 0`).
- Reland must use the same `appendCommitAndPush` → same `mayPush` guard: only a diff of
  exactly `BACKLOG.md` is ever pushed (constitution-safe).

## Acceptance criteria

1. `npm run test:unit` green, including new checks (fake IO pattern of unit.test.ts:555-569):
   - save/read round-trip preserves lines + message exactly.
   - fake IO with push always failing: `appendCommitAndPush` returns `"failed"`,
     `savePendingRefill` stores the drafted lines; a simulated syncWorkspace
     (`reset --hard` + `clean` against a real bare-remote clone, like the smoke at
     unit.test.ts:593-611) does NOT remove them from the store.
   - reland with push restored: returns `"pushed"`, file cleared, lines present on
     `origin/main:BACKLOG.md`.
   - reland with ids already on origin/main: returns `"empty"`, file cleared, 0 pushes.
   - reland with push still failing: returns `"failed"`, file KEPT (verifiable by re-read).
   - corrupt JSON file: `readPendingRefill` → `null`, no throw.
2. `npm run typecheck` and `npm run lint` green.
3. Observable: a strategist landing failure logs `refill saved as pending` with line count;
   the next idle cycle logs the reland outcome (`pending refill landed N lines` / `still
   failing` / `already landed`).

## Out of scope

- Wiring `savePendingRefill` into `runResearcher` / redteam experience flow (the helper is
  shared; propose a follow-up task).
- Changing `syncWorkspace` semantics, the `mayPush` allowlist, or `appendCommitAndPush`
  retry/backoff numbers.
- Any UI surface (dashboard chips) for pending refills.
