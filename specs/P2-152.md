# P2-152 — Fechar a janela deixa de parecer que o app sumiu: dica única de close-to-tray

## Problem
Desde a P2-021 o handler de `close` em `apps/desktop/src/main.ts:946-952` faz
`event.preventDefault()` + `win.hide()` no ramo não-quitting: a janela some, o
daemon sidecar segue rodando e o tray continua vivo. Nada disso é dito ao
usuário. O leigo do estágio 3 clica no botão vermelho, vê o app desaparecer,
conclui que fechou e nunca descobre que o ícone da bandeja reabre a janela
(`README.md:721-726` documenta o comportamento, mas ninguém lê README depois de
clicar em fechar). A P2-148 (`.welcome`) só cobre o primeiro boot e a P2-150
(`badgePlan`) só cobre não lidas — nenhuma das duas fala no momento do close.

## Approach
1. **`apps/desktop/src/closehint.ts` (novo, sem imports de electron)** — mesmo
   padrão puro de `tray.ts` / `notify.ts` / `badge.ts`, testável por
   `scripts/unit.test.ts`:
   - `export type CloseHintKind = "notify" | "none"` e
     `export interface CloseHintPlan { kind: CloseHintKind; title: string; body: string }`.
   - `export const CLOSE_HINT_SENTINEL = "1"` (mesma convenção do
     `WELCOME_DONE` da P2-148) e
     `export const CLOSE_HINT_LOG = "[desktop] close-to-tray hint shown"`
     (marcador único que o beat de e2e conta em `desktop.log`).
   - Copy pt-BR curta, sem emoji (P2-107), sem caminho/token/segredo:
     `CLOSE_HINT_TITLE = "OpenCode Remote continua rodando"`;
     `CLOSE_HINT_BODY_MENUBAR = "A janela fechou, mas o app segue na barra de menus. Clique no ícone para abrir de novo."`;
     `CLOSE_HINT_BODY_TRAY = "A janela fechou, mas o app segue na bandeja do sistema. Clique no ícone para abrir de novo."`.
   - `closeHintPlan(platform: string, flag: string | null | undefined): CloseHintPlan`
     — `flag === CLOSE_HINT_SENTINEL` ⇒ `{ kind: "none", title: "", body: "" }`
     (silêncio total, como o badge zerado); qualquer outro valor (`null`,
     `undefined`, `""`, `"0"`, `" 1 "`, JSON quebrado) é tratado como ausente e
     devolve `notify`. Body: `darwin` ⇒ menubar; `win32`/`linux` e **qualquer
     outra plataforma** ⇒ tray (texto genérico de bandeja).
   - `hintFlagPath(userDataDir: string): string` ⇒
     `join(userDataDir, "close-hint.flag")` (mesmo formato de
     `windowStateFile()` em `apps/desktop/src/window-state.ts:27-29`).
   - `readHintFlag(read: () => string): string | null` — sink de leitura
     injetado; `try/catch` devolvendo `null` quando o sink lança (arquivo
     ausente, disco ruim, permissão). Fail-open da P2-148: no pior caso a dica
     aparece de novo, nunca some para sempre.
   - `writeHintFlag(write: (value: string) => void): boolean` — chama
     `write(CLOSE_HINT_SENTINEL)`, devolve `false` se o sink lançar.
2. **`apps/desktop/src/main.ts`** — importar de `./closehint` e chamar um novo
   `maybeShowCloseHint()` **apenas** dentro do `if (!quitting)` do
   `win.on("close", …)`, **depois** do `win.hide()` (linha ~950). O caminho de
   quit real (`quitting === true`, limpeza do sidecar em `will-quit`) não é
   tocado. `maybeShowCloseHint()` é integralmente best-effort — mesma disciplina
   de `observeDaemonHealth()` (`main.ts:701-717`): lê a flag via
   `readHintFlag(() => readFileSync(file, "utf8"))`, chama `closeHintPlan`,
   retorna cedo em `kind === "none"`; se `!Notification.isSupported()` degrada
   para **uma** linha `log("[desktop] close hint skipped: notifications unsupported")`
   e retorna; senão dispara `new Notification({ title, body, silent: true }).show()`,
   emite exatamente uma `log(CLOSE_HINT_LOG)` e grava a flag em
   `hintFlagPath(app.getPath("userData"))`, com
   `if (!writeHintFlag(…)) log("[desktop] close hint flag write failed")`.
   A flag só é gravada quando a notificação de fato saiu (não queimar a única
   chance numa plataforma sem suporte). Todo o corpo dentro de `try/catch` com
   `logError` — nenhuma falha pode bloquear o `hide()`.
3. **`README.md`** (bloco "Close-to-tray keeps the daemon alive",
   linhas 721-726) e **`README.pt-BR.md`** (bloco de notificação nativa,
   linhas ~492-500, antes de `## Roadmap`) ganham uma linha dizendo que a
   primeira vez que a janela é fechada o app avisa, uma única vez, que continua
   na barra de menus/bandeja e como reabrir.

- `scripts/unit.test.ts` (novo bloco `closeHintPlan`, ao lado do bloco

## Edge cases
- Flag ausente/vazia/corrompida ⇒ `notify` (fail-open, P2-148).
- Sink de leitura ou de escrita lançando ⇒ decisão intacta, log-only.
- `Notification.isSupported() === false` ⇒ nenhuma exceção, nenhuma flag
  gravada, uma linha de log.
- Quit real (tray Quit, `Cmd+Q`, `before-quit`) ⇒ nenhuma dica.
- Segundo close na mesma sessão (flag já no disco) ⇒ `none`, zero logs de hint.
- Plataforma desconhecida (`sunos`) ⇒ `notify` com o texto genérico de bandeja.
- Copy sem emoji (regra P2-107) e sem caminho/token/segredo.
- Beat hermético: a janela nunca é mostrada (`HERMETIC_E2E`), então a prova de
  close-to-tray é a janela **continuar existindo** após o `close`, não
  `isVisible`.

## Acceptance criteria
1. `npx tsc -p tsconfig.base.json --noEmit` equivalente via `npm run typecheck`
   e `npm run build` verdes, com output real colado no EVIDENCE.
2. `npm run test:unit` verde, com um bloco novo em `scripts/unit.test.ts`
   cobrindo, no mínimo: `closeHintPlan("darwin", null).kind === "notify"` e
   body === `CLOSE_HINT_BODY_MENUBAR`; `win32` e `linux` ⇒ `notify` com
   `CLOSE_HINT_BODY_TRAY`; `closeHintPlan(p, CLOSE_HINT_SENTINEL).kind === "none"`
   com `title`/`body` vazios; `"0"`, `""`, `" 1 "`, `undefined` e um JSON
   quebrado tratados como ausentes (⇒ `notify`); `sunos` ⇒ `notify` com o texto
   de bandeja; `readHintFlag(() => { throw new Error("boom") }) === null` e o
   plano derivado ainda `notify`; `writeHintFlag(() => { throw … }) === false`;
   `hintFlagPath("/tmp/x")` termina em `close-hint.flag`; título e bodies sem
   emoji (mesmo regex de `scripts/i18n-emoji.test.ts:20`) e sem `/` nem `\`.
3. `npm run test:desktop-flow` verde dentro do budget, com um beat novo
   (`phase("P2-152: …")`) em `scripts/desktop-flow.test.ts` que, num
   `OCR_USER_DATA_DIR` limpo e sessão própria: abre o app, fecha a janela pelo
   renderer (`ipc window.close()`), prova que a janela sobreviveu
   (`wins` devolve 1 janela), prova **exatamente uma** ocorrência de
   `CLOSE_HINT_LOG` em `<userData>/logs/desktop.log`, e prova
   `existsSync(<userData>/close-hint.flag)` com conteúdo `"1"`.
4. O mesmo beat encerra a instância (`tools/desktop.mjs close` + loop de
   `pgrep -f tools/desktop\.mjs`, respeitando a instância única da P2-069),
   reabre com o **mesmo** `OCR_USER_DATA_DIR`, fecha a janela de novo e prova
   que a contagem de `CLOSE_HINT_LOG` no `desktop.log` continua exatamente 1.
5. `git diff --stat` não mostra `package.json`, `scripts/invariants.ts` nem
   `deploy/`.
6. README e README.pt-BR contêm a linha sobre a dica única de close-to-tray.

## Out of scope
- Mudar o comportamento de close-to-tray em si (a janela continua escondendo).
- Preferência/toggle em Settings para desligar a dica.
- Qualquer mudança no renderer (`apps/web/`), i18n ou IPC novo.
- Notificações em outros momentos (daemon down/back da P3-013, badge da P2-150).
- Balão nativo do tray (`tray.displayBalloon`) ou segundo canal de aviso.
