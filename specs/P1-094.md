# P1-094 — Infra/merit classifier must not read findings text

## Problem

`infraFailureKind(text)` (apps/pilot/src/audit.ts:83-89) classifies a pipeline failure as
infra by case-insensitive substring search (`"econnrefused"`, `"econnreset"`, `"etimedout"`,
…) over the whole `result.detail` string. The only caller is `runSlot`
(apps/pilot/src/index.ts:337). But `detail` is free text that often embeds reviewer
**findings**: at apps/pilot/src/pipeline.ts:1464 a review failure returns
`max review rounds reached — findings: ${findings.slice(0, 400)}`. A merit finding that
merely cites ECONNREFUSED (e.g. "flaky test got ECONNREFUSED") then classifies as `network`
infra → `runSlot` skips `tripCircuitBreaker` (index.ts:344), burns no attempt, adds no
fever sample → **infinite retry** of a defective task. Same exposure: pipeline.ts:1232
(builder stdout tail) and pipeline.ts:1038-1044 (evidence re-run tail).

## Approach

Classify infra **only** from structured evidence — an explicit kind set by the producer of
the failure (runner stage + exit/timeout flags) — never by scanning embedded text
(findings, builder output, command stderr). Concretely: `RunResult` and `PipelineResult`
gain an optional `infra` field, set at the exact sites that *are* infra (preflight API
unreachable, spawn error, timeout without output); `runSlot` reads only that field. The
text-scan function `infraFailureKind` and its needle table are deleted (no caller remains).

## Edge cases

- Builder stdout tail (pipeline.ts:1232) containing "econnreset"/"etimedout" from a failed
  test is now **merit** — correct per spec: only the runner's own stage flags count.
- Genuine api-down/spawn still spared: runner sets `infra` at the producer, so the
  `builder did not finish (round N): [preflight] …` path keeps the free retry.
- The literal `[infra]` marker in the timeout detail (pipeline.ts:1230) stays for
  log greppability, but classification no longer depends on it.
- `runTierB` timeouts (`timedOut: true`) are NOT classified infra today; keep it that way.
- Legacy `state.json` `infraFails` backfill test (unit.test.ts:3846-3854) must keep passing.

## Acceptance criteria

1. `npm run typecheck` and `npm run build` (repo root, workspaces) exit 0.
2. `npm run test:unit` exits 0 and includes the new checks:
   - **The task criterion**: `resultInfraKind({ ok: false, detail: "max review rounds reached — findings: fix flaky test (got ECONNREFUSED at setup)" , infra: undefined }) === null` — a finding citing ECONNREFUSED is merit.
   - `resultInfraKind({ ok: false, infra: "api-down" }) === "api-down"` (same for
     `"spawn"`, `"timeout"`); `resultInfraKind({ ok: true, detail: "anything-econnrefused" }) === null`.
3. Fever-immunity loop (unit.test.ts:3823-3829 semantics preserved): 12 outcomes with
   `infra: "api-down"` produce `infraFails === 12`, no cycle samples, no attempts.
4. `rg -n "infraFailureKind" apps/pilot/src scripts` returns no hits.
5. Behavior invariant observable in `runSlot`: only `result.infra` takes the
   `recordInfraFailure` branch; any other `ok:false` result reaches
   `tripCircuitBreaker` and increments `state.taskAttempts[task.id]`.

## Out of scope

- The crash catch path (index.ts:369-375) — already merit-only, unchanged.
- Retrying genuinely-crashed pipelines (e.g. mid-run fetch exceptions) as infra.
- Any change to `scripts/invariants.ts`, `deploy/`, crypto, allowlist or state-file perms.
- Budgets (`maxReviewRounds`, `maxAttemptsPerTask`) and the size-L checkpoint logic.
