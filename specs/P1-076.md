# P1-076 — main protegida: meta-commits via branch pilot/meta

## Problem

At least 8 code paths push directly to `origin/main`, so any hostile deviation hides inside
a trusted bookkeeping push:

| Site | Flow |
|---|---|
| `apps/pilot/src/pipeline.ts:2077` | local merge fallback when `gh pr` fails |
| `apps/pilot/src/pipeline.ts:2101` | mark-done commit after merge |
| `apps/pilot/src/pipeline.ts:1584` | empty-diff self-heal mark-done |
| `apps/pilot/src/pipeline.ts:655` (`commitLessons`) | scribe |
| `apps/pilot/src/index.ts:651` | redteam finding |
| `apps/pilot/src/index.ts:744` (`blockAndPush`) | circuit breaker |
| `apps/pilot/src/backlog.ts:277` (`appendCommitAndPush`) | strategist refill / researcher / pending refill relanding |
| `apps/pilot/src/gate-corpus.ts:147` | corpus growth |
| `apps/pilot/src/experience.ts:339` | experience maintenance |
| `apps/pilot/src/explorer.ts:128` (`commitAndPushFindings`) | explorer findings |

Fix: these "meta" commits land via a long-lived `pilot/meta` branch + PR with auto-merge;
the local merge fallback is removed; the operator enables GitHub branch protection after
this task merges.

## Approach

1. New module `apps/pilot/src/metapush.ts` exporting `landMetaCommit(ws, io, { files, message, guardFile }, attempts=3)`:
   - Loop: `git fetch -q origin` → `git checkout -q -B pilot/meta origin/main` → apply the
     caller's deterministic edit → `git add <files> && git commit`.
   - P1-057 guard unchanged in spirit: re-read `git diff --name-only origin/main...HEAD`
     every attempt; reuse `mayPush(names, guardFile)`; a refused diff never pushes.
   - `git push -q --force origin HEAD:pilot/meta` (force is required: `-B` rewinds the
     branch to main each landing, so the PR head is always exactly main + this commit).
   - PR (idempotent, reuse across runs): `gh pr view pilot/meta --json url` to find an open
     PR, else `gh pr create --head pilot/meta --base main --title "pilot: meta commits"`.
   - Merge: `gh pr merge --squash --auto` first (works once branch protection exists); if it
     errors (no protection configured yet), fall back to `gh pr merge --squash`.
     NEVER `--delete-branch` — `pilot/meta` is long-lived.
   - Return `"pushed" | "refused" | "failed"` mirroring `AuxPushResult`; best-effort
     `git checkout -q main` at the end so the worktree isn't left on `pilot/meta`.
   - `io` injectable (exec/sleep) like `auxPushIo` (backlog.ts:242) so the battery can fake git/gh.
2. Migrate every site in the table to `landMetaCommit`; keep each site's retry/persist
   semantics (P1-037 pending refill, scribe best-effort logging, corpus "no-op when deduped").
3. Remove the local merge fallback in `pipeline.ts` (lines 2065–2079): if `gh pr create`/
   `merge` fails, return `false` — the branch stays on origin and the next cycle retries.
   Keep the `gh pr merge --squash --delete-branch --auto || ...` for TASK PRs (line 2059) —
   only the fallback and the main-push sites change.
4. Docs: `docs/PILOT.md` (merge diagram + corpus section) and `docs/CONSTITUTION.md` get the
   new rule: meta commits land via `pilot/meta` PR; direct pushes to main no longer exist.
   Include an operator runbook block: after this task merges, enable GitHub branch protection
   on `main` ("Require a pull request before merging" + squash merges; required checks per
   existing CI). No code change needed for that step.

## Edge cases

- Concurrent slots landing meta commits: the second `-B` reset can drop the first's commit
  before it merges; existing 3-attempt loops + callers' dedupe/persist (P1-037) absorb it.
- `gh` unauthenticated/absent: PR steps fail → `"failed"`; commit stays on `origin/pilot/meta`;
  NO fallback to `git push origin main` anywhere.
- Open PR exists from a previous landing: reuse it; force-push updates the head and auto-merge re-arms.
- Auto-merge queued (protection on, check pending): `"pushed"`/ok is returned; landing completes async.
- Guard diff base stays `origin/main` (branch = main + 1 commit), so `mayPush` semantics are unchanged.
- P2-058 verified-merge logic only concerns task PRs; meta bookkeeping commits must NOT be
  recorded as verified merges.
- `blockAndPush` currently chains commit+push in one shell line — split before migrating.
- Refname hygiene (P1-030): `pilot/meta` is a constant, never task-derived.

## Acceptance criteria

- `rg -n "push -q origin main" apps/pilot/src` → 0 matches; `rg -n "git merge -q --no-ff" apps/pilot/src/pipeline.ts` → 0 matches.
- `npm run build`, `npm run typecheck`, `npm run test:unit` all green.
- Unit battery pins: (a) guard refusal ⇒ zero `origin HEAD:pilot/meta` pushes; (b) real-git
  smoke lands the commit on `origin/pilot/meta` with gh faked via injectable io; (c) battery
  asserts no site pushes `origin main` (grep-style check over `apps/pilot/src`).
- Post-merge behavior (operational): 24h of pipeline logs show zero direct pushes to main;
  deploys still fire from PR squash-merges (verified-merge SHAs) with typecheck/build green.
- `docs/CONSTITUTION.md` and `docs/PILOT.md` document the new flow + operator steps.
