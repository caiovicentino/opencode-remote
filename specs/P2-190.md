# P2-190 — Janela de pareamento limitada no bootstrap do allowlist

## Problem

`apps/daemon/src/index.ts:1906-1914` (ramo `if (!client && allowlist.length === 0)`) persiste no allowlist,
sem limite de tempo e sem confirmação, o **primeiro** cliente que completa o handshake enquanto o allowlist
está vazio. Hoje isso é quase inofensivo porque o relay é loopback (`RELAY_URL` default
`ws://127.0.0.1:8787`, `index.ts:106`), mas o id de sala viaja num QR (`index.ts:3000-3015`) que fica numa
tela, aparece em foto, compartilhamento de tela e print anexado a suporte. Assim que a sala for para um
relay hospedado (`docs/RELAY-HOSTING.md`), um daemon que passou dias sem parear confia em quem chegar
primeiro — para sempre. Não existe hoje nenhuma noção de "janela de pareamento": a confiança concedida no
bootstrap é ilimitada no tempo.

## Approach

1. **Novo módulo `apps/daemon/src/pairwindow.ts`** — 100% puro, sem `node:fs`, `node:http`, `ws` ou
   `fetch` (mesmo contrato de `relayurl.ts` / `bodylimit.ts`: `index.ts` roda `main()` no import, então o
   teste unitário nunca pode subir um daemon). Exporta:
   ```ts
   export const DEFAULT_PAIR_WINDOW_MS = 15 * 60_000;      // 15 min, documentado
   export const PAIR_WINDOW_CEILING_MS = 24 * 60 * 60_000; // teto documentado
   export interface PairWindow { windowMs: number; problems: string[] }
   export function pairWindow(env: Record<string, string | undefined>): PairWindow;
   export type BootstrapDecision = "allow" | "reject-expired" | "reject-not-allowlisted";
   export function bootstrapDecision(
     allowlistSize: number, openedAt: number, now: number,
     windowMs: number = DEFAULT_PAIR_WINDOW_MS,
   ): BootstrapDecision;
   ```
2. **`pairWindow(env)` lê `OCR_PAIR_WINDOW_MS` fail-closed**, copiando literalmente a estrutura de
   `bodyLimit()` em `apps/daemon/src/bodylimit.ts:35-73` (mesmo formato `problems: string[]`, mensagens em
   inglês terminadas em `refusing to start the daemon (fail-closed)`, valor bruto em `JSON.stringify`):
   ausente ou em branco (`trim() === ""`) → default **sem nenhum problem** (único caso); não numérico
   (`!Number.isFinite`), `<= 0`, não inteiro (`!Number.isInteger`) e `> PAIR_WINDOW_CEILING_MS` → um
   problem cada, `windowMs` volta ao default (irrelevante, o boot morre).
3. **`bootstrapDecision`** — pura, sem `Date.now()` dentro:
   - `allowlistSize !== 0` → `"reject-not-allowlisted"` (dentro **e** fora da janela; o tempo nem é olhado).
   - `allowlistSize === 0` e `now - openedAt < 0` → `"reject-expired"`: instante de abertura no futuro
     (relógio adiantado / clock jump) **nunca** amplia a janela. Recuperação documentada: reabrir a tela
     de pareamento rearma com um `Date.now()` fresco.
   - `allowlistSize === 0` e `0 <= now - openedAt < windowMs` → `"allow"`.
   - caso contrário (`now - openedAt >= windowMs`, comparação estrita: igual ao teto já é fechado) →
     `"reject-expired"`.
4. **`index.ts` — estado da janela**: `const pairWindowCfg = pairWindow(process.env);` junto de
   `bodyLimitResolution`/`chunkLimits` (`index.ts:114-121`); em `main()` (`index.ts:2892-2906`), no mesmo
   bloco fail-closed dos outros dois: `if (pairWindowCfg.problems.length > 0) { for (…) log("error", p);
   process.exit(1); return; }`. Declarar `let pairWindowOpenedAt = 0;` ao lado de `pairingUri`
   (`index.ts:241`) — `0` = epoch = fechado, fail-closed antes do boot — e definir
   `pairWindowOpenedAt = Date.now()` em `main()`, antes de `connectRelay()`.
5. **Rearme na leitura da tela de pareamento**: dentro do ramo `url.pathname === "/__ocr/pairing-uri"`
   (`index.ts:2366-2368`), já **depois** do `authorized(req)` (`index.ts:2361-2364`), fazer
   `if (pairingUri !== null) pairWindowOpenedAt = Date.now();` antes de responder. É exatamente o período em
   que o app desktop está com o QR na tela. **Sem log e sem audit no rearme** (a rota é polida pelo overlay;
   uma linha por leitura viraria flood). Quando o QR está retido (`relayDisabled`, `pairingUri === null`)
   não há rearme.
6. **`index.ts` — ramo do bootstrap** (`index.ts:1906-1914`): trocar `if (!client && allowlist.length === 0)`
   por uma decisão explícita
   `const decision = client ? "allow" : bootstrapDecision(allowlist.length, pairWindowOpenedAt, Date.now(), pairWindowCfg.windowMs);`
   e persistir o cliente `first` **apenas** quando `decision === "allow"` e `!client` (bloco atual byte a
   byte: `saveAllowlist`, `audit("client.paired", { …, bootstrap: true })`, `log("info", …)`). Quando
   `decision === "reject-expired"`, emitir antes do caminho de recusa já existente
   `audit("client.bootstrap-expired", { pub: accepted.clientPub.slice(0, 16) })` e **uma** linha
   `log("warn", "bootstrap pairing window closed: reopen the pairing screen in the desktop app or restart the daemon", { pub: accepted.clientPub.slice(0, 16) })`,
   e deixar cair no `if (!client)` existente (`rejectPayload(sessionKey, "not-allowed")` + `ws.close()` em
   500 ms) sem alterar uma linha dele. Nunca imprimir chave inteira, sala ou token.
7. **Intocado (verificar no diff)**: `serverAccept`, `acceptPayload`, `rejectPayload`, `seqAad`/AAD de
   replay, formato do arquivo de allowlist (`PairedClient`, `index.ts:137-186`), o caminho de dispositivo já
   pareado (`client` encontrado → `sessions.set(...)`), e o arquivo de estado 0600.
8. **`/api/health`** (`index.ts:2401-2440`): campo **aditivo**
   `pairingWindowOpen: bootstrapDecision(0, pairWindowOpenedAt, Date.now(), pairWindowCfg.windowMs) === "allow"`
   (boolean; `0` = "a janela por tempo está aberta", independente do allowlist). Nenhum campo existente é
   removido ou renomeado.
9. **Docs**: `README.md` (parágrafo de limites por env, ~L517, + seção de segurança), `README.pt-BR.md`
   (equivalente) e `docs/security.md` item **6. Allowlist** (L22-24): a janela existe, default 15 min,
   `OCR_PAIR_WINDOW_MS` (ms, inteiro positivo, teto 24 h, inválido = daemon não sobe), o rearme a cada
   leitura autenticada da tela de pareamento, e o que fazer quando fechou (reabrir a tela de pareamento no
   app desktop ou reiniciar o daemon).
10. **Commit**: declarar `constitution-change` com justificativa explícita — a mudança apenas **ESTREITA**
    a confiança concedida no bootstrap e nunca a amplia; crypto E2E, proteção de replay e o state 0600
    permanecem intocados.

## Edge cases

- `OCR_PAIR_WINDOW_MS` ausente **ou** `"   "` → default, `problems === []`, daemon sobe normalmente.
- `"abc"`, `"-1"`, `"0"`, `"1.5"`, `"86400001"` → exatamente 1 problem cada, boot sai com código 1 e
  **nenhum listener** aberto (contrato P2-180/P2-181).
- `openedAt` no futuro (`now - openedAt < 0`) → `"reject-expired"`, nunca `"allow"`.
- `now - openedAt === windowMs` (limite exato) → `"reject-expired"`.
- Allowlist não vazio → `"reject-not-allowlisted"` mesmo com a janela recém-rearmada.
- `pairingUri === null` (relay inválido, QR retido) → a rota não rearma a janela.
- `/__ocr/pairing-uri` sem Bearer → 401 antes de qualquer rearme (nenhum rearme não autenticado).
- Dispositivo já no allowlist reconectando dias depois → caminho inalterado, janela irrelevante.
- Daemon recém-bootado com allowlist vazio → janela aberta, pareamento imediato continua funcionando
  (é o cenário do `scripts/localws.test.ts`, que sobe com `HOME` temporário).

## Acceptance criteria

- `npx tsc --noEmit` limpo via `npm run typecheck` — verde.
- `npm run build` — verde.
- `npm run test:unit` — verde, com blocos novos prefixados `P2-190:` em `scripts/unit.test.ts` usando o
  helper `check(name, ok)` de `scripts/unit.test.ts:497` (**2 argumentos**, a assinatura não muda), cobrindo:
  1. allowlist vazio dentro da janela → `"allow"`;
  2. allowlist vazio fora da janela (`now = openedAt + windowMs` e `+ windowMs + 1`) → `"reject-expired"`;
  3. allowlist com 1 entrada → `"reject-not-allowlisted"` dentro **e** fora da janela;
  4. rearme: `bootstrapDecision(0, openedAtAntigo, now)` = `"reject-expired"` e, com `openedAt = now`
     (rearme), = `"allow"`;
  5. `openedAt` no futuro (`now - 60_000`… i.e. `openedAt = now + 60_000`) → `"reject-expired"`;
  6. `pairWindow({})` e `pairWindow({ OCR_PAIR_WINDOW_MS: "  " })` → `windowMs === DEFAULT_PAIR_WINDOW_MS`
     e `problems.length === 0`; cada valor inválido da lista de Edge cases → `problems.length === 1`;
  7. assertion de fonte real: ler `apps/daemon/src/index.ts` com `readFileSync` e checar que o trecho a
     partir de `const allowlist = readAllowlist();` (até ~800 chars) contém `bootstrapDecision(` — o ramo de
     allowlist vazio passa obrigatoriamente pela função.
- `npm run test:e2e` — verde; o EVIDENCE cola o output real de `scripts/localws.test.ts` mostrando
  `local hello→confirm handshake: OK`, provando que o pareamento logo após o boot continua funcionando.
- `curl -H "Authorization: Bearer $(node cli.mjs token)" http://127.0.0.1:8792/api/health` devolve
  `pairingWindowOpen` booleano e mantém `healthy`, `version`, `machine`, `opencodeHealthy`, `opencode`,
  `relayConnected`, `relayRetry`, `relay`.
- `grep -n "OCR_PAIR_WINDOW_MS" README.md README.pt-BR.md docs/security.md` retorna ocorrência nos três.
- Mensagem do commit contém `constitution-change` com a justificativa de estreitamento de confiança.

## Out of scope

- UI: nenhuma mudança visual, nenhum screenshot é evidência desta task.
- `package.json` (nenhum script novo), `scripts/invariants.ts`, `deploy/`.
- Confirmação interativa de pareamento, códigos de pareamento de uso único, rotação de sala.
