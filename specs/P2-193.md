# P2-193 — QR único de pareamento (credencial no fragmento)

## Problem
`apps/desktop/src/main.ts:1023` monta hoje DOIS QR no mesmo card: o endereço do app
(`webApp.qrDataUrl`, P2-189) e o URI `opencode-remote://pair?...` (`qrDataUrl`).
`PairingOverlay.tsx` mostra os dois como "Passo 1"/"Passo 2", o que obriga a pessoa a
escanear o primeiro com a câmera do sistema, achar o leitor de QR (`QrScanner.tsx`) dentro
do app e escanear o segundo QR na mesma tela do Mac. Quem instala o DMG não completa isso.
A credencial já está no URI; basta movê-la para o **fragmento** da URL do app — nenhum
navegador envia fragmento ao servidor, então o relay hospedado continua cego.

## Approach
1. **Novo módulo puro `apps/desktop/src/pairlink.ts`** (sem `electron`, sem `node:*`, sem
   `fetch` — mesma higiene de `webappurl.ts`/`relaysetting.ts`):
   - `export const PAIR_LINK_HASH_ROUTE = "#/pair?"` e
     `export const PAIR_LINK_MAX_LEN = 2048` (teto documentado da URL final).
   - `export function buildPairLink(app: { url: string; origin: string; problems: string[] }, rawUri: unknown): { url: string; problems: string[] }`.
   - Query movida **byte a byte**: `const q = rawUri.slice(rawUri.indexOf("?") + 1)` —
     NUNCA `URLSearchParams`/`URL.searchParams` (reencodam `+` e `%`). Resultado:
     `` `${app.url}${PAIR_LINK_HASH_ROUTE}${q}` ``.
   - `problems` (formato do P2-189: strings em inglês, log-safe, nunca ecoam a credencial):
     `app.origin.toLowerCase()` em `"unavailable"`/`"stored-invalid"`; qualquer
     `app.problems` não-vazio (propagado); `app.url === ""`; URI que não começa por
     `opencode-remote://pair` **comparado em caixa baixa** (lição P2-178) ou com path extra;
     URI sem `v=2` (comparação sobre a query crua, `v` decodificado como em
     `parsePairingUri`); URI que já traz `#`; `query.length > DEEP_LINK_QUERY_MAX` (4096,
     reusar a constante de `deeplink.ts`); URL final `> PAIR_LINK_MAX_LEN`; `app.url`
     contendo `#`. Com `problems` não-vazio, `url` volta `""` (fail-closed).
2. **`main.ts`** (bloco `refreshPairingState`, ~L1080): depois de `webApp`, calcular
   `const pairLinkRes = uri ? buildPairLink(webAppRes, uri) : { url: "", problems: [...] }`
   e montar campo **aditivo** `pairLink: { url, qrDataUrl, problems }` no `setPairingState`,
   com `qrDataUrl` gerado por `QRCode.toDataURL(pairLinkRes.url, { margin: 1, width: 480 })`
   **somente** quando `pairLinkRes.problems.length === 0 && pairLinkRes.url !== ""`.
   Nenhum campo existente (`uri`, `qrDataUrl`, `webApp`, …) é removido ou renomeado.
   Espelhar o tipo em `apps/desktop/src/preload.ts` (`PairingState`).
3. **`apps/web/src/App.tsx`**: no mesmo `applyHash` (~L391), ANTES do ramo `#/send`,
   tratar `h.startsWith("#/pair")`: extrair a query crua com `h.slice(h.indexOf("?") + 1)`,
   remontar `opencode-remote://pair?<query>` e chamar o **mesmo** `parsePairingUri` do
   caminho de colar (`lib/client.ts:183`) dentro de `try/catch` (ele lança em versão não
   suportada). Sucesso → `history.replaceState(null, "", location.pathname + location.search)`
   e `void connect(pairing, true)`. Fragmento inválido → mesmo `replaceState`, `setError(t("invalidCode"))`,
   `setPhase("error")` (cai na tela de colar de hoje, em português no locale pt) — nunca tela
   branca. Zero linha nova de crypto.
4. **`PairingOverlay.tsx`**: quando `pairLink?.qrDataUrl` existir, renderizar UM passo único
   (`.pair-step.pair-step-single`, QR 240px) com título/frase "a câmera do celular basta" e
   o endereço + botão copiar já existentes; sem `pairLink` utilizável, cair no par de passos
   rotulados de hoje. Estilos em `apps/web/src/index.css` seguindo os tokens atuais
   (`tokens.css`) — sem gradiente, sem emoji, sem canto arredondado novo. O hatch de colar
   manual (`PairingView`) fica intacto.
5. **Docs**: README.md (§ Desktop app / pareamento), README.pt-BR.md e docs/security.md
   (§ Properties ou § Threat notes) registram: credencial viaja no fragmento; navegador
   nenhum envia fragmento ao servidor, logo o relay hospedado segue cego; o app apaga o
   fragmento com `history.replaceState` assim que consome; a janela limitada da P2-190
   continua sendo o que restringe a validade.

## Edge cases
- URI com `+` ou `%2F` na chave `k`: preservado byte a byte (nada de `URLSearchParams`).
- `OPENCODE-REMOTE://PAIR?...` → mesmo esquema (comparação lowercase), sem problem.
- `app.url` com barra final (`https://x/`) → resultado sem `//` duplo antes do `#`.
- Relay loopback (default) → `webApp.origin === "unavailable"` → problem → dois QR de hoje.
- URI já com `#` → problem (a query do fragmento nunca é remontada por cima de outro).
- `#/pair` sem `?` ou com query lixo → tela de colar com `invalidCode` em pt, não branca.
- `#/pair` chegando com sessão já pareada: `connect` só é disparado no ramo novo; o
  `replaceState` roda sempre para o fragmento sumir do histórico.
- `i18n-emoji.test.ts`: chaves novas em ambos os dicionários, sem emoji.
