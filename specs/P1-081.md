# P1-081 — E2E hermético em portas dinâmicas + limpa zumbis pre-flight

## Problem

The P1-077 gate failed `INTEGRATION handshake` with main green in parallel: the integration
e2e binds the relay at FIXED port 4378 (`scripts/integration.ts:24`) and a zombie relay/daemon
from a previous gate run can hold that port, making the new relay crash on `EADDRINUSE`
(`apps/relay/src/index.ts:23` reads `RELAY_PORT` once) and the handshake then times out
(`scripts/integration.ts:201-204`) with zero diagnostic about who owns the port.
`scripts/chunk.test.ts:15-16` has the same disease (fixed 4561/4562). Three more defects compound it:

1. Gate runs steal the operator's screen: the hermetic Electron shell still calls
   `win.show()` on `ready-to-show` (`apps/desktop/src/main.ts:739`) and `showMainWindow()`
   (`main.ts:158` second-instance, `main.ts:430` activate).
2. No pre-flight: orphans (electron/daemon/relay from a killed previous run) linger and race the next run.
3. (Re-raise after block, round-3 finding) the orphan-killer kill decision is ASYMMETRIC:
   if relay/desktop markers match argv substring alone, the killer can murder the operator's
   REAL dev app/relay, which shares argv shapes. Every marker needs a second env factor.

## Approach

1. **Dynamic ports**: adopt the existing kernel-free-port pattern (`scripts/reconnect.test.ts:27-35`,
   `createServer().listen(0)` → `AddressInfo.port`) in `scripts/integration.ts` (4377→ephemeral,
   4378→ephemeral) and `scripts/chunk.test.ts` (4561/4562→ephemeral). No production listener
   changes — `RELAY_PORT` env override already exists.
2. **`scripts/e2e-orphans.ts` (new pre-flight)**: enumerate candidates with
   `ps -axww -o pid=,command=` (macOS host); a process is an orphan victim only if BOTH:
   (a) argv matches one of the three markers — `apps/daemon/src/index.ts`,
   `apps/relay/src/index.ts`, `apps/desktop` (electron) — AND (b) `envHasTempMarker`
   holds for its environment. Env is read via `ps -wwE -p <pid>` (darwin; Linux fallback
   `/proc/<pid>/environ`); unreadable env ⇒ spare the process (fail-safe, never kill on
   partial proof). `envHasTempMarker(env)`: true when any env value contains
   `<tmpdir>/ocr-` OR `OCR_DESKTOP_SESSION`/`OCR_USER_DATA_DIR`/`OCR_E2E_MARKER` is set
   (tmpdir + `ocr-` is the shared mkdtemp convention of every e2e here: `ocr-int-`,
   `ocr-reconnect-`, `ocr-flow-*`, `ocr-desktop-app-` from `tools/desktop.mjs:251`).
   Kill = SIGTERM, re-check after 1s, SIGKILL survivors; log one line per kill (pid + which marker).
   **Symmetry rule (the re-raise fix)**: the env factor is MANDATORY for all three markers,
   not just the daemon's.
3. **Marker at spawn time**: e2e scripts that spawn a relay with only `RELAY_PORT` env get
   `OCR_E2E_MARKER: <tempdir>` added so the relay's env factor exists:
   `scripts/integration.ts:80`, `scripts/chunk.test.ts:75`, `scripts/message-paging.test.ts:132`,
   and the `startRelay`/`bg` helpers in `scripts/relay-ratelimit.test.ts`, `relay-rooms.test.ts`,
   `relay-healthz.test.ts`, `relay-liveness.test.ts`, `relay-ipcap.test.ts`. Daemons already
   carry `HOME=<tmp ocr-*>`; the hermetic desktop app already carries
   `OCR_USER_DATA_DIR=<tmp>/ocr-desktop-app-*`.
4. **Handshake diagnostics**: in `scripts/integration.ts` (pairing timeout) and
   `scripts/chunk.test.ts` (relay-never-up path), on timeout run
   `lsof -nP -iTCP:<port> -sTCP:LISTEN` and print its output plus the port in the failure
   message before `process.exit(1)`.
5. **Invisible gate window**: in `apps/desktop/src/main.ts`, when
   `process.env.OCR_DESKTOP_SESSION` is set (the harness/eval marker, `tools/desktop.mjs:42`,
   same test-only-hatch policy as `OCR_DAEMON_FORCE_*`): skip the `ready-to-show → show()`
   hook (main.ts:739), make `showMainWindow()` a no-op (gates :158 and :430), and pass
   `paintWhenInitiallyHidden: true` explicitly in the `BrowserWindow` options (main.ts:721-738)
   so the renderer keeps painting while hidden. Interaction stays via webContents
   (`page.evaluate`/Playwright), evidence shots keep working through CDP capture.
6. **Wire pre-flight**: prepend `tsx scripts/e2e-orphans.ts && ` to the `test:e2e` and
   `test:desktop-flow` scripts in `package.json`.
7. **Stress**: `npm run test:e2e` concurrently with `npm run test:desktop-flow` must pass
   (parallel runs are only safe once every port is dynamic).

- `scripts/e2e-orphans.ts` — NEW: marker table (daemon/relay/desktop), `envHasTempMarker`, `collectCandidates`/`killOrphans` (pure helpers exported for tests), `main()` when run directly.
- `scripts/e2e-orphans.test.ts` — NEW: unit test (check() style like `scripts/client-ready.test.ts`); wired into the `test:unit` chain in `package.json`.
- `scripts/message-paging.test.ts`, `scripts/relay-ratelimit.test.ts`, `scripts/relay-rooms.test.ts`, `scripts/relay-healthz.test.ts`, `scripts/relay-liveness.test.ts`, `scripts/relay-ipcap.test.ts` — one env key (`OCR_E2E_MARKER`) per relay spawn site.
- `apps/desktop/src/main.ts` — hermetic hidden window (`showMainWindow` no-op, skip show-on-ready, `paintWhenInitiallyHidden`).
- `package.json` — `test:e2e`/`test:desktop-flow` gain the pre-flight; `test:unit` gains the new test file.
- `AGENTS.md` — one line under the desktop-e2e paragraph documenting the invisible-window behavior and the pre-flight.

## Edge cases

- Operator's REAL dev app running (`electron apps/desktop`, real `HOME`): argv matches, env has no `ocr-` marker ⇒ spared — covered by the unit test.
- Operator's real relay (production binary/launchd): argv does not contain `tsx apps/relay/src/index.ts` in dev form ⇒ no argv match at all.
- Env unreadable (other user, restricted /proc): spare + warn, never guess-kill.
- Process started before the marker convention existed (old orphan): env lacks the marker ⇒ survives the killer; the dynamic-port fix makes it harmless anyway (it holds a port nothing asks for).
- Hidden window must still paint for `page.screenshot` (`paintWhenInitiallyHidden`) — if CDP capture returns a blank frame on macOS, fall back to `webContents.capturePage()` inside the keeper's `shot` handler (`tools/desktop.mjs`), never `win.show()`.
- `tools/desktop.mjs shot <w h>` resizes the hidden window via `setContentSize` — works on hidden windows, but the gate's PNG-size assertions must stay green (verified by the desktop-flow run itself).
- Two e2e runs racing for the SAME ephemeral port between `listen(0)` close and bind: extremely unlikely; the lsof diagnostic names the collision instead of hanging.
- Crypto untouched: relay stays a blind router; no frame plaintext is ever logged by the new diagnostics (only `lsof` output and pids).

## Acceptance criteria

- `npm run typecheck && npm run build && npm run test:unit` all green (gate re-runs them).
- New unit test (`npx tsx scripts/e2e-orphans.test.ts`): for each of the 3 markers (daemon/relay/desktop), a fake process with matching argv but clean env is SPARED, and the same argv + `<tmpdir>/ocr-*`-marked env (or `OCR_E2E_MARKER`) is KILLED; `envHasTempMarker` false for a real-HOME env dump.
- Zombie drill: `node -e "require('net').createServer().listen(4378)"` (planted zombie holding 4378), then 5 CONSECUTIVE runs of `npm run test:e2e` — all green, none ever binds 4378.
- `npx tsx scripts/integration.ts` prints `INTEGRATION PASSED`; killing the relay mid-run prints the `lsof` output naming the port holder before exiting 1.
- Parallel stress: `npm run test:e2e & npm run test:desktop-flow & wait` — both exit 0 concurrently.
- `npm run test:desktop-flow` green with `OCR_DESKTOP_SESSION` set AND no visible app window on the operator's screen: during the gate, an ipc probe `document.visibilityState` returns `"hidden"` while `#root` is mounted; evidence shots are still real 1440x900 / 390px PNGs.
- `npx tsx scripts/e2e-orphans.ts` run twice back-to-back: second run logs 0 kills (idempotent).

## Out of scope

- Any change to `scripts/invariants.ts`, `deploy/`, crypto/protocol, handshake allowlist, replay protection (seq/AAD) or the 0600 state file.
- Killing orphans by TCP-port probing or by process age heuristics — argv+env match only.
- Making the packaged/production desktop app hidden-capable (the invisible window is strictly the `OCR_DESKTOP_SESSION` test hatch).
- Parallelizing the pilot scheduler slots or changing gate timeouts/budgets in `apps/pilot/`.
- Switching the remaining `relay-*` tests from random-range ports to the `listen(0)` pattern (already collision-safe enough); only the marker env is added there.
